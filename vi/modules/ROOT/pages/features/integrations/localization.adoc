[[localization]]
= Bản địa hóa
Spring Security hỗ trợ bản địa hóa các thông báo exception mà người dùng cuối có khả năng nhìn thấy.
Nếu ứng dụng của bạn được thiết kế cho người dùng nói tiếng Anh, bạn không cần làm gì vì theo mặc định, tất cả message của Spring Security đều bằng tiếng Anh.
Nếu cần hỗ trợ các locale khác, mọi thông tin cần thiết đều có trong phần này.

Tất cả thông báo exception đều có thể được bản địa hóa, bao gồm các thông báo liên quan đến authentication failure và access bị từ chối (authorization failure).
Các exception và logging message dành cho developer hoặc người deploy system (bao gồm attribute không chính xác, vi phạm interface contract, sử dụng constructor không chính xác, validation tại startup và logging ở debug level) không được bản địa hóa mà được hard-code bằng tiếng Anh trong code của Spring Security.

Trong `spring-security-core-xx.jar`, bạn sẽ tìm thấy package `org.springframework.security`, bên trong có file `messages.properties` cùng với các phiên bản đã được bản địa hóa cho một số ngôn ngữ phổ biến.
`ApplicationContext` của bạn nên tham chiếu đến file này, vì các class của Spring Security triển khai interface `MessageSourceAware` của Spring và mong đợi message resolver được inject vào application context thông qua dependency injection tại thời điểm startup.
Thông thường, bạn chỉ cần đăng ký một bean trong application context để tham chiếu đến các message.
Ví dụ được trình bày bên dưới:

[source,xml]
----
<bean id="messageSource"
	class="org.springframework.context.support.ReloadableResourceBundleMessageSource">
<property name="basename" value="classpath:org/springframework/security/messages"/>
</bean>
----

File `messages.properties` được đặt tên theo quy ước resource bundle tiêu chuẩn và đại diện cho ngôn ngữ mặc định của các message được Spring Security hỗ trợ.
File mặc định này bằng tiếng Anh.

Nếu muốn tùy chỉnh file `messages.properties` hoặc hỗ trợ các ngôn ngữ khác, bạn nên sao chép file, đổi tên file cho phù hợp rồi đăng ký file trong bean definition ở trên.
File này không có nhiều message key, vì vậy localization không nên được xem là một công việc lớn.
Nếu thực hiện localization file này, hãy cân nhắc chia sẻ công việc với cộng đồng bằng cách tạo một JIRA task và đính kèm bản `messages.properties` đã được bản địa hóa, được đặt tên phù hợp.

Spring Security dựa vào cơ chế localization của Spring để thực hiện lookup message phù hợp.
Để việc này hoạt động, bạn phải bảo đảm locale của incoming request được lưu trong `org.springframework.context.i18n.LocaleContextHolder` của Spring.
`DispatcherServlet` của Spring MVC tự động thực hiện việc này cho application, nhưng vì các filter của Spring Security được gọi trước khi việc này diễn ra, `LocaleContextHolder` cần được thiết lập để chứa `Locale` chính xác trước khi các filter được gọi.
Bạn có thể tự thực hiện việc này trong một filter (filter này phải đứng trước các filter của Spring Security trong `web.xml`) hoặc sử dụng `RequestContextFilter` của Spring.
Tham khảo tài liệu Spring Framework để biết thêm chi tiết về cách sử dụng localization với Spring.

Ứng dụng mẫu "contacts" được thiết lập để sử dụng các message đã được bản địa hóa.
