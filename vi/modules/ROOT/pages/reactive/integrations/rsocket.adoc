[[rsocket]]
= Bảo mật RSocket

Hỗ trợ RSocket của Spring Security dựa trên một `SocketAcceptorInterceptor`.
Điểm vào chính của security nằm trong `PayloadSocketAcceptorInterceptor`, thành phần điều chỉnh các API RSocket để cho phép intercept một `PayloadExchange` bằng các triển khai `PayloadInterceptor`.

Ví dụ sau minh họa cấu hình Bảo mật RSocket tối thiểu:

* Hello RSocket {gh-samples-url}/reactive/rsocket/hello-security[hellorsocket]
* https://github.com/rwinch/spring-flights/tree/security[Spring Flights]


== Cấu hình Bảo mật RSocket tối thiểu

Bạn có thể xem cấu hình Bảo mật RSocket tối thiểu dưới đây:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Configuration
@EnableRSocketSecurity
public class HelloRSocketSecurityConfig {

	@Bean
	public MapReactiveUserDetailsService userDetailsService() {
		UserDetails user = User.withDefaultPasswordEncoder()
			.username("user")
			.password("user")
			.roles("USER")
			.build();
		return new MapReactiveUserDetailsService(user);
	}
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Configuration
@EnableRSocketSecurity
open class HelloRSocketSecurityConfig {
    @Bean
    open fun userDetailsService(): MapReactiveUserDetailsService {
        val user = User.withDefaultPasswordEncoder()
            .username("user")
            .password("user")
            .roles("USER")
            .build()
        return MapReactiveUserDetailsService(user)
    }
}
----
======

Cấu hình này bật <<rsocket-authentication-simple,authentication đơn giản>> và thiết lập <<rsocket-authorization,authorization RSocket>> để yêu cầu người dùng đã được authentication cho mọi request.

== Thêm SecuritySocketAcceptorInterceptor

Để Spring Security hoạt động, chúng ta cần áp dụng `SecuritySocketAcceptorInterceptor` cho `ServerRSocketFactory`.
Việc này kết nối `PayloadSocketAcceptorInterceptor` với hạ tầng RSocket.

Spring Boot tự động đăng ký nó trong `RSocketSecurityAutoConfiguration` khi bạn thêm {gh-samples-url}/reactive/rsocket/hello-security/build.gradle[các dependency phù hợp].

Hoặc, nếu không sử dụng auto-configuration của Boot, bạn có thể đăng ký nó thủ công như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
RSocketServerCustomizer springSecurityRSocketSecurity(SecuritySocketAcceptorInterceptor interceptor) {
    return (server) -> server.interceptors((registry) -> registry.forSocketAcceptor(interceptor));
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
fun springSecurityRSocketSecurity(interceptor: SecuritySocketAcceptorInterceptor): RSocketServerCustomizer {
    return RSocketServerCustomizer { server ->
        server.interceptors { registry ->
            registry.forSocketAcceptor(interceptor)
        }
    }
}
----
======

Để tùy chỉnh chính interceptor này, hãy sử dụng `RSocketSecurity` để thêm <<rsocket-authentication,authentication>> và <<rsocket-authorization,authorization>>.

[[rsocket-authentication]]
== Authentication RSocket

Authentication RSocket được thực hiện bằng `AuthenticationPayloadInterceptor`, thành phần này hoạt động như một controller để gọi một instance `ReactiveAuthenticationManager`.

[[rsocket-authentication-setup-vs-request]]
=== Authentication tại thời điểm Setup so với thời điểm Request

Thông thường, authentication có thể diễn ra tại thời điểm setup, tại thời điểm request hoặc cả hai.

Authentication tại thời điểm setup phù hợp trong một số tình huống.
Một tình huống phổ biến là khi một người dùng duy nhất (chẳng hạn một kết nối mobile) sử dụng một kết nối RSocket.
Trong trường hợp này, chỉ một người dùng sử dụng kết nối, vì vậy authentication có thể được thực hiện một lần tại thời điểm kết nối.

Trong tình huống kết nối RSocket được dùng chung, việc gửi credential trong mỗi request là phù hợp.
Ví dụ, một web application kết nối đến RSocket server dưới dạng downstream service sẽ tạo một kết nối duy nhất mà tất cả người dùng cùng sử dụng.
Trong trường hợp này, nếu RSocket server cần thực hiện authorization dựa trên credential của người dùng web application, authentication cho từng request là phù hợp.

Trong một số tình huống, authentication tại cả thời điểm setup và trong mỗi request là phù hợp.
Hãy xem xét web application như đã mô tả trước đó.
Nếu cần giới hạn kết nối chỉ cho bản thân web application, chúng ta có thể cung cấp một credential có authority `SETUP` tại thời điểm kết nối.
Khi đó, mỗi người dùng có thể có các authority khác nhau nhưng không có authority `SETUP`.
Điều này có nghĩa là từng người dùng có thể thực hiện request nhưng không thể tạo thêm kết nối.

[[rsocket-authentication-simple]]
=== Authentication đơn giản

Spring Security hỗ trợ https://github.com/rsocket/rsocket/blob/5920ed374d008abb712cb1fd7c9d91778b2f4a68/Extensions/Security/Simple.md[Simple Authentication Metadata Extension].

[NOTE]
====
Basic Authentication đã phát triển thành Simple Authentication và chỉ được hỗ trợ để duy trì backward compatibility.
Xem `RSocketSecurity.basicAuthentication(Customizer)` để thiết lập.
====

RSocket receiver có thể giải mã credential bằng cách sử dụng `AuthenticationPayloadExchangeConverter`, thành phần được tự động thiết lập khi sử dụng phần `simpleAuthentication` của DSL.
Ví dụ sau minh họa một cấu hình tường minh:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
PayloadSocketAcceptorInterceptor rsocketInterceptor(RSocketSecurity rsocket) {
	rsocket
		.authorizePayload(authorize ->
			authorize
					.anyRequest().authenticated()
					.anyExchange().permitAll()
		)
		.simpleAuthentication(Customizer.withDefaults());
	return rsocket.build();
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
open fun rsocketInterceptor(rsocket: RSocketSecurity): PayloadSocketAcceptorInterceptor {
    rsocket
        .authorizePayload { authorize -> authorize
                .anyRequest().authenticated()
                .anyExchange().permitAll()
        }
        .simpleAuthentication(withDefaults())
    return rsocket.build()
}
----
======

RSocket sender có thể gửi credential bằng cách sử dụng `SimpleAuthenticationEncoder`, thành phần bạn có thể thêm vào `RSocketStrategies` của Spring.

[tabs]
======
Java::
+
[source,java,role="primary"]
----
RSocketStrategies.Builder strategies = ...;
strategies.encoder(new SimpleAuthenticationEncoder());
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
var strategies: RSocketStrategies.Builder = ...
strategies.encoder(SimpleAuthenticationEncoder())
----
======

Sau đó, bạn có thể sử dụng nó để gửi username và password đến receiver trong setup:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
MimeType authenticationMimeType =
	MimeTypeUtils.parseMimeType(WellKnownMimeType.MESSAGE_RSOCKET_AUTHENTICATION.getString());
UsernamePasswordMetadata credentials = new UsernamePasswordMetadata("user", "password");
Mono<RSocketRequester> requester = RSocketRequester.builder()
	.setupMetadata(credentials, authenticationMimeType)
	.rsocketStrategies(strategies.build())
	.connectTcp(host, port);
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
val authenticationMimeType: MimeType =
    MimeTypeUtils.parseMimeType(WellKnownMimeType.MESSAGE_RSOCKET_AUTHENTICATION.string)
val credentials = UsernamePasswordMetadata("user", "password")
val requester: Mono<RSocketRequester> = RSocketRequester.builder()
    .setupMetadata(credentials, authenticationMimeType)
    .rsocketStrategies(strategies.build())
    .connectTcp(host, port)
----
======

Ngoài ra hoặc đồng thời, username và password có thể được gửi trong một request.

[tabs]
======
Java::
+
[source,java,role="primary"]
----
Mono<RSocketRequester> requester;
UsernamePasswordMetadata credentials = new UsernamePasswordMetadata("user", "password");

public Mono<AirportLocation> findRadar(String code) {
	return this.requester.flatMap(req ->
		req.route("find.radar.{code}", code)
			.metadata(credentials, authenticationMimeType)
			.retrieveMono(AirportLocation.class)
	);
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
import org.springframework.messaging.rsocket.retrieveMono

// ...

var requester: Mono<RSocketRequester>? = null
var credentials = UsernamePasswordMetadata("user", "password")

open fun findRadar(code: String): Mono<AirportLocation> {
    return requester!!.flatMap { req ->
        req.route("find.radar.{code}", code)
            .metadata(credentials, authenticationMimeType)
            .retrieveMono<AirportLocation>()
    }
}
----
======

[[rsocket-authentication-jwt]]
=== JWT

Spring Security hỗ trợ https://github.com/rsocket/rsocket/blob/5920ed374d008abb712cb1fd7c9d91778b2f4a68/Extensions/Security/Bearer.md[Bearer Token Authentication Metadata Extension].
Hỗ trợ này thực hiện authentication một JWT (xác định rằng JWT hợp lệ), sau đó sử dụng JWT để đưa ra các quyết định authorization.

RSocket receiver có thể giải mã credential bằng cách sử dụng `BearerPayloadExchangeConverter`, thành phần được tự động thiết lập khi sử dụng phần `jwt` của DSL.
Đoạn mã sau minh họa một cấu hình:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
PayloadSocketAcceptorInterceptor rsocketInterceptor(RSocketSecurity rsocket) {
	rsocket
		.authorizePayload(authorize ->
			authorize
				.anyRequest().authenticated()
				.anyExchange().permitAll()
		)
		.jwt(Customizer.withDefaults());
	return rsocket.build();
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
fun rsocketInterceptor(rsocket: RSocketSecurity): PayloadSocketAcceptorInterceptor {
    rsocket
        .authorizePayload { authorize -> authorize
            .anyRequest().authenticated()
            .anyExchange().permitAll()
        }
        .jwt(withDefaults())
    return rsocket.build()
}
----
======

Cấu hình trên dựa vào việc một `@Bean` `ReactiveJwtDecoder` tồn tại.
Ví dụ tạo một bean từ issuer được trình bày dưới đây:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
ReactiveJwtDecoder jwtDecoder() {
	return ReactiveJwtDecoders
		.fromIssuerLocation("https://example.com/auth/realms/demo");
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
fun jwtDecoder(): ReactiveJwtDecoder {
    return ReactiveJwtDecoders
        .fromIssuerLocation("https://example.com/auth/realms/demo")
}
----
======

RSocket sender không cần làm gì đặc biệt để gửi token vì giá trị này là một `String` đơn giản.
Ví dụ sau gửi token tại thời điểm setup:

[tabs]
======

+
[source,java,role="primary"]

Kotlin::
+

    .setupMetadata(token, authenticationMimeType)

======

[[rsocket-authorization]]
== Authorization RSocket

Authorization RSocket được thực hiện bằng `AuthorizationPayloadInterceptor`, thành phần này hoạt động như một controller để gọi một instance `ReactiveAuthorizationManager`.
Bạn có thể sử dụng DSL để thiết lập các rule authorization dựa trên `PayloadExchange`.
Đoạn mã sau minh họa một cấu hình:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
rsocket
	.authorizePayload(authz ->
		authz
			.setup().hasRole("SETUP") // <1>
			.route("fetch.profile.me").authenticated() // <2>
			.matcher((payloadExchange) -> payloadExchange(payloadExchange)) // <3>
				.hasRole("CUSTOM")
			.route("fetch.profile.{username}") // <4>
				.access((authentication, context) -> checkFriends(authentication, context))
			.anyRequest().authenticated() // <5>
			.anyExchange().permitAll() // <6>
	);
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
rsocket
    .authorizePayload { authz ->
        authz
            .setup().hasRole("SETUP") // <1>
            .route("fetch.profile.me").authenticated() // <2>
            .matcher { payloadExchange -> isMatch(payloadExchange) } // <3>
            .hasRole("CUSTOM")
            .route("fetch.profile.{username}") // <4>
            .access { authentication, context -> checkFriends(authentication, context) }
            .anyRequest().authenticated() // <5>
            .anyExchange().permitAll()
    } // <6>
----
======
<1> Thiết lập một kết nối yêu cầu authority `ROLE_SETUP`.
<2> Nếu route là `fetch.profile.me`, authorization chỉ yêu cầu người dùng đã được authentication.
<3> Trong rule này, chúng ta thiết lập một matcher tùy chỉnh, trong đó authorization yêu cầu người dùng có authority `ROLE_CUSTOM`.
<4> Rule này sử dụng authorization tùy chỉnh.
Matcher biểu diễn một biến có tên `username`, biến này được cung cấp trong `context`.
Một rule authorization tùy chỉnh được cung cấp trong method `checkFriends`.
<5> Rule này đảm bảo rằng một request chưa có rule sẽ yêu cầu người dùng đã được authentication.
Request là nơi metadata được bao gồm.
Request đó sẽ không bao gồm các payload bổ sung.
<6> Rule này đảm bảo rằng bất kỳ exchange nào chưa có rule đều được cho phép với mọi người.
Trong ví dụ này, điều đó có nghĩa là các payload không có metadata cũng không có rule authorization.

Lưu ý rằng các rule authorization được thực thi theo thứ tự.
Chỉ rule authorization đầu tiên khớp mới được gọi.
