[[webflux-testing-oauth2]]
= Kiểm thử OAuth 2.0

Đối với OAuth 2.0, xref:reactive/test/method.adoc#test-erms[các nguyên tắc đã trình bày trước đó vẫn được áp dụng]: Cuối cùng, điều này phụ thuộc vào những gì method đang được kiểm thử mong đợi có trong `SecurityContextHolder`.

Xét ví dụ sau về một controller:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public Mono<String> foo(Principal user) {
    return Mono.just(user.getName());
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(user: Principal): Mono<String> {
    return Mono.just(user.name)
}
----
======

Không có gì trong đó dành riêng cho OAuth2, vì vậy bạn có thể xref:reactive/test/method.adoc#test-erms[sử dụng `@WithMockUser`] mà không gặp vấn đề gì.

Tuy nhiên, hãy xét trường hợp controller của bạn gắn với một khía cạnh nào đó trong phần hỗ trợ OAuth 2.0 của Spring Security:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public Mono<String> foo(@AuthenticationPrincipal OidcUser user) {
    return Mono.just(user.getIdToken().getSubject());
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(@AuthenticationPrincipal user: OidcUser): Mono<String> {
    return Mono.just(user.idToken.subject)
}
----
======

Trong trường hợp đó, phần hỗ trợ kiểm thử của Spring Security rất hữu ích.

[[webflux-testing-oidc-login]]
== Kiểm thử đăng nhập OIDC

Kiểm thử method được trình bày trong <<webflux-testing-oauth2,phần trước>> bằng `WebTestClient` yêu cầu mô phỏng một dạng grant flow nào đó với một authorization server.
Đây là một nhiệm vụ khó khăn, đó là lý do Spring Security cung cấp phần hỗ trợ để loại bỏ boilerplate này.

Ví dụ, chúng ta có thể yêu cầu Spring Security bao gồm một `OidcUser` mặc định bằng cách sử dụng method `SecurityMockServerConfigurers#oidcLogin`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
client
    .mutateWith(mockOidcLogin()).get().uri("/endpoint").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
client
    .mutateWith(mockOidcLogin())
    .get().uri("/endpoint")
    .exchange()
----
======

Dòng đó cấu hình `MockServerRequest` liên kết với một `OidcUser` bao gồm một `OidcIdToken` đơn giản, một `OidcUserInfo` và một `Collection` các authority được cấp.

Cụ thể, nó bao gồm một `OidcIdToken` có claim `sub` được đặt thành `user`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(user.getIdToken().getClaim("sub")).isEqualTo("user");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(user.idToken.getClaim<String>("sub")).isEqualTo("user")
----
======

Nó cũng bao gồm một `OidcUserInfo` không có claim nào được thiết lập:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(user.getUserInfo().getClaims()).isEmpty();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(user.userInfo.claims).isEmpty()
----
======

Nó cũng bao gồm một `Collection` authority chỉ có một authority là `SCOPE_read`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(user.getAuthorities()).hasSize(1);
assertThat(user.getAuthorities()).containsExactly(new SimpleGrantedAuthority("SCOPE_read"));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(user.authorities).hasSize(1)
assertThat(user.authorities).containsExactly(SimpleGrantedAuthority("SCOPE_read"))
----
======

Spring Security đảm bảo instance `OidcUser` khả dụng cho xref:servlet/integrations/mvc.adoc#mvc-authentication-principal[annotation `@AuthenticationPrincipal`].

Ngoài ra, nó còn liên kết `OidcUser` với một instance đơn giản của `OAuth2AuthorizedClient` mà nó đặt vào một `ServerOAuth2AuthorizedClientRepository` giả lập.
Điều này có thể hữu ích nếu các kiểm thử của bạn <<webflux-testing-oauth2-client,sử dụng annotation `@RegisteredOAuth2AuthorizedClient`>>.

[[webflux-testing-oidc-login-claims]]
=== Cấu hình claim

Mặc dù authority được cấp là thành phần phổ biến trong toàn bộ Spring Security, OAuth 2.0 cũng có các claim.

Ví dụ, giả sử bạn có claim `user_id` cho biết ID của user trong hệ thống.
Bạn có thể truy cập claim đó trong controller như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public Mono<String> foo(@AuthenticationPrincipal OidcUser oidcUser) {
    String userId = oidcUser.getIdToken().getClaim("user_id");
    // ...
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(@AuthenticationPrincipal oidcUser: OidcUser): Mono<String> {
    val userId = oidcUser.idToken.getClaim<String>("user_id")
    // ...
}
----
======

Trong trường hợp đó, bạn có thể chỉ định claim bằng method `idToken()`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
client
    .mutateWith(mockOidcLogin()
        .idToken((token) -> token.claim("user_id", "1234"))
    )
    .get().uri("/endpoint").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
client
    .mutateWith(mockOidcLogin()
        .idToken { token -> token.claim("user_id", "1234") }
    )
    .get().uri("/endpoint").exchange()
----
======

Điều này hoạt động vì `OidcUser` lấy các claim của nó từ `OidcIdToken`.

[[webflux-testing-oidc-login-user]]
=== Cấu hình bổ sung

Ngoài ra còn có các method để cấu hình thêm authentication, tùy thuộc vào dữ liệu mà controller của bạn mong đợi:

* `userInfo(OidcUserInfo.Builder)`: Cấu hình instance `OidcUserInfo`
* `clientRegistration(ClientRegistration)`: Cấu hình `OAuth2AuthorizedClient` liên kết với một `ClientRegistration` được cung cấp
* `oidcUser(OidcUser)`: Cấu hình instance `OidcUser` hoàn chỉnh

Method cuối cùng hữu ích nếu bạn:
* Có implementation riêng của `OidcUser` hoặc
* Cần thay đổi attribute name

Ví dụ, giả sử authorization server của bạn gửi tên principal trong claim `user_name` thay vì claim `sub`.
Trong trường hợp đó, bạn có thể tự cấu hình một `OidcUser`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
OidcUser oidcUser = new DefaultOidcUser(
        AuthorityUtils.createAuthorityList("SCOPE_message:read"),
        OidcIdToken.withTokenValue("id-token").claim("user_name", "foo_user").build(),
        "user_name");

client
    .mutateWith(mockOidcLogin().oidcUser(oidcUser))
    .get().uri("/endpoint").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
val oidcUser: OidcUser = DefaultOidcUser(
    AuthorityUtils.createAuthorityList("SCOPE_message:read"),
    OidcIdToken.withTokenValue("id-token").claim("user_name", "foo_user").build(),
    "user_name"
)

client
    .mutateWith(mockOidcLogin().oidcUser(oidcUser))
    .get().uri("/endpoint").exchange()
----
======

[[webflux-testing-oauth2-login]]

----

fun foo(@AuthenticationPrincipal oauth2User: OAuth2User): Mono<String> {
    return Mono.just(oauth2User.getAttribute("sub"))

----
======

Trong trường hợp đó, chúng ta có thể yêu cầu Spring Security bao gồm một `OAuth2User` mặc định bằng cách sử dụng method `SecurityMockServerConfigurers#oauth2User`:

[[webflux-testing-oauth2-client]]
== Kiểm thử OAuth 2.0 Client

Bất kể user của bạn authentication như thế nào, request đang được kiểm thử có thể sử dụng các token và client registration khác.
Ví dụ, controller của bạn có thể dựa vào client credentials grant để lấy một token hoàn toàn không liên kết với user:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public Mono<String> foo(@RegisteredOAuth2AuthorizedClient("my-app") OAuth2AuthorizedClient authorizedClient) {
    return this.webClient.get()
        .attributes(oauth2AuthorizedClient(authorizedClient))
        .retrieve()
        .bodyToMono(String.class);
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
import org.springframework.web.reactive.function.client.bodyToMono

// ...

@GetMapping("/endpoint")
fun foo(@RegisteredOAuth2AuthorizedClient("my-app") authorizedClient: OAuth2AuthorizedClient?): Mono<String> {
    return this.webClient.get()
        .attributes(oauth2AuthorizedClient(authorizedClient))
        .retrieve()
        .bodyToMono()
}
----
======

Mô phỏng quá trình bắt tay này với authorization server có thể khá rườm rà.
Thay vào đó, bạn có thể sử dụng `SecurityMockServerConfigurers#oauth2Client` để thêm một `OAuth2AuthorizedClient` vào `ServerOAuth2AuthorizedClientRepository` giả lập:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
client
    .mutateWith(mockOAuth2Client("my-app"))
    .get().uri("/endpoint").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
client
    .mutateWith(mockOAuth2Client("my-app"))
    .get().uri("/endpoint").exchange()
----
======

Thao tác này tạo một `OAuth2AuthorizedClient` có một `ClientRegistration` đơn giản, một `OAuth2AccessToken` và tên resource owner.

Cụ thể, nó bao gồm một `ClientRegistration` có client ID là `test-client` và client secret là `test-secret`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(authorizedClient.getClientRegistration().getClientId()).isEqualTo("test-client");
assertThat(authorizedClient.getClientRegistration().getClientSecret()).isEqualTo("test-secret");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(authorizedClient.clientRegistration.clientId).isEqualTo("test-client")
assertThat(authorizedClient.clientRegistration.clientSecret).isEqualTo("test-secret")
----
======

Nó cũng bao gồm tên resource owner là `user`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(authorizedClient.getPrincipalName()).isEqualTo("user");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(authorizedClient.principalName).isEqualTo("user")
----
======

Nó cũng bao gồm một `OAuth2AccessToken` có một scope là `read`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(authorizedClient.getAccessToken().getScopes()).hasSize(1);
assertThat(authorizedClient.getAccessToken().getScopes()).containsExactly("read");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(authorizedClient.accessToken.scopes).hasSize(1)
assertThat(authorizedClient.accessToken.scopes).containsExactly("read")
----
======

Sau đó, bạn có thể lấy client như bình thường bằng cách sử dụng `@RegisteredOAuth2AuthorizedClient` trong một method của controller.

[[webflux-testing-oauth2-client-scopes]]
=== Cấu hình scope

Trong nhiều trường hợp, access token OAuth 2.0 đi kèm một tập scope.
Xét ví dụ sau về cách controller có thể kiểm tra các scope:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public Mono<String> foo(@RegisteredOAuth2AuthorizedClient("my-app") OAuth2AuthorizedClient authorizedClient) {
    Set<String> scopes = authorizedClient.getAccessToken().getScopes();
    if (scopes.contains("message:read")) {
        return this.webClient.get()
            .attributes(oauth2AuthorizedClient(authorizedClient))
            .retrieve()
            .bodyToMono(String.class);
    }
    // ...
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
import org.springframework.web.reactive.function.client.bodyToMono

// ...

@GetMapping("/endpoint")
fun foo(@RegisteredOAuth2AuthorizedClient("my-app") authorizedClient: OAuth2AuthorizedClient): Mono<String> {
    val scopes = authorizedClient.accessToken.scopes
    if (scopes.contains("message:read")) {
        return webClient.get()
            .attributes(oauth2AuthorizedClient(authorizedClient))
            .retrieve()
            .bodyToMono()
    }
    // ...
}
----
======

Với một controller kiểm tra scope, bạn có thể cấu hình scope bằng cách sử dụng method `accessToken()`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
client
    .mutateWith(mockOAuth2Client("my-app")
        .accessToken(new OAuth2AccessToken(BEARER, "token", null, null, Collections.singleton("message:read")))
    )
    .get().uri("/endpoint").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
client
    .mutateWith(mockOAuth2Client("my-app")
        .accessToken(OAuth2AccessToken(BEARER, "token", null, null, setOf("message:read")))
)
.get().uri("/endpoint").exchange()
----
======

[[webflux-testing-oauth2-client-registration]]
=== Cấu hình bổ sung

Bạn cũng có thể sử dụng các method bổ sung để cấu hình thêm authentication, tùy thuộc vào dữ liệu mà controller của bạn mong đợi:

* `principalName(String)`; Cấu hình tên resource owner
* `clientRegistration(Consumer<ClientRegistration.Builder>)`: Cấu hình `ClientRegistration` liên kết
* `clientRegistration(ClientRegistration)`: Cấu hình `ClientRegistration` hoàn chỉnh

Method cuối cùng hữu ích nếu bạn muốn sử dụng một `ClientRegistration` thực.

Ví dụ, giả sử bạn muốn sử dụng một trong các định nghĩa `ClientRegistration` của ứng dụng, như được chỉ định trong `application.yml`.

Trong trường hợp đó, kiểm thử của bạn có thể autowire `ReactiveClientRegistrationRepository` và tìm registration mà kiểm thử cần:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Autowired
ReactiveClientRegistrationRepository clientRegistrationRepository;

// ...

client
    .mutateWith(mockOAuth2Client()
        .clientRegistration(this.clientRegistrationRepository.findByRegistrationId("facebook").block())
    )
    .get().uri("/exchange").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Autowired
lateinit var clientRegistrationRepository: ReactiveClientRegistrationRepository

// ...

client
    .mutateWith(mockOAuth2Client()
        .clientRegistration(this.clientRegistrationRepository.findByRegistrationId("facebook").block())
    )
    .get().uri("/exchange").exchange()
----
======

[[webflux-testing-jwt]]
== Kiểm thử JWT authentication

Để thực hiện một request đã được authorization trên resource server, bạn cần một bearer token.
Nếu resource server của bạn được cấu hình cho JWT, bearer token cần được ký rồi mã hóa theo đặc tả JWT.
Tất cả việc này có thể khá khó khăn, đặc biệt khi đó không phải là trọng tâm của kiểm thử.

May mắn là có một số cách đơn giản giúp bạn vượt qua khó khăn này để các kiểm thử tập trung vào authorization thay vì biểu diễn bearer token.
Hai cách trong số đó được trình bày ở hai subsection tiếp theo.

=== `mockJwt() WebTestClientConfigurer`

Cách thứ nhất là sử dụng một `WebTestClientConfigurer`.
Cách đơn giản nhất là sử dụng method `SecurityMockServerConfigurers#mockJwt` như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
client
    .mutateWith(mockJwt()).get().uri("/endpoint").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
client
    .mutateWith(mockJwt()).get().uri("/endpoint").exchange()
----
======

Ví dụ này tạo một `Jwt` giả lập và truyền nó qua mọi API authentication để các cơ chế authorization của bạn có thể kiểm tra nó.

Theo mặc định, `JWT` được tạo có các đặc điểm sau:

[source,json]
----
{
  "headers" : { "alg" : "none" },
  "claims" : {
    "sub" : "user",
    "scope" : "read"
  }
}
----

Nếu kiểm thử `Jwt` kết quả, nó sẽ đạt kiểm tra như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(jwt.getTokenValue()).isEqualTo("token");
assertThat(jwt.getHeaders().get("alg")).isEqualTo("none");
assertThat(jwt.getSubject()).isEqualTo("sub");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(jwt.tokenValue).isEqualTo("token")
assertThat(jwt.headers["alg"]).isEqualTo("none")
assertThat(jwt.subject).isEqualTo("sub")
----
======

Lưu ý rằng bạn có thể cấu hình các giá trị này.

Bạn cũng có thể cấu hình bất kỳ header hoặc claim nào bằng các method tương ứng:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
client
	.mutateWith(mockJwt().jwt((jwt) -> jwt.header("kid", "one")
		.claim("iss", "https://idp.example.org")))
	.get().uri("/endpoint").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
client
    .mutateWith(mockJwt().jwt { jwt -> jwt.header("kid", "one")
        .claim("iss", "https://idp.example.org")
    })
    .get().uri("/endpoint").exchange()
----
======

[tabs]
======
Java::
+
[source,java,role="primary"]
----
client
	.mutateWith(mockJwt().jwt((jwt) -> jwt.claims((claims) -> claims.remove("scope"))))
	.get().uri("/endpoint").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
client
    .mutateWith(mockJwt().jwt { jwt ->
        jwt.claims { claims -> claims.remove("scope") }
    })
    .get().uri("/endpoint").exchange()
----
======

Các claim `scope` và `scp` được xử lý ở đây giống như trong một request bearer token thông thường.
Tuy nhiên, bạn có thể dễ dàng ghi đè hành vi này bằng cách cung cấp danh sách instance `GrantedAuthority` mà kiểm thử cần:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
client
	.mutateWith(mockJwt().authorities(new SimpleGrantedAuthority("SCOPE_messages")))
	.get().uri("/endpoint").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
client
    .mutateWith(mockJwt().authorities(SimpleGrantedAuthority("SCOPE_messages")))
    .get().uri("/endpoint").exchange()
----
======

Ngoài ra, nếu có một converter tùy chỉnh từ `Jwt` sang `Collection<GrantedAuthority>`, bạn cũng có thể sử dụng converter đó để suy ra các authority:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
client
	.mutateWith(mockJwt().authorities(new MyConverter()))
	.get().uri("/endpoint").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
client
    .mutateWith(mockJwt().authorities(MyConverter()))
    .get().uri("/endpoint").exchange()
----
======

Bạn cũng có thể chỉ định một `Jwt` hoàn chỉnh; javadoc:org.springframework.security.oauth2.jwt.Jwt$Builder[] rất hữu ích cho việc này:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
Jwt jwt = Jwt.withTokenValue("token")
    .header("alg", "none")
    .claim("sub", "user")
    .claim("scope", "read")
    .build();

client
	.mutateWith(mockJwt().jwt(jwt))
	.get().uri("/endpoint").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
val jwt: Jwt = Jwt.withTokenValue("token")
    .header("alg", "none")
    .claim("sub", "user")
    .claim("scope", "read")
    .build()

client
    .mutateWith(mockJwt().jwt(jwt))
    .get().uri("/endpoint").exchange()
----
======

=== `authentication()` và `WebTestClientConfigurer`

Cách thứ hai là sử dụng `Mutator` `authentication()`.
Bạn có thể khởi tạo `JwtAuthenticationToken` của riêng mình và cung cấp nó trong kiểm thử:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
Jwt jwt = Jwt.withTokenValue("token")
    .header("alg", "none")
    .claim("sub", "user")
    .build();
Collection<GrantedAuthority> authorities = AuthorityUtils.createAuthorityList("SCOPE_read");
JwtAuthenticationToken token = new JwtAuthenticationToken(jwt, authorities);

client
	.mutateWith(mockAuthentication(token))
	.get().uri("/endpoint").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
val jwt = Jwt.withTokenValue("token")
    .header("alg", "none")
    .claim("sub", "user")
    .build()
val authorities: Collection<GrantedAuthority> = AuthorityUtils.createAuthorityList("SCOPE_read")
val token = JwtAuthenticationToken(jwt, authorities)

client
    .mutateWith(mockAuthentication<JwtMutator>(token))
    .get().uri("/endpoint").exchange()
----
======

Lưu ý rằng, thay cho các cách trên, bạn cũng có thể mock bean `ReactiveJwtDecoder` bằng annotation `@MockBean`.

[[webflux-testing-opaque-token]]
== Kiểm thử opaque token authentication

Tương tự <<webflux-testing-jwt,JWT>>, opaque token yêu cầu một authorization server để xác minh tính hợp lệ, điều này có thể khiến việc kiểm thử khó khăn hơn.
Để hỗ trợ việc đó, Spring Security có phần hỗ trợ kiểm thử cho opaque token.

Giả sử bạn có một controller lấy authentication dưới dạng `BearerTokenAuthentication`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public Mono<String> foo(BearerTokenAuthentication authentication) {
    return Mono.just((String) authentication.getTokenAttributes().get("sub"));
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(authentication: BearerTokenAuthentication): Mono<String?> {
    return Mono.just(authentication.tokenAttributes["sub"] as String?)
}
----
======

Trong trường hợp đó, bạn có thể yêu cầu Spring Security bao gồm một `BearerTokenAuthentication` mặc định bằng cách sử dụng method `SecurityMockServerConfigurers#opaqueToken`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
client
    .mutateWith(mockOpaqueToken())
    .get().uri("/endpoint").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
client
    .mutateWith(mockOpaqueToken())
    .get().uri("/endpoint").exchange()
----
======

Ví dụ này cấu hình `MockHttpServletRequest` liên kết với một `BearerTokenAuthentication` bao gồm một `OAuth2AuthenticatedPrincipal` đơn giản, một `Map` attribute và một `Collection` các authority được cấp.

Cụ thể, nó bao gồm một `Map` có cặp key/value `sub`/`user`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat((String) token.getTokenAttributes().get("sub")).isEqualTo("user");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(token.tokenAttributes["sub"] as String?).isEqualTo("user")
----
======

Nó cũng bao gồm một `Collection` authority chỉ có một authority là `SCOPE_read`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(token.getAuthorities()).hasSize(1);
assertThat(token.getAuthorities()).containsExactly(new SimpleGrantedAuthority("SCOPE_read"));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(token.authorities).hasSize(1)
assertThat(token.authorities).containsExactly(SimpleGrantedAuthority("SCOPE_read"))
----
======

Spring Security thực hiện các công việc cần thiết để đảm bảo instance `BearerTokenAuthentication` khả dụng cho các method của controller.

[[webflux-testing-opaque-token-attributes]]
=== Cấu hình claim

Mặc dù authority được cấp khá phổ biến trong toàn bộ Spring Security, OAuth 2.0 cũng có các attribute.

Ví dụ, giả sử bạn có attribute `user_id` cho biết ID của user trong hệ thống.
Bạn có thể truy cập attribute đó trong controller như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public Mono<String> foo(BearerTokenAuthentication authentication) {
    String userId = (String) authentication.getTokenAttributes().get("user_id");
    // ...
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(authentication: BearerTokenAuthentication): Mono<String?> {
    val userId = authentication.tokenAttributes["user_id"] as String?
    // ...
}
----
======

Trong trường hợp đó, bạn có thể chỉ định attribute bằng method `attributes()`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
client
    .mutateWith(mockOpaqueToken()
        .attributes((attrs) -> attrs.put("user_id", "1234"))
    )
    .get().uri("/endpoint").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
client
    .mutateWith(mockOpaqueToken()
        .attributes { attrs -> attrs["user_id"] = "1234" }
    )
    .get().uri("/endpoint").exchange()
----
======

[[webflux-testing-opaque-token-principal]]
=== Cấu hình bổ sung

Bạn cũng có thể sử dụng các method bổ sung để cấu hình thêm authentication, tùy thuộc vào dữ liệu mà controller của bạn mong đợi.

Một method như vậy là `principal(OAuth2AuthenticatedPrincipal)`, method này cho phép bạn cấu hình instance `OAuth2AuthenticatedPrincipal` hoàn chỉnh nằm bên dưới `BearerTokenAuthentication`.

Method này hữu ích nếu bạn:
* Có implementation riêng của `OAuth2AuthenticatedPrincipal` hoặc
* Muốn chỉ định tên principal khác

Ví dụ, giả sử authorization server của bạn gửi tên principal trong attribute `user_name` thay vì attribute `sub`.
Trong trường hợp đó, bạn có thể tự cấu hình một `OAuth2AuthenticatedPrincipal`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
Map<String, Object> attributes = Collections.singletonMap("user_name", "foo_user");
OAuth2AuthenticatedPrincipal principal = new DefaultOAuth2AuthenticatedPrincipal(
        (String) attributes.get("user_name"),
        attributes,
        AuthorityUtils.createAuthorityList("SCOPE_message:read"));

client
    .mutateWith(mockOpaqueToken().principal(principal))
    .get().uri("/endpoint").exchange();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
val attributes: Map<String, Any> = mapOf(Pair("user_name", "foo_user"))
val principal: OAuth2AuthenticatedPrincipal = DefaultOAuth2AuthenticatedPrincipal(
    attributes["user_name"] as String?,
    attributes,
    AuthorityUtils.createAuthorityList("SCOPE_message:read")
)

client
    .mutateWith(mockOpaqueToken().principal(principal))
    .get().uri("/endpoint").exchange()
----
======

Lưu ý rằng, thay cho phần hỗ trợ kiểm thử `mockOpaqueToken()`, bạn cũng có thể mock chính bean `OpaqueTokenIntrospector` bằng annotation `@MockBean`.
