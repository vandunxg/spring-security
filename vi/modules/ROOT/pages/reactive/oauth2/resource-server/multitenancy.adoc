= Multi-tenancy trong OAuth 2.0 Resource Server

[[webflux-oauth2resourceserver-multitenancy]]
== Multi-tenancy

Một resource server được xem là multi-tenant khi có nhiều strategy để verify bearer token, với mỗi strategy được gắn với một tenant identifier.

Ví dụ, resource server của bạn có thể accept bearer token từ hai authorization server khác nhau.
Hoặc authorization server của bạn có thể đại diện cho nhiều issuer.

Trong cả hai trường hợp, cần thực hiện hai việc; cách bạn chọn thực hiện mỗi việc sẽ đi kèm với những trade-off:

. Resolve tenant.
. Propagate tenant.

=== Resolve tenant bằng claim

Một cách để phân biệt các tenant là dựa trên issuer claim. Vì issuer claim nằm trong signed JWT, bạn có thể dùng `JwtIssuerReactiveAuthenticationManagerResolver` để thực hiện việc này:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
JwtIssuerReactiveAuthenticationManagerResolver authenticationManagerResolver = JwtIssuerReactiveAuthenticationManagerResolver
    .fromTrustedIssuers("https://idp.example.org/issuerOne", "https://idp.example.org/issuerTwo");

http
    .authorizeExchange((authorize) -> authorize
        .anyExchange().authenticated()
    )
    .oauth2ResourceServer((oauth2) -> oauth2
        .authenticationManagerResolver(authenticationManagerResolver)
    );
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
val customAuthenticationManagerResolver = JwtIssuerReactiveAuthenticationManagerResolver
    .fromTrustedIssuers("https://idp.example.org/issuerOne", "https://idp.example.org/issuerTwo")

return http {
    authorizeExchange {
        authorize(anyExchange, authenticated)
    }
    oauth2ResourceServer {
        authenticationManagerResolver = customAuthenticationManagerResolver
    }
}
----
======

Điểm thuận tiện của cách này là các issuer endpoint được load lazily.
Trên thực tế, `JwtReactiveAuthenticationManager` tương ứng chỉ được instantiate khi request đầu tiên mang issuer tương ứng được gửi đến.
Nhờ đó, application có thể startup độc lập với việc các authorization server đó có đang up và available hay không.

==== Tenant động

Có thể bạn không muốn restart application mỗi khi thêm tenant mới.
Trong trường hợp này, bạn có thể configure `JwtIssuerReactiveAuthenticationManagerResolver` bằng một repository chứa các instance `ReactiveAuthenticationManager`; repository này có thể được chỉnh sửa at runtime:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
private Mono<ReactiveAuthenticationManager> addManager(
		Map<String, ReactiveAuthenticationManager> authenticationManagers, String issuer) {

	return Mono.fromCallable(() -> ReactiveJwtDecoders.fromIssuerLocation(issuer))
            .subscribeOn(Schedulers.boundedElastic())
            .map(JwtReactiveAuthenticationManager::new)
            .doOnNext((authenticationManager) -> authenticationManager.put(issuer, authenticationManager));
}

// ...

JwtIssuerReactiveAuthenticationManagerResolver authenticationManagerResolver =
        new JwtIssuerReactiveAuthenticationManagerResolver(authenticationManagers::get);

http
    .authorizeExchange((authorize) -> authorize
        .anyExchange().authenticated()
    )
    .oauth2ResourceServer((oauth2) -> oauth2
        .authenticationManagerResolver(authenticationManagerResolver)
    );
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
private fun addManager(
        authenticationManagers: MutableMap<String, ReactiveAuthenticationManager>, issuer: String): Mono<JwtReactiveAuthenticationManager> {
    return Mono.fromCallable { ReactiveJwtDecoders.fromIssuerLocation(issuer) }
            .subscribeOn(Schedulers.boundedElastic())
            .map { jwtDecoder: ReactiveJwtDecoder -> JwtReactiveAuthenticationManager(jwtDecoder) }
            .doOnNext { authenticationManager: JwtReactiveAuthenticationManager -> authenticationManagers[issuer] = authenticationManager }
}

// ...

var customAuthenticationManagerResolver = JwtIssuerReactiveAuthenticationManagerResolver(authenticationManagers::get)
return http {
    authorizeExchange {
        authorize(anyExchange, authenticated)
    }
    oauth2ResourceServer {
        authenticationManagerResolver = customAuthenticationManagerResolver
    }
}
----
======

Trong trường hợp này, bạn construct `JwtIssuerReactiveAuthenticationManagerResolver` với một strategy để lấy `ReactiveAuthenticationManager` tương ứng với issuer.
Cách này cho phép chúng ta thêm và xóa các phần tử khỏi repository (được biểu diễn dưới dạng `Map` trong snippet trước) at runtime.

[NOTE]
====
Sẽ không an toàn nếu chỉ lấy bất kỳ issuer nào rồi construct một `ReactiveAuthenticationManager` từ issuer đó.
Issuer phải là issuer mà code có thể verify từ một trusted source, chẳng hạn như allowlist các issuer.
====
