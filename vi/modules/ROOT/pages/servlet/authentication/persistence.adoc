[[persistant]]
= Lưu trữ Authentication
:figures: servlet/authentication

Lần đầu user request một protected resource, họ sẽ được xref:servlet/authentication/architecture.adoc#servlet-authentication-authenticationentrypoint[yêu cầu cung cấp credential].
Một trong những cách phổ biến nhất để yêu cầu credential là redirect user đến xref:servlet/authentication/passwords/form.adoc[trang login].
Một HTTP exchange được tóm tắt cho user unauthenticated đang request một protected resource có thể như sau:

.User chưa authenticated request protected resource
====
[source,http]
----
GET / HTTP/1.1
Host: example.com
Cookie: SESSION=91470ce0-3f3c-455b-b7ad-079b02290f7b
----

[source,http]
----
HTTP/1.1 302 Found
Location: /login
----
====

User submit username và password của họ.

.Username và password được submit
[source,http]
----
POST /login HTTP/1.1
Host: example.com
Cookie: SESSION=91470ce0-3f3c-455b-b7ad-079b02290f7b

username=user&password=password&_csrf=35942e65-a172-4cd4-a1d4-d16a51147b3e
----

Sau khi authenticate user, user được associate với một session ID mới để ngăn xref:servlet/authentication/session-management.adoc#ns-session-fixation[session fixation attack].

.User authenticated được associate với session mới
[source,http]
----
HTTP/1.1 302 Found
Location: /
Set-Cookie: SESSION=4c66e474-3f5a-43ed-8e48-cc1d8cb1d1c8; Path=/; HttpOnly; SameSite=Lax
----

Các request tiếp theo include session cookie được dùng để authenticate user trong phần còn lại của session.

.Authenticated session được cung cấp làm credential
[source,http]
----
GET / HTTP/1.1
Host: example.com
Cookie: SESSION=4c66e474-3f5a-43ed-8e48-cc1d8cb1d1c8
----


[[securitycontextrepository]]
== SecurityContextRepository

// FIXME: tài liệu API
Trong Spring Security, việc associate user với các request tiếp theo được thực hiện bằng javadoc:org.springframework.security.web.context.SecurityContextRepository[].
Implementation mặc định của `SecurityContextRepository` là javadoc:org.springframework.security.web.context.DelegatingSecurityContextRepository[] và delegate đến các thành phần sau:

* <<httpsecuritycontextrepository,`HttpSessionSecurityContextRepository`>>
* <<requestattributesecuritycontextrepository,`RequestAttributeSecurityContextRepository`>>

[[httpsecuritycontextrepository]]
=== HttpSessionSecurityContextRepository

javadoc:org.springframework.security.web.context.HttpSessionSecurityContextRepository[] thực hiện việc associate xref:servlet/authentication/architecture.adoc#servlet-authentication-securitycontext[`SecurityContext`] với `HttpSession`.
User có thể thay thế `HttpSessionSecurityContextRepository` bằng một implementation khác của `SecurityContextRepository` nếu muốn associate user với các request tiếp theo theo cách khác hoặc hoàn toàn không associate.

[[nullsecuritycontextrepository]]
=== NullSecurityContextRepository

Nếu không muốn associate `SecurityContext` với `HttpSession` (ví dụ khi authenticate bằng OAuth), javadoc:org.springframework.security.web.context.NullSecurityContextRepository[] là một implementation của `SecurityContextRepository` không làm gì cả.

[[requestattributesecuritycontextrepository]]
=== RequestAttributeSecurityContextRepository

javadoc:org.springframework.security.web.context.RequestAttributeSecurityContextRepository[] lưu `SecurityContext` dưới dạng một request attribute để bảo đảm `SecurityContext` khả dụng trong một request duy nhất đi qua các dispatch type có thể clear `SecurityContext`.

Ví dụ, giả sử client thực hiện một request, được authenticated, sau đó xảy ra error.
Tùy thuộc vào implementation của servlet container, error có thể khiến mọi `SecurityContext` đã được thiết lập bị clear, sau đó thực hiện error dispatch.
Khi error dispatch được thực hiện, không có `SecurityContext` nào được thiết lập.
Điều này có nghĩa là error page không thể dùng `SecurityContext` cho authorization hoặc hiển thị current user, trừ khi `SecurityContext` được persist bằng cách nào đó.

.Sử dụng RequestAttributeSecurityContextRepository
[tabs]
======
Java::
+
[source,java,role="primary"]
----
public SecurityFilterChain filterChain(HttpSecurity http) {
	http
		// ...
		.securityContext((securityContext) -> securityContext
			.securityContextRepository(new RequestAttributeSecurityContextRepository())
		);
	return http.build();
}
----

XML::
+
[source,xml,role="secondary"]
----
<http security-context-repository-ref="contextRepository">
	<!-- ... -->
</http>
<b:bean name="contextRepository"
	class="org.springframework.security.web.context.RequestAttributeSecurityContextRepository" />
----
======

[[delegatingsecuritycontextrepository]]
=== DelegatingSecurityContextRepository

javadoc:org.springframework.security.web.context.DelegatingSecurityContextRepository[] lưu `SecurityContext` vào nhiều delegate `SecurityContextRepository` và cho phép lấy lại từ bất kỳ delegate nào theo thứ tự được chỉ định.

Cấu hình hữu ích nhất cho trường hợp này được thể hiện trong ví dụ sau, cho phép dùng đồng thời cả xref:requestattributesecuritycontextrepository[`RequestAttributeSecurityContextRepository`] và xref:httpsecuritycontextrepository[`HttpSessionSecurityContextRepository`].

.Cấu hình DelegatingSecurityContextRepository
[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
	http
		// ...
		.securityContext((securityContext) -> securityContext
			.securityContextRepository(new DelegatingSecurityContextRepository(
				new RequestAttributeSecurityContextRepository(),
				new HttpSessionSecurityContextRepository()
			))
		);
	return http.build();
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
fun securityFilterChain(http: HttpSecurity): SecurityFilterChain {
	http {
		// ...
		securityContext {
			securityContextRepository = DelegatingSecurityContextRepository(
				RequestAttributeSecurityContextRepository(),
				HttpSessionSecurityContextRepository()
			)
		}
	}
	return http.build()
}
----

XML::
+
[source,xml,role="secondary"]
----
<http security-context-repository-ref="contextRepository">
	<!-- ... -->
</http>
<bean name="contextRepository"
	class="org.springframework.security.web.context.DelegatingSecurityContextRepository">
		<constructor-arg>
			<bean class="org.springframework.security.web.context.RequestAttributeSecurityContextRepository" />
		</constructor-arg>
		<constructor-arg>
			<bean class="org.springframework.security.web.context.HttpSessionSecurityContextRepository" />
		</constructor-arg>
</bean>
----
======

[NOTE]
====
Trong Spring Security 6, ví dụ trên là cấu hình mặc định.
====

[[securitycontextpersistencefilter]]
== SecurityContextPersistenceFilter

javadoc:org.springframework.security.web.context.SecurityContextPersistenceFilter[] chịu trách nhiệm persist `SecurityContext` giữa các request bằng cách sử dụng xref::servlet/authentication/persistence.adoc#securitycontextrepository[`SecurityContextRepository`].

[.invert-dark]
image::{figures}/securitycontextpersistencefilter.png[]

image:{icondir}/number_1.png[] Trước khi chạy phần còn lại của ứng dụng, `SecurityContextPersistenceFilter` load `SecurityContext` từ `SecurityContextRepository` và set nó vào `SecurityContextHolder`.

image:{icondir}/number_2.png[] Tiếp theo, ứng dụng được chạy.

image:{icondir}/number_3.png[] Cuối cùng, nếu `SecurityContext` đã thay đổi, chúng ta save `SecurityContext` bằng `SecurityContextRepository`.
Điều này có nghĩa là khi sử dụng `SecurityContextPersistenceFilter`, chỉ cần set `SecurityContextHolder` là đủ để bảo đảm `SecurityContext` được persist bằng `SecurityContextRepository`.

Trong một số trường hợp, response được commit và ghi vào client trước khi method của `SecurityContextPersistenceFilter` hoàn tất.
Ví dụ, nếu một redirect được gửi đến client, response ngay lập tức được ghi về client.
Điều này có nghĩa là không thể thiết lập một `HttpSession` ở bước 3 vì session ID không thể được đưa vào response đã được ghi.
Một tình huống khác có thể xảy ra khi client authenticate thành công, response được commit trước khi `SecurityContextPersistenceFilter` hoàn tất, và client thực hiện request thứ hai trước khi `SecurityContextPersistenceFilter` hoàn tất. Khi đó, authentication không đúng có thể xuất hiện trong request thứ hai.


Để tránh các vấn đề này, `SecurityContextPersistenceFilter` wrap cả `HttpServletRequest` và `HttpServletResponse` để phát hiện `SecurityContext` có thay đổi hay không và, nếu có, save `SecurityContext` ngay trước khi response được commit.

[[securitycontextholderfilter]]
== SecurityContextHolderFilter

javadoc:org.springframework.security.web.context.SecurityContextHolderFilter[] chịu trách nhiệm load `SecurityContext` giữa các request bằng cách sử dụng xref::servlet/authentication/persistence.adoc#securitycontextrepository[`SecurityContextRepository`].

[.invert-dark]
image::{figures}/securitycontextholderfilter.png[]

image:{icondir}/number_1.png[] Trước khi chạy phần còn lại của ứng dụng, `SecurityContextHolderFilter` load `SecurityContext` từ `SecurityContextRepository` và set nó vào `SecurityContextHolder`.

image:{icondir}/number_2.png[] Tiếp theo, ứng dụng được chạy.

Không giống xref:servlet/authentication/persistence.adoc#securitycontextpersistencefilter[`SecurityContextPersistenceFilter`], `SecurityContextHolderFilter` chỉ load `SecurityContext`, không save `SecurityContext`.
Điều này có nghĩa là khi sử dụng `SecurityContextHolderFilter`, bắt buộc phải save `SecurityContext` một cách tường minh.
