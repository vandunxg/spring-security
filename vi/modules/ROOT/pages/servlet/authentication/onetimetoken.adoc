[[one-time-token-login]]
= Đăng nhập bằng One-Time Token

Spring Security hỗ trợ authentication bằng One-Time Token (OTT) thông qua DSL `oneTimeTokenLogin()`.
Trước khi đi vào chi tiết triển khai, cần làm rõ phạm vi của tính năng OTT trong framework, nêu rõ những gì được hỗ trợ và những gì không được hỗ trợ.

== Tìm hiểu One-Time Token và One-Time Password

One-Time Token (OTT) thường bị nhầm lẫn với https://en.wikipedia.org/wiki/One-time_password[One-Time Password] (OTP), nhưng trong Spring Security, hai khái niệm này khác nhau ở một số điểm chính.
Để rõ ràng, trong tài liệu này OTP được hiểu là https://en.wikipedia.org/wiki/Time-based_one-time_password[TOTP] (Time-Based One-Time Password) hoặc https://en.wikipedia.org/wiki/HMAC-based_one-time_password[HOTP] (HMAC-Based One-Time Password).

=== Yêu cầu thiết lập

- OTT: Không yêu cầu thiết lập ban đầu. Người dùng không cần cấu hình trước bất kỳ điều gì.
- OTP: Thông thường yêu cầu thiết lập, chẳng hạn như tạo và chia sẻ một secret key với một công cụ bên ngoài để tạo các one-time password.

=== Phân phối token

- OTT: Thông thường cần triển khai một javadoc:org.springframework.security.web.authentication.ott.OneTimeTokenGenerationSuccessHandler[] tùy chỉnh, chịu trách nhiệm phân phối token đến người dùng cuối.
- OTP: Token thường được tạo bởi một công cụ bên ngoài, vì vậy không cần gửi token đến người dùng thông qua ứng dụng.

=== Tạo token

- OTT: Method javadoc:org.springframework.security.authentication.ott.OneTimeTokenService#generate(org.springframework.security.authentication.ott.GenerateOneTimeTokenRequest)[] yêu cầu trả về một javadoc:org.springframework.security.authentication.ott.OneTimeToken[], nhấn mạnh việc tạo token ở phía server.
- OTP: Token không nhất thiết được tạo ở phía server; thường được tạo bởi client bằng secret đã chia sẻ.

Tóm lại, One-Time Token (OTT) cung cấp một cách để authentication người dùng mà không cần thiết lập tài khoản bổ sung, khác với One-Time Password (OTP), vốn thường có quy trình thiết lập phức tạp hơn và dựa vào các công cụ bên ngoài để tạo token.

Đăng nhập bằng One-Time Token hoạt động qua hai bước chính.

1. Người dùng yêu cầu token bằng cách gửi user identifier, thường là username, và token được phân phối đến họ, thường dưới dạng Magic Link, qua email, SMS, v.v.
2. Người dùng gửi token đến endpoint đăng nhập bằng one-time token và nếu token hợp lệ, người dùng sẽ được đăng nhập.

== Trang đăng nhập mặc định và trang gửi One-Time Token mặc định

Khi sử dụng DSL `oneTimeTokenLogin()`, theo mặc định, trang đăng nhập bằng One-Time Token được tự động tạo bởi javadoc:org.springframework.security.web.authentication.ui.DefaultLoginPageGeneratingFilter[].
DSL cũng thiết lập javadoc:org.springframework.security.web.authentication.ui.DefaultOneTimeTokenSubmitPageGeneratingFilter[] để tạo trang gửi One-Time Token mặc định.

== Gửi token đến người dùng

Spring Security không thể xác định một cách hợp lý phương thức phân phối token đến người dùng của bạn.
Do đó, cần cung cấp một javadoc:org.springframework.security.web.authentication.ott.OneTimeTokenGenerationSuccessHandler[] tùy chỉnh để phân phối token đến người dùng theo nhu cầu của bạn.
Một trong những chiến lược phân phối phổ biến nhất là Magic Link, qua email, SMS, v.v.

== Tùy chỉnh cách tạo và sử dụng One-Time Token

Interface định nghĩa các thao tác chung để tạo và sử dụng one-time token là javadoc:org.springframework.security.authentication.ott.OneTimeTokenService[].
Nếu không cung cấp implementation nào, Spring Security sử dụng javadoc:org.springframework.security.authentication.ott.InMemoryOneTimeTokenService[] làm implementation mặc định của interface đó.
Trong môi trường production, hãy cân nhắc sử dụng javadoc:org.springframework.security.authentication.ott.JdbcOneTimeTokenService[].

Một số lý do phổ biến nhất để tùy chỉnh `OneTimeTokenService` bao gồm, nhưng không giới hạn ở:

- Thay đổi thời gian hết hạn của one-time token
- Lưu thêm thông tin từ request tạo token
- Thay đổi cách tạo giá trị token
- Bổ sung validation khi sử dụng one-time token

Có hai lựa chọn để tùy chỉnh `OneTimeTokenService`.

[[validating-account-status]]
== Xác thực trạng thái tài khoản

Theo mặc định, javadoc:org.springframework.security.authentication.ott.OneTimeTokenAuthenticationProvider[] không validation trạng thái của tài khoản đã authentication, chẳng hạn tài khoản có bị khóa, bị vô hiệu hóa hoặc hết hạn hay không.
Điều này giữ cho hành vi của provider nhất quán với các phiên bản Spring Security trước đây; mặc định này có thể thay đổi trong các phiên bản Spring Security tương lai.

Nếu muốn `OneTimeTokenAuthenticationProvider` từ chối authentication bằng One-Time Token đối với các tài khoản như vậy, hãy cung cấp cho nó một javadoc:org.springframework.security.core.userdetails.UserDetailsChecker[], chẳng hạn javadoc:org.springframework.security.authentication.AccountStatusUserDetailsChecker[], bằng `setUserDetailsChecker`:
