[[one-time-token-login]]
= Đăng nhập bằng One-Time Token

Spring Security hỗ trợ authentication bằng One-Time Token (OTT) thông qua DSL `oneTimeTokenLogin()`.
Trước khi đi vào chi tiết triển khai, cần làm rõ phạm vi của tính năng OTT trong framework, bao gồm những gì được hỗ trợ và những gì không được hỗ trợ.

== Tìm hiểu One-Time Token và One-Time Password

One-Time Token (OTT) thường bị nhầm lẫn với https://en.wikipedia.org/wiki/One-time_password[One-Time Password] (OTP), nhưng trong Spring Security, hai khái niệm này khác nhau ở một số điểm quan trọng.
Để rõ ràng, trong tài liệu này OTP được hiểu là https://en.wikipedia.org/wiki/Time-based_one-time_password[TOTP] (Time-Based One-Time Password) hoặc https://en.wikipedia.org/wiki/HMAC-based_one-time_password[HOTP] (HMAC-Based One-Time Password).

=== Yêu cầu setup

- OTT: Không cần setup ban đầu. Người dùng không cần cấu hình gì trước.
- OTP: Thông thường cần setup, chẳng hạn như tạo và chia sẻ một secret key với một external tool để tạo one-time passwords.

=== Token delivery

- OTT: Thông thường cần triển khai một javadoc:org.springframework.security.web.authentication.ott.OneTimeTokenGenerationSuccessHandler[] tùy chỉnh, chịu trách nhiệm delivery token đến end user.
- OTP: Token thường được generate bởi một external tool, vì vậy không cần delivery token đến user qua application.

=== Token generation

- OTT: Method javadoc:org.springframework.security.authentication.ott.OneTimeTokenService#generate(org.springframework.security.authentication.ott.GenerateOneTimeTokenRequest)[] yêu cầu trả về một javadoc:org.springframework.security.authentication.ott.OneTimeToken[], nhấn mạnh việc generate token ở server-side.
- OTP: Token không nhất thiết được generate ở server-side; thường được client tạo bằng shared secret.

Tóm lại, One-Time Token (OTT) cung cấp một cách để authenticate user mà không cần setup account bổ sung, khác với One-Time Password (OTP), vốn thường có quy trình setup phức tạp hơn và dựa vào external tool để generate token.

Đăng nhập bằng One-Time Token hoạt động qua hai bước chính.

1. User submit user identifier để request token, thường là username, và token được delivery đến họ, thường dưới dạng Magic Link, qua e-mail, SMS, v.v.
2. User submit token đến one-time token login endpoint; nếu token hợp lệ, user sẽ được authenticated.

[[default-pages]]
== Default Login Page và Default One-Time Token Submit Page

Khi sử dụng DSL `oneTimeTokenLogin()`, theo mặc định, One-Time Token Login Page được auto-generate bởi javadoc:org.springframework.security.web.authentication.ui.DefaultLoginPageGeneratingFilter[].
DSL cũng thiết lập javadoc:org.springframework.security.web.authentication.ui.DefaultOneTimeTokenSubmitPageGeneratingFilter[] để generate default One-Time Token submit page.

[[sending-token-to-user]]
== Token delivery đến user

[[customize-generate-consume-token]]
== Customize cách generate và consume One-Time Token

Interface định nghĩa các operation chung để generate và consume one-time token là javadoc:org.springframework.security.authentication.ott.OneTimeTokenService[].
Nếu không cung cấp implementation nào, Spring Security sử dụng javadoc:org.springframework.security.authentication.ott.InMemoryOneTimeTokenService[] làm default implementation của interface đó.
Trong production, hãy cân nhắc sử dụng javadoc:org.springframework.security.authentication.ott.JdbcOneTimeTokenService[].

Một số lý do phổ biến nhất để customize `OneTimeTokenService` bao gồm, nhưng không giới hạn ở:

- Thay đổi expire time của one-time token
- Lưu thêm information từ generate token request
- Thay đổi cách generate token value
- Bổ sung validation khi consume one-time token

Có hai option để customize `OneTimeTokenService`.

[[validating-account-status]]
== Validate trạng thái account

Theo mặc định, javadoc:org.springframework.security.authentication.ott.OneTimeTokenAuthenticationProvider[] không validate trạng thái của account đã authenticated, chẳng hạn account có bị locked, disabled hoặc expired hay không.
Điều này giúp behavior của provider nhất quán với các version Spring Security trước đây; default này có thể thay đổi trong các version Spring Security tương lai.

Nếu muốn `OneTimeTokenAuthenticationProvider` reject One-Time Token authentication đối với các account như vậy, hãy cung cấp cho nó một javadoc:org.springframework.security.core.userdetails.UserDetailsChecker[], chẳng hạn javadoc:org.springframework.security.authentication.AccountStatusUserDetailsChecker[], thông qua `setUserDetailsChecker`:
