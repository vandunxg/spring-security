= Form Login
:figures: servlet/authentication/unpwd

Phần này trình bày chi tiết cách form-based authentication hoạt động trong Spring Security.

[[servlet-authentication-usernamepasswordauthenticationfilter]]
Khi username và password được submit, `UsernamePasswordAuthenticationFilter` tạo một `UsernamePasswordAuthenticationToken`, là một kiểu xref:servlet/authentication/architecture.adoc#servlet-authentication-authentication[Authentication], bằng cách extract username và password từ instance `HttpServletRequest`.
`UsernamePasswordAuthenticationFilter` mở rộng xref:servlet/authentication/architecture.adoc#servlet-authentication-abstractprocessingfilter[AbstractAuthenticationProcessingFilter], vì vậy sơ đồ sau đây sẽ khá giống:

.Authenticate username và password

image::{figures}/usernamepasswordauthenticationfilter.png[]

Hình minh họa được xây dựng dựa trên sơ đồ xref:servlet/architecture.adoc#servlet-securityfilterchain[`SecurityFilterChain`] của chúng ta.


image:{icondir}/number_1.png[] Khi user submit username và password, `UsernamePasswordAuthenticationFilter` tạo một `UsernamePasswordAuthenticationToken`, là một kiểu xref:servlet/authentication/architecture.adoc#servlet-authentication-authentication[`Authentication`], bằng cách extract username và password từ instance `HttpServletRequest`.

image:{icondir}/number_2.png[]  Tiếp theo, `UsernamePasswordAuthenticationToken` được truyền cho instance `AuthenticationManager` để authenticate.

Xem interface javadoc:org.springframework.security.web.authentication.session.SessionAuthenticationStrategy[] trong Javadoc.

[[servlet-authentication-form-min]]
Theo mặc định, form login của Spring Security được enabled.
Tuy nhiên, ngay khi cung cấp bất kỳ cấu hình dựa trên Servlet nào, form-based login phải được cấu hình rõ ràng.
Ví dụ sau đây cho thấy một cấu hình Java rõ ràng, tối thiểu:

.Form Login
[tabs]
======
Java::
+
[source,java,role="primary"]
----
public SecurityFilterChain filterChain(HttpSecurity http) {
	http
		.formLogin(withDefaults());
	// ...
}
----

XML::
+
[source,xml,role="secondary"]
----
<http>
	<!-- ... -->
	<form-login />
</http>
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
open fun filterChain(http: HttpSecurity): SecurityFilterChain {
	http {
		formLogin { }
	}
	// ...
}
----
======

Trong cấu hình trên, Spring Security render login page mặc định.
Hầu hết application chạy trong production đều yêu cầu custom login form.

[[servlet-authentication-form-custom]]
Cấu hình sau đây minh họa cách cung cấp custom login form.

.Cấu hình custom login form
[tabs]
======
Java::
+
[source,java,role="primary"]
----
public SecurityFilterChain filterChain(HttpSecurity http) {
	http
		.formLogin((form) -> form
			.loginPage("/login")
			.permitAll()
		);
	// ...
}
----

XML::
+
[source,xml,role="secondary"]
----
<http>
	<!-- ... -->
	<intercept-url pattern="/login" access="permitAll" />
	<form-login login-page="/login" />
</http>
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
open fun filterChain(http: HttpSecurity): SecurityFilterChain {
	http {
		formLogin {
			loginPage = "/login"
			permitAll()
		}
	}
	// ...
}
----
======

[NOTE]
====
URI được truyền cho `loginPage` (và cho `loginProcessingUrl`, nếu được set riêng) được match và redirect nguyên văn.
Nếu custom login page của bạn được serve bởi một Servlet application được map dưới một base path, hãy include prefix đó trong URI bạn truyền cho DSL.
Ví dụ, nếu dispatcher của bạn ở `/api/*`:

include-code::./FormLoginServletPathConfiguration[tag=loginPage,indent=0]
====

[[servlet-authentication-form-custom-html]]
Khi login page được chỉ định trong cấu hình Spring Security, bạn chịu trách nhiệm render login page đó.
// FIXME: trang đăng nhập mặc định do Spring Security render
Template https://www.thymeleaf.org/[Thymeleaf] sau đây tạo ra một login form HTML tương thích với login page tại `/login`:

.Form đăng nhập - src/main/resources/templates/login.html
[source,xml]
----
<!DOCTYPE html>
<html xmlns="http://www.w3.org/1999/xhtml" xmlns:th="https://www.thymeleaf.org">
	<head>
		<title>Please Log In</title>
	</head>
	<body>
		<h1>Please Log In</h1>
		<div th:if="${param.error}">
			Invalid username and password.</div>
		<div th:if="${param.logout}">
			You have been logged out.</div>
		<form th:action="@{/login}" method="post">
			<div>
			<input type="text" name="username" placeholder="Username"/>
			</div>
			<div>
			<input type="password" name="password" placeholder="Password"/>
			</div>
			<input type="submit" value="Log in" />
		</form>
	</body>
</html>
----

Có một số điểm chính về HTML form mặc định:

* Form phải gửi `post` đến `/login`.
* Form cần bao gồm xref:servlet/exploits/csrf.adoc#servlet-csrf[CSRF Token], được Thymeleaf xref:servlet/exploits/csrf.adoc#csrf-integration-form[tự động đưa vào].
* Form phải chỉ định username trong một parameter có tên `username`.
* Form phải chỉ định password trong một parameter có tên `password`.
* Nếu tìm thấy HTTP parameter có tên `error`, điều đó cho biết user không cung cấp username hoặc password hợp lệ.
* Nếu tìm thấy HTTP parameter có tên `logout`, điều đó cho biết user đã logout thành công.

Nhiều user không cần làm gì nhiều ngoài việc customize login page.
Tuy nhiên, nếu cần, bạn có thể customize mọi thứ được trình bày trước đó bằng cấu hình bổ sung.

[[servlet-authentication-form-custom-controller]]
Nếu sử dụng Spring MVC, bạn cần một controller map `GET /login` tới login template đã tạo.
Ví dụ sau đây cho thấy một `LoginController` tối thiểu:

.LoginController
[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Controller
class LoginController {
	@GetMapping("/login")
	String login() {
		return "login";
	}
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Controller
class LoginController {
    @GetMapping("/login")
    fun login(): String {
        return "login"
    }
}
----
======
