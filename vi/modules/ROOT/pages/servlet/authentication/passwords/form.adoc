[[servlet-authentication-usernamepasswordauthenticationfilter]]
Khi username và password được gửi, `UsernamePasswordAuthenticationFilter` tạo một `UsernamePasswordAuthenticationToken`, là một kiểu xref:servlet/authentication/architecture.adoc#servlet-authentication-authentication[Authentication], bằng cách trích xuất username và password từ instance `HttpServletRequest`.
`UsernamePasswordAuthenticationFilter` mở rộng xref:servlet/authentication/architecture.adoc#servlet-authentication-abstractprocessingfilter[AbstractAuthenticationProcessingFilter], vì vậy sơ đồ sau đây sẽ khá tương tự:

.Authentication username và password
[.invert-dark]
image::{figures}/usernamepasswordauthenticationfilter.png[]

Hình minh họa được xây dựng dựa trên sơ đồ xref:servlet/architecture.adoc#servlet-securityfilterchain[`SecurityFilterChain`] của chúng ta.


image:{icondir}/number_1.png[] Khi người dùng gửi username và password, `UsernamePasswordAuthenticationFilter` tạo một `UsernamePasswordAuthenticationToken`, là một kiểu xref:servlet/authentication/architecture.adoc#servlet-authentication-authentication[`Authentication`], bằng cách trích xuất username và password từ instance `HttpServletRequest`.

image:{icondir}/number_2.png[]  Tiếp theo, `UsernamePasswordAuthenticationToken` được truyền vào instance `AuthenticationManager` để được authentication.
Chi tiết về hình dạng của `AuthenticationManager` phụ thuộc vào cách xref:servlet/authentication/passwords/index.adoc#servlet-authentication-unpwd-storage[thông tin người dùng được lưu trữ].

image:{icondir}/number_4.png[] Nếu authentication thành công thì __Thành công__.

[[servlet-authentication-form-min]]
Theo mặc định, Form Login của Spring Security được bật.
Tuy nhiên, ngay khi cung cấp bất kỳ cấu hình dựa trên Servlet nào, Form Login phải được cung cấp rõ ràng.
Ví dụ sau đây cho thấy một cấu hình Java rõ ràng, tối thiểu:

.Form Login
[tabs]
======
Java::
+
[source,java,role="primary"]
----
public SecurityFilterChain filterChain(HttpSecurity http) {
	http
		.formLogin(withDefaults());
	// ...
}
----

XML::
+
[source,xml,role="secondary"]
----
<http>
	<!-- ... -->
	<form-login />
</http>
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
open fun filterChain(http: HttpSecurity): SecurityFilterChain {
	http {
		formLogin { }
	}
	// ...
}
----
======

Trong cấu hình trước, Spring Security render trang đăng nhập mặc định.
Hầu hết ứng dụng dùng trong production đều yêu cầu form đăng nhập tùy chỉnh.

[[servlet-authentication-form-custom]]
Cấu hình sau đây minh họa cách cung cấp form đăng nhập tùy chỉnh.

.Cấu hình form đăng nhập tùy chỉnh
[tabs]
======
Java::
+
[source,java,role="primary"]
----
public SecurityFilterChain filterChain(HttpSecurity http) {
	http
		.formLogin((form) -> form
			.loginPage("/login")
			.permitAll()
		);
	// ...
}
----

XML::
+
[source,xml,role="secondary"]
----
<http>
	<!-- ... -->
	<intercept-url pattern="/login" access="permitAll" />
	<form-login login-page="/login" />
</http>
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
open fun filterChain(http: HttpSecurity): SecurityFilterChain {
	http {
		formLogin {
			loginPage = "/login"
			permitAll()
		}
	}
	// ...
}
----
======

[NOTE]
====
URI được truyền cho `loginPage` (và cho `loginProcessingUrl`, nếu được đặt riêng) được đối sánh và chuyển hướng nguyên văn.
Nếu trang đăng nhập tùy chỉnh của bạn được phục vụ bởi một application Servlet được mapping dưới một base path, hãy include prefix đó trong URI bạn truyền cho DSL.
Ví dụ, nếu dispatcher của bạn ở `/api/*`:

include-code::./FormLoginServletPathConfiguration[tag=loginPage,indent=0]
====

[[servlet-authentication-form-custom-html]]
Khi trang đăng nhập được chỉ định trong cấu hình Spring Security, bạn chịu trách nhiệm render trang đó.
// FIXME: trang đăng nhập mặc định do Spring Security render
Template https://www.thymeleaf.org/[Thymeleaf] sau đây tạo ra một form đăng nhập HTML tương thích với trang đăng nhập tại `/login`.:

.Form đăng nhập - src/main/resources/templates/login.html
[source,xml]
----
<!DOCTYPE html>
<html xmlns="http://www.w3.org/1999/xhtml" xmlns:th="https://www.thymeleaf.org">
	<head>
		<title>Please Log In</title>
	</head>
	<body>
		<h1>Please Log In</h1>
		<div th:if="${param.error}">
			Invalid username and password.</div>
		<div th:if="${param.logout}">
			You have been logged out.</div>
		<form th:action="@{/login}" method="post">
			<div>
			<input type="text" name="username" placeholder="Username"/>
			</div>
			<div>
			<input type="password" name="password" placeholder="Password"/>
			</div>
			<input type="submit" value="Log in" />
		</form>
	</body>
</html>
----

Có một số điểm chính về form HTML mặc định:

* Form phải thực hiện `post` đến `/login`.
* Form cần bao gồm xref:servlet/exploits/csrf.adoc#servlet-csrf[CSRF Token], được Thymeleaf xref:servlet/exploits/csrf.adoc#csrf-integration-form[tự động đưa vào].
* Form phải chỉ định username trong một parameter có tên `username`.
* Form phải chỉ định password trong một parameter có tên `password`.
* Nếu tìm thấy HTTP parameter có tên `error`, điều đó cho biết người dùng không cung cấp username hoặc password hợp lệ.
* Nếu tìm thấy HTTP parameter có tên `logout`, điều đó cho biết người dùng đã logout thành công.

Nhiều người dùng không cần làm gì nhiều ngoài việc tùy chỉnh trang đăng nhập.
Tuy nhiên, nếu cần, bạn có thể tùy chỉnh mọi thứ đã trình bày ở trên bằng cấu hình bổ sung.

[[servlet-authentication-form-custom-controller]]
Nếu sử dụng Spring MVC, bạn cần một controller mapping `GET /login` tới template đăng nhập đã tạo.
Ví dụ sau đây cho thấy một `LoginController` tối thiểu:

.LoginController
[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Controller
class LoginController {
	@GetMapping("/login")
	String login() {
		return "login";
	}
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Controller
class LoginController {
    @GetMapping("/login")
    fun login(): String {
        return "login"
    }
}
----
======
