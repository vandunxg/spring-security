== Xóa credential

Sau khi authentication thành công, một thực hành tốt về bảo mật là xóa credential khỏi bộ nhớ để ngăn chúng bị lộ do các cuộc tấn công memory dump tiềm ẩn.
`ProviderManager` trong Spring Security hỗ trợ thực hành này thông qua method `eraseCredentials`, method này nên được gọi sau khi quy trình authentication hoàn tất.

=== Các thực hành tốt nhất

* *Xóa ngay*: Credential phải được xóa ngay sau khi không còn cần thiết, giúp giảm thiểu khoảng thời gian credential bị lộ trong bộ nhớ.
* *Xóa tự động*: Cấu hình `ProviderManager` tự động xóa credential sau authentication bằng cách đặt `eraseCredentialsAfterAuthentication` thành `true` (mặc định).
* *Chiến lược xóa tùy chỉnh*: Triển khai các chiến lược xóa tùy chỉnh trong các implementation `AuthenticationManager` tùy chỉnh nếu hành vi xóa mặc định không đáp ứng các yêu cầu bảo mật cụ thể.

=== Đánh giá rủi ro

Việc không xóa credential đúng cách có thể dẫn đến một số rủi ro:

* *Tấn công truy cập bộ nhớ*: Kẻ tấn công có thể truy cập credential dạng raw từ bộ nhớ thông qua các exploit như tấn công buffer overflow hoặc memory dump.
* *Mối đe dọa nội bộ*: Người nội gián độc hại có quyền truy cập hệ thống có thể trích xuất credential từ bộ nhớ ứng dụng.
* *Lộ ngoài ý muốn*: Trong môi trường multi-tenant, credential còn tồn tại trong bộ nhớ có thể vô tình bị lộ cho các tenant khác.

=== Triển khai

[source,java]
----
public class CustomAuthenticationManager implements AuthenticationManager {

	@Override
	public Authentication authenticate(Authentication authenticationRequest)
			throws AuthenticationException {

		Authentication authenticationResult;
		// TODO: Perform authentication checks...

		// Erase credentials post-check
		if (authenticationResult instanceof CredentialsContainer container) {
			container.eraseCredentials();
		}
	}

}
----

Bằng cách triển khai các thực hành này, các tổ chức có thể tăng cường đáng kể bảo mật của hệ thống authentication bằng cách bảo đảm credential không bị để lộ trong bộ nhớ hệ thống.
