[[testing-oauth2]]
= Kiểm thử OAuth 2.0

Khi làm việc với OAuth 2.0, các nguyên tắc đã trình bày trước đó vẫn được áp dụng: về cơ bản, điều này phụ thuộc vào những gì method được kiểm thử cần có trong `SecurityContextHolder`.

Ví dụ, với một controller như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public String foo(Principal user) {
    return user.getName();
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(user: Principal): String {
    return user.name
}
----
======

Trường hợp này không có gì đặc thù cho OAuth 2.0, vì vậy bạn chỉ cần xref:servlet/test/method.adoc#test-method-withmockuser[sử dụng `@WithMockUser`] là được.

Tuy nhiên, nếu controller của bạn gắn với một khía cạnh nào đó trong phần hỗ trợ OAuth 2.0 của Spring Security, như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public String foo(@AuthenticationPrincipal OidcUser user) {
    return user.getIdToken().getSubject();
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(@AuthenticationPrincipal user: OidcUser): String {
    return user.idToken.subject
}
----
======

thì test support của Spring Security có thể rất hữu ích.

[[testing-oidc-login]]
== Kiểm thử OIDC Login

Kiểm thử method trên bằng Spring MVC Test sẽ yêu cầu mô phỏng một grant flow với authorization server.
Đây chắc chắn là một task khó, vì vậy Spring Security cung cấp test support để loại bỏ phần boilerplate này.

Ví dụ, chúng ta có thể yêu cầu Spring Security thêm một `OidcUser` mặc định bằng `oidcLogin` xref:servlet/test/mockmvc/request-post-processors.adoc[`RequestPostProcessor`], như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint").with(oidcLogin()));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(oidcLogin())
}
----
======

Thao tác này sẽ configure `MockHttpServletRequest` liên kết với một `OidcUser` bao gồm một `OidcIdToken` đơn giản, `OidcUserInfo` và `Collection` các granted authorities.

Cụ thể, nó sẽ bao gồm một `OidcIdToken` có claim `sub` được set thành `user`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(user.getIdToken().getClaim("sub")).isEqualTo("user");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(user.idToken.getClaim<String>("sub")).isEqualTo("user")
----
======

một `OidcUserInfo` không có claim nào được set:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(user.getUserInfo().getClaims()).isEmpty();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(user.userInfo.claims).isEmpty()
----
======

và một `Collection` các granted authorities chỉ gồm một authority là `SCOPE_read`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(user.getAuthorities()).hasSize(1);
assertThat(user.getAuthorities()).containsExactly(new SimpleGrantedAuthority("SCOPE_read"));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(user.authorities).hasSize(1)
assertThat(user.authorities).containsExactly(SimpleGrantedAuthority("SCOPE_read"))
----
======

Spring Security thực hiện các công việc cần thiết để bảo đảm instance `OidcUser` sẵn sàng cho xref:servlet/integrations/mvc.adoc#mvc-authentication-principal[annotation `@AuthenticationPrincipal`].

Ngoài ra, nó còn liên kết `OidcUser` đó với một instance đơn giản của `OAuth2AuthorizedClient`, rồi đưa instance này vào một mock `OAuth2AuthorizedClientRepository`.
Điều này hữu ích nếu test của bạn <<testing-oauth2-client,sử dụng annotation `@RegisteredOAuth2AuthorizedClient`>>.

Trong trường hợp này, bạn có thể cung cấp các granted authorities cần thiết bằng method `authorities()`:

Kotlin::

}
----
======

[[testing-oidc-login-claims]]
== Cấu hình Claims

Mặc dù granted authorities khá phổ biến trong toàn bộ Spring Security, OAuth 2.0 cũng có các claims.

Ví dụ, giả sử bạn có một claim `user_id` biểu thị ID của user trong system.
Bạn có thể truy cập claim này trong controller như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public String foo(@AuthenticationPrincipal OidcUser oidcUser) {
    String userId = oidcUser.getIdToken().getClaim("user_id");
    // ...
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(@AuthenticationPrincipal oidcUser: OidcUser): String {
    val userId = oidcUser.idToken.getClaim<String>("user_id")
    // ...
}
----
======

Trong trường hợp đó, bạn nên chỉ định claim này bằng method `idToken()`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint")
        .with(oidcLogin()
                .idToken((token) -> token.claim("user_id", "1234"))
        )
    );
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(oidcLogin()
        .idToken {
            it.claim("user_id", "1234")
        }
    )
}
----
======

vì `OidcUser` lấy các claim từ `OidcIdToken`.

[[testing-oidc-login-user]]
== Cấu hình bổ sung

Ngoài ra cũng có các method để configure authentication chi tiết hơn; điều này phụ thuộc vào data mà controller của bạn cần:

* `userInfo(OidcUserInfo.Builder)` - Dùng để configure instance `OidcUserInfo`
* `clientRegistration(ClientRegistration)` - Dùng để configure `OAuth2AuthorizedClient` liên kết với một `ClientRegistration` cụ thể
* `oidcUser(OidcUser)` - Dùng để configure toàn bộ instance `OidcUser`

Method cuối cùng hữu ích nếu bạn:
1. Có implementation riêng của `OidcUser`, hoặc
2. Cần thay đổi thuộc tính name

Ví dụ, giả sử authorization server gửi tên principal trong claim `user_name` thay vì claim `sub`.
Trong trường hợp đó, bạn có thể tự configure một `OidcUser`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
OidcUser oidcUser = new DefaultOidcUser(
        AuthorityUtils.createAuthorityList("SCOPE_message:read"),
        OidcIdToken.withTokenValue("id-token").claim("user_name", "foo_user").build(),
        "user_name");

mvc
    .perform(get("/endpoint")
        .with(oidcLogin().oidcUser(oidcUser))
    );
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
val oidcUser: OidcUser = DefaultOidcUser(
    AuthorityUtils.createAuthorityList("SCOPE_message:read"),
    OidcIdToken.withTokenValue("id-token").claim("user_name", "foo_user").build(),
    "user_name"
)

mvc.get("/endpoint") {
    with(oidcLogin().oidcUser(oidcUser))
}
----
======

[[testing-oauth2-client]]
== Kiểm thử OAuth 2.0 Client

Bất kể user của bạn authenticated như thế nào, request đang được test có thể sử dụng các token và client registration khác.
Ví dụ, controller của bạn có thể dựa vào client credentials grant để lấy một token hoàn toàn không liên kết với user:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public String foo(@RegisteredOAuth2AuthorizedClient("my-app") OAuth2AuthorizedClient authorizedClient) {
    return this.webClient.get()
        .attributes(oauth2AuthorizedClient(authorizedClient))
        .retrieve()
        .bodyToMono(String.class)
        .block();
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(@RegisteredOAuth2AuthorizedClient("my-app") authorizedClient: OAuth2AuthorizedClient?): String? {
    return this.webClient.get()
        .attributes(oauth2AuthorizedClient(authorizedClient))
        .retrieve()
        .bodyToMono(String::class.java)
        .block()
}
----
======

Việc mô phỏng handshake này với authorization server có thể khá phức tạp.
Thay vào đó, bạn có thể dùng `oauth2Client` xref:servlet/test/mockmvc/request-post-processors.adoc[`RequestPostProcessor`] để thêm một `OAuth2AuthorizedClient` vào một mock `OAuth2AuthorizedClientRepository`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint").with(oauth2Client("my-app")));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(
        oauth2Client("my-app")
    )
}
----
======

Thao tác này sẽ tạo một `OAuth2AuthorizedClient` có một `ClientRegistration`, `OAuth2AccessToken` đơn giản và resource owner name.

Cụ thể, nó sẽ bao gồm một `ClientRegistration` có client ID là "test-client" và client secret là "test-secret":

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(authorizedClient.getClientRegistration().getClientId()).isEqualTo("test-client");
assertThat(authorizedClient.getClientRegistration().getClientSecret()).isEqualTo("test-secret");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(authorizedClient.clientRegistration.clientId).isEqualTo("test-client")
assertThat(authorizedClient.clientRegistration.clientSecret).isEqualTo("test-secret")
----
======

resource owner name là "user":

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(authorizedClient.getPrincipalName()).isEqualTo("user");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(authorizedClient.principalName).isEqualTo("user")
----
======

và một `OAuth2AccessToken` chỉ có một scope là `read`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(authorizedClient.getAccessToken().getScopes()).hasSize(1);
assertThat(authorizedClient.getAccessToken().getScopes()).containsExactly("read");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(authorizedClient.accessToken.scopes).hasSize(1)
assertThat(authorizedClient.accessToken.scopes).containsExactly("read")
----
======

Sau đó, client có thể được retrieve như bình thường bằng `@RegisteredOAuth2AuthorizedClient` trong method của controller.

+
[source,java,role="primary"]

@GetMapping("/endpoint")
public String foo(@RegisteredOAuth2AuthorizedClient("my-app") OAuth2AuthorizedClient authorizedClient) {
    Set<String> scopes = authorizedClient.getAccessToken().getScopes();
    if (scopes.contains("message:read")) {
        return this.webClient.get()
            .attributes(oauth2AuthorizedClient(authorizedClient))
            .retrieve()
            .bodyToMono(String.class)
            .block();
    }
    // ...
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(@RegisteredOAuth2AuthorizedClient("my-app") authorizedClient: OAuth2AuthorizedClient): String? {

        return webClient.get()
            .attributes(oauth2AuthorizedClient(authorizedClient))
            .retrieve()
            .bodyToMono(String::class.java)

    // ...
}
----
======

[tabs]

----

Kotlin::
+
[source,kotlin,role="secondary"]
----

    with(oauth2Client("my-app")

[[testing-oauth2-client-registration]]
== Cấu hình bổ sung

Ngoài ra cũng có các method để configure authentication chi tiết hơn; điều này phụ thuộc vào data mà controller của bạn cần:

* `principalName(String)` - Dùng để configure resource owner name
* `clientRegistration(Consumer<ClientRegistration.Builder>)` - Dùng để configure `ClientRegistration` liên kết
* `clientRegistration(ClientRegistration)` - Dùng để configure toàn bộ `ClientRegistration`

Method cuối cùng hữu ích nếu bạn muốn dùng một `ClientRegistration` thực tế.

Ví dụ, giả sử bạn muốn dùng một definition `ClientRegistration` của app, như được chỉ định trong `application.yml`.

Khi đó, test của bạn có thể autowire `ClientRegistrationRepository` và lookup registration cần dùng:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Autowired
ClientRegistrationRepository clientRegistrationRepository;

// ...

mvc
    .perform(get("/endpoint")
        .with(oauth2Client()
            .clientRegistration(this.clientRegistrationRepository.findByRegistrationId("facebook"))));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Autowired
lateinit var clientRegistrationRepository: ClientRegistrationRepository

// ...

mvc.get("/endpoint") {
    with(oauth2Client("my-app")
        .clientRegistration(clientRegistrationRepository.findByRegistrationId("facebook"))
    )
}
----
======

[[testing-jwt]]
== Kiểm thử JWT Authentication

Để thực hiện một request được authorized trên resource server, bạn cần một bearer token.

Nếu resource server của bạn được configure cho JWT, bearer token đó phải được signed rồi encoded theo specification của JWT.
Toàn bộ việc này có thể khá khó, đặc biệt khi đó không phải focus của test.

May mắn là có một số cách đơn giản để vượt qua khó khăn này, để test tập trung vào authorization thay vì biểu diễn bearer token.
Sau đây chúng ta sẽ xem xét hai cách:

== `jwt() RequestPostProcessor`

Cách đầu tiên là dùng `jwt` xref:servlet/test/mockmvc/request-post-processors.adoc[`RequestPostProcessor`].
Cách đơn giản nhất như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint").with(jwt()));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(jwt())
}
----
======

Thao tác này sẽ tạo một mock `Jwt`, đưa nó đi qua đúng các authentication API để các cơ chế authorization của bạn có thể verify nó.

Theo mặc định, `JWT` được tạo có các đặc điểm sau:

[source,json]
----
{
  "headers" : { "alg" : "none" },
  "claims" : {
    "sub" : "user",
    "scope" : "read"
  }
}
----

Và nếu kiểm tra `Jwt` kết quả, kết quả sẽ như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(jwt.getTokenValue()).isEqualTo("token");
assertThat(jwt.getHeaders().get("alg")).isEqualTo("none");
assertThat(jwt.getSubject()).isEqualTo("sub");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(jwt.tokenValue).isEqualTo("token")
assertThat(jwt.headers["alg"]).isEqualTo("none")
assertThat(jwt.subject).isEqualTo("sub")
----
======

Tất nhiên, các giá trị này có thể được configure.

Bạn có thể configure mọi header hoặc claim bằng method tương ứng:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint")
        .with(jwt().jwt((jwt) -> jwt.header("kid", "one").claim("iss", "https://idp.example.org"))));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(
        jwt().jwt { jwt -> jwt.header("kid", "one").claim("iss", "https://idp.example.org") }
    )
}
----
======

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint")
        .with(jwt().jwt((jwt) -> jwt.claims((claims) -> claims.remove("scope")))));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(
        jwt().jwt { jwt -> jwt.claims { claims -> claims.remove("scope") } }
    )
}
----
======

Các `scope` và `scp` claims được xử lý ở đây giống như trong một request bearer token thông thường.
Tuy nhiên, bạn có thể dễ dàng override hành vi này bằng cách cung cấp danh sách các instance `GrantedAuthority` mà test cần:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint")
        .with(jwt().authorities(new SimpleGrantedAuthority("SCOPE_messages"))));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(
        jwt().authorities(SimpleGrantedAuthority("SCOPE_messages"))
    )
}
----
======

Hoặc nếu bạn có một converter tùy chỉnh từ `Jwt` sang `Collection<GrantedAuthority>`, bạn cũng có thể dùng converter đó để derive các authority:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint")
        .with(jwt().authorities(new MyConverter())));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(
        jwt().authorities(MyConverter())
    )
}
----
======

Bạn cũng có thể chỉ định một `Jwt` đầy đủ; javadoc:org.springframework.security.oauth2.jwt.Jwt$Builder[] rất hữu ích cho việc này:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
Jwt jwt = Jwt.withTokenValue("token")
    .header("alg", "none")
    .claim("sub", "user")
    .claim("scope", "read")
    .build();

mvc
    .perform(get("/endpoint")
        .with(jwt().jwt(jwt)));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
val jwt: Jwt = Jwt.withTokenValue("token")
    .header("alg", "none")
    .claim("sub", "user")
    .claim("scope", "read")
    .build()

mvc.get("/endpoint") {
    with(
        jwt().jwt(jwt)
    )
}
----
======

== `authentication()` `RequestPostProcessor`

Cách thứ hai là dùng `authentication()` xref:servlet/test/mockmvc/request-post-processors.adoc[`RequestPostProcessor`].
Về cơ bản, bạn có thể tự khởi tạo `JwtAuthenticationToken` và cung cấp nó trong test như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
Jwt jwt = Jwt.withTokenValue("token")
    .header("alg", "none")
    .claim("sub", "user")
    .build();
Collection<GrantedAuthority> authorities = AuthorityUtils.createAuthorityList("SCOPE_read");
JwtAuthenticationToken token = new JwtAuthenticationToken(jwt, authorities);

mvc
    .perform(get("/endpoint")
        .with(authentication(token)));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
val jwt = Jwt.withTokenValue("token")
    .header("alg", "none")
    .claim("sub", "user")
    .build()
val authorities: Collection<GrantedAuthority> = AuthorityUtils.createAuthorityList("SCOPE_read")
val token = JwtAuthenticationToken(jwt, authorities)

mvc.get("/endpoint") {
    with(
        authentication(token)
    )
}
----
======

Lưu ý rằng, thay vì dùng các cách trên, bạn cũng có thể mock chính bean `JwtDecoder` bằng annotation `@MockBean`.

[[testing-opaque-token]]
== Kiểm thử Opaque Token Authentication

Tương tự <<testing-jwt,JWT>>, opaque token yêu cầu authorization server để verify tính hợp lệ, điều này có thể khiến test khó hơn.
Để hỗ trợ việc này, Spring Security có test support cho opaque token.

Giả sử chúng ta có một controller lấy authentication dưới dạng `BearerTokenAuthentication`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public String foo(BearerTokenAuthentication authentication) {
    return (String) authentication.getTokenAttributes().get("sub");
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(authentication: BearerTokenAuthentication): String {
    return authentication.tokenAttributes["sub"] as String
}
----
======

Trong trường hợp đó, chúng ta có thể yêu cầu Spring Security thêm một `BearerTokenAuthentication` mặc định bằng method `opaqueToken` xref:servlet/test/mockmvc/request-post-processors.adoc[`RequestPostProcessor`], như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint").with(opaqueToken()));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(opaqueToken())
}
----
======

Thao tác này sẽ configure `MockHttpServletRequest` liên kết với một `BearerTokenAuthentication` bao gồm một `OAuth2AuthenticatedPrincipal` đơn giản, `Map` các attributes và `Collection` các granted authorities.

Cụ thể, nó sẽ bao gồm một `Map` có cặp key/value là `sub`/`user`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat((String) token.getTokenAttributes().get("sub")).isEqualTo("user");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(token.tokenAttributes["sub"] as String).isEqualTo("user")
----
======

và một `Collection` các granted authorities chỉ gồm một authority là `SCOPE_read`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(token.getAuthorities()).hasSize(1);
assertThat(token.getAuthorities()).containsExactly(new SimpleGrantedAuthority("SCOPE_read"));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(token.authorities).hasSize(1)
assertThat(token.authorities).containsExactly(SimpleGrantedAuthority("SCOPE_read"))
----
======

Spring Security thực hiện các công việc cần thiết để bảo đảm instance `BearerTokenAuthentication` sẵn sàng cho các method của controller.

[[testing-opaque-token-authorities]]
== Cấu hình Granted Authorities

Trong nhiều trường hợp, method của bạn được bảo vệ bởi filter hoặc method security và `Authentication` cần có một số granted authorities nhất định để cho phép request.

Trong trường hợp này, bạn có thể cung cấp các granted authorities cần thiết bằng method `authorities()`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint")
        .with(opaqueToken()
            .authorities(new SimpleGrantedAuthority("SCOPE_message:read"))
        )
    );
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(opaqueToken()
        .authorities(SimpleGrantedAuthority("SCOPE_message:read"))
    )
}
----
======

[[testing-opaque-token-attributes]]
== Cấu hình Claims

Mặc dù granted authorities khá phổ biến trong toàn bộ Spring Security, OAuth 2.0 cũng có các attributes.

Ví dụ, giả sử bạn có một attribute `user_id` biểu thị ID của user trong system.
Bạn có thể truy cập attribute này trong controller như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public String foo(BearerTokenAuthentication authentication) {
    String userId = (String) authentication.getTokenAttributes().get("user_id");
    // ...
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(authentication: BearerTokenAuthentication): String {
    val userId = authentication.tokenAttributes["user_id"] as String
    // ...
}
----
======

Trong trường hợp đó, bạn nên chỉ định attribute này bằng method `attributes()`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint")
        .with(opaqueToken()
                .attributes((attrs) -> attrs.put("user_id", "1234"))
        )
    );
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(opaqueToken()
        .attributes { attrs -> attrs["user_id"] = "1234" }
    )
}
----
======

[[testing-opaque-token-principal]]
== Cấu hình bổ sung

Ngoài ra cũng có các method để configure authentication chi tiết hơn; điều này phụ thuộc vào data mà controller của bạn cần.

Một method như vậy là `principal(OAuth2AuthenticatedPrincipal)`, bạn có thể dùng method này để configure toàn bộ instance `OAuth2AuthenticatedPrincipal` làm nền tảng cho `BearerTokenAuthentication`.

Method này hữu ích nếu bạn:
1. Có implementation riêng của `OAuth2AuthenticatedPrincipal`, hoặc
2. Muốn chỉ định một principal name khác

Ví dụ, giả sử authorization server gửi principal name trong attribute `user_name` thay vì attribute `sub`.
Trong trường hợp đó, bạn có thể tự configure một `OAuth2AuthenticatedPrincipal`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
Map<String, Object> attributes = Collections.singletonMap("user_name", "foo_user");
OAuth2AuthenticatedPrincipal principal = new DefaultOAuth2AuthenticatedPrincipal(
        (String) attributes.get("user_name"),
        attributes,
        AuthorityUtils.createAuthorityList("SCOPE_message:read"));

mvc
    .perform(get("/endpoint")
        .with(opaqueToken().principal(principal))
    );
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
val attributes: Map<String, Any> = Collections.singletonMap("user_name", "foo_user")
val principal: OAuth2AuthenticatedPrincipal = DefaultOAuth2AuthenticatedPrincipal(
    attributes["user_name"] as String?,
    attributes,
    AuthorityUtils.createAuthorityList("SCOPE_message:read")
)

mvc.get("/endpoint") {
    with(opaqueToken().principal(principal))
}
----
======

Lưu ý rằng, thay vì dùng test support `opaqueToken()`, bạn cũng có thể mock chính bean `OpaqueTokenIntrospector` bằng annotation `@MockBean`.
