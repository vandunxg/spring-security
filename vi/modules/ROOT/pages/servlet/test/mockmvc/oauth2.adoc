[[testing-oauth2]]
= Kiểm thử OAuth 2.0

Đối với OAuth 2.0, các nguyên tắc đã trình bày trước đó vẫn được áp dụng: về cơ bản, điều này phụ thuộc vào những gì method đang được kiểm thử mong đợi có trong `SecurityContextHolder`.

Ví dụ, với một controller có dạng như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public String foo(Principal user) {
    return user.getName();
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(user: Principal): String {
    return user.name
}
----
======

Không có gì riêng cho OAuth2 trong trường hợp này, vì vậy bạn có thể chỉ cần xref:servlet/test/method.adoc#test-method-withmockuser[sử dụng `@WithMockUser`] là đủ.

Tuy nhiên, trong trường hợp controller của bạn gắn với một khía cạnh nào đó trong hỗ trợ OAuth 2.0 của Spring Security, như ví dụ sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public String foo(@AuthenticationPrincipal OidcUser user) {
    return user.getIdToken().getSubject();
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(@AuthenticationPrincipal user: OidcUser): String {
    return user.idToken.subject
}
----
======

thì hỗ trợ kiểm thử của Spring Security có thể rất hữu ích.

[[testing-oidc-login]]
== Kiểm thử Đăng nhập OIDC

Kiểm thử method ở trên bằng Spring MVC Test sẽ yêu cầu mô phỏng một loại luồng cấp quyền nào đó với Authorization Server.
Đây chắc chắn là một công việc khó khăn, vì vậy Spring Security cung cấp hỗ trợ để loại bỏ phần boilerplate này.

Ví dụ, chúng ta có thể yêu cầu Spring Security đưa vào một `OidcUser` mặc định bằng `oidcLogin` xref:servlet/test/mockmvc/request-post-processors.adoc[`RequestPostProcessor`], như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint").with(oidcLogin()));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(oidcLogin())
}
----
======

Thao tác này sẽ cấu hình `MockHttpServletRequest` liên kết với một `OidcUser` bao gồm một `OidcIdToken`, `OidcUserInfo` đơn giản và một `Collection` các authority được cấp.

Cụ thể, nó sẽ bao gồm một `OidcIdToken` có claim `sub` được đặt thành `user`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(user.getIdToken().getClaim("sub")).isEqualTo("user");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(user.idToken.getClaim<String>("sub")).isEqualTo("user")
----
======

Một `OidcUserInfo` không có claim nào được thiết lập:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(user.getUserInfo().getClaims()).isEmpty();
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(user.userInfo.claims).isEmpty()
----
======

và một `Collection` authority chỉ có một authority là `SCOPE_read`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(user.getAuthorities()).hasSize(1);
assertThat(user.getAuthorities()).containsExactly(new SimpleGrantedAuthority("SCOPE_read"));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(user.authorities).hasSize(1)
assertThat(user.authorities).containsExactly(SimpleGrantedAuthority("SCOPE_read"))
----
======

Spring Security thực hiện các công việc cần thiết để bảo đảm instance `OidcUser` có sẵn cho xref:servlet/integrations/mvc.adoc#mvc-authentication-principal[annotation `@AuthenticationPrincipal`].

Ngoài ra, nó còn liên kết `OidcUser` đó với một instance đơn giản của `OAuth2AuthorizedClient`, rồi đưa instance này vào một `OAuth2AuthorizedClientRepository` mock.
Điều này có thể hữu ích nếu các bài kiểm thử của bạn <<testing-oauth2-client,sử dụng annotation `@RegisteredOAuth2AuthorizedClient`>>..

Trong trường hợp này, bạn có thể cung cấp các authority được cấp cần thiết bằng method `authorities()`:

        )
    );
----

Kotlin::
+
[source,kotlin,role="secondary"]

    with(oidcLogin()
        .authorities(SimpleGrantedAuthority("SCOPE_message:read"))
    )
}
----
======

[[testing-oidc-login-claims]]
== Cấu hình Claim

Mặc dù authority được cấp khá phổ biến trong toàn bộ Spring Security, OAuth 2.0 còn có các claim.

Ví dụ, giả sử bạn có claim `user_id` biểu thị ID của user trong hệ thống.
Bạn có thể truy cập claim này trong controller như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public String foo(@AuthenticationPrincipal OidcUser oidcUser) {
    String userId = oidcUser.getIdToken().getClaim("user_id");
    // ...
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(@AuthenticationPrincipal oidcUser: OidcUser): String {
    val userId = oidcUser.idToken.getClaim<String>("user_id")
    // ...
}
----
======

Trong trường hợp đó, bạn sẽ muốn chỉ định claim này bằng method `idToken()`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint")
        .with(oidcLogin()
                .idToken((token) -> token.claim("user_id", "1234"))
        )
    );
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(oidcLogin()
        .idToken {
            it.claim("user_id", "1234")
        }
    )
}
----
======

vì `OidcUser` lấy các claim của nó từ `OidcIdToken`.

[[testing-oidc-login-user]]
== Cấu hình bổ sung

Ngoài ra còn có các method để cấu hình authentication chi tiết hơn; điều này chỉ phụ thuộc vào dữ liệu mà controller của bạn mong đợi:

* `userInfo(OidcUserInfo.Builder)` - Dùng để cấu hình instance `OidcUserInfo`
* `clientRegistration(ClientRegistration)` - Dùng để cấu hình `OAuth2AuthorizedClient` liên kết với một `ClientRegistration` cho trước
* `oidcUser(OidcUser)` - Dùng để cấu hình toàn bộ instance `OidcUser`

Method cuối cùng hữu ích nếu bạn:
1. Có implementation riêng của `OidcUser`, hoặc
2. Cần thay đổi thuộc tính name

Ví dụ, giả sử Authorization Server gửi tên principal trong claim `user_name` thay vì claim `sub`.
Trong trường hợp đó, bạn có thể cấu hình thủ công một `OidcUser`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
OidcUser oidcUser = new DefaultOidcUser(
        AuthorityUtils.createAuthorityList("SCOPE_message:read"),
        OidcIdToken.withTokenValue("id-token").claim("user_name", "foo_user").build(),
        "user_name");

mvc
    .perform(get("/endpoint")
        .with(oidcLogin().oidcUser(oidcUser))
    );
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
val oidcUser: OidcUser = DefaultOidcUser(
    AuthorityUtils.createAuthorityList("SCOPE_message:read"),
    OidcIdToken.withTokenValue("id-token").claim("user_name", "foo_user").build(),
    "user_name"
)

mvc.get("/endpoint") {
    with(oidcLogin().oidcUser(oidcUser))
}
----
======

[[testing-oauth2-client]]
== Kiểm thử Client OAuth 2.0

Bất kể user của bạn thực hiện authentication như thế nào, request đang được kiểm thử có thể sử dụng các token và client registration khác.
Ví dụ, controller của bạn có thể dựa vào grant client credentials để lấy một token hoàn toàn không liên kết với user:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public String foo(@RegisteredOAuth2AuthorizedClient("my-app") OAuth2AuthorizedClient authorizedClient) {
    return this.webClient.get()
        .attributes(oauth2AuthorizedClient(authorizedClient))
        .retrieve()
        .bodyToMono(String.class)
        .block();
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(@RegisteredOAuth2AuthorizedClient("my-app") authorizedClient: OAuth2AuthorizedClient?): String? {
    return this.webClient.get()
        .attributes(oauth2AuthorizedClient(authorizedClient))
        .retrieve()
        .bodyToMono(String::class.java)
        .block()
}
----
======

Mô phỏng quá trình bắt tay này với Authorization Server có thể khá phức tạp.
Thay vào đó, bạn có thể sử dụng `oauth2Client` xref:servlet/test/mockmvc/request-post-processors.adoc[`RequestPostProcessor`] để thêm một `OAuth2AuthorizedClient` vào `OAuth2AuthorizedClientRepository` mock:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint").with(oauth2Client("my-app")));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(
        oauth2Client("my-app")
    )
}
----
======

Thao tác này sẽ tạo một `OAuth2AuthorizedClient` có `ClientRegistration`, `OAuth2AccessToken` đơn giản và tên resource owner.

Cụ thể, nó sẽ bao gồm một `ClientRegistration` có client id là "test-client" và client secret là "test-secret":

[tabs]
======
Java::
+
[source,java,role="primary"]

----

Kotlin::
+
[source,kotlin,role="secondary"]
----

----
======

tên resource owner là "user":

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(authorizedClient.getPrincipalName()).isEqualTo("user");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----

----
======

và một `OAuth2AccessToken` chỉ có một scope là `read`:

[tabs]
======

[source,java,role="primary"]

+

[[testing-oauth2-client-scopes]]
== Cấu hình Scope

Trong nhiều trường hợp, access token OAuth 2.0 đi kèm một tập scope.
Nếu controller của bạn kiểm tra các scope này, chẳng hạn như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public String foo(@RegisteredOAuth2AuthorizedClient("my-app") OAuth2AuthorizedClient authorizedClient) {
    Set<String> scopes = authorizedClient.getAccessToken().getScopes();
    if (scopes.contains("message:read")) {
        return this.webClient.get()
            .attributes(oauth2AuthorizedClient(authorizedClient))
            .retrieve()
            .bodyToMono(String.class)
            .block();
    }
    // ...
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(@RegisteredOAuth2AuthorizedClient("my-app") authorizedClient: OAuth2AuthorizedClient): String? {
    val scopes = authorizedClient.accessToken.scopes
    if (scopes.contains("message:read")) {
        return webClient.get()
            .attributes(oauth2AuthorizedClient(authorizedClient))
            .retrieve()
            .bodyToMono(String::class.java)
            .block()
    }
    // ...
}
----
======

thì bạn có thể cấu hình scope bằng method `accessToken()`:

[tabs]

+
[source,java,role="primary"]

        )
    );
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(oauth2Client("my-app")

[[testing-oauth2-client-registration]]
== Cấu hình bổ sung

Ngoài ra còn có các method để cấu hình authentication chi tiết hơn; điều này chỉ phụ thuộc vào dữ liệu mà controller của bạn mong đợi:

* `principalName(String)` - Dùng để cấu hình tên resource owner
* `clientRegistration(Consumer<ClientRegistration.Builder>)` - Dùng để cấu hình `ClientRegistration` liên kết
* `clientRegistration(ClientRegistration)` - Dùng để cấu hình toàn bộ `ClientRegistration`

Method cuối cùng hữu ích nếu bạn muốn sử dụng một `ClientRegistration` thực tế.

Ví dụ, giả sử bạn muốn sử dụng một định nghĩa `ClientRegistration` của ứng dụng, như được chỉ định trong `application.yml`.

Trong trường hợp đó, bài kiểm thử của bạn có thể autowire `ClientRegistrationRepository` và tra cứu registration mà bài kiểm thử cần:

[tabs]
======
Java::

[[testing-jwt]]
== Kiểm thử Authentication JWT

Để thực hiện một request được authorization trên Resource Server, bạn cần một bearer token.

Nếu Resource Server của bạn được cấu hình cho JWT, điều đó có nghĩa là bearer token phải được ký rồi mã hóa theo đặc tả JWT.
Tất cả việc này có thể khá khó khăn, đặc biệt khi đó không phải trọng tâm của bài kiểm thử.

May mắn là có một số cách đơn giản để vượt qua khó khăn này, cho phép các bài kiểm thử của bạn tập trung vào authorization thay vì biểu diễn bearer token.
Sau đây chúng ta sẽ xem xét hai cách:

== `jwt() RequestPostProcessor`

Cách đầu tiên là thông qua `jwt` xref:servlet/test/mockmvc/request-post-processors.adoc[`RequestPostProcessor`].
Cách đơn giản nhất có dạng như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint").with(jwt()));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(jwt())
}
----
======

Thao tác này sẽ tạo một `Jwt` mock và đưa nó đi đúng qua mọi API authentication, để các cơ chế authorization của bạn có thể xác minh nó.

Theo mặc định, `JWT` được tạo có các đặc điểm sau:

[source,json]
----
{
  "headers" : { "alg" : "none" },
  "claims" : {
    "sub" : "user",
    "scope" : "read"
  }
}
----

Và nếu kiểm thử `Jwt` kết quả, nó sẽ cho kết quả như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(jwt.getTokenValue()).isEqualTo("token");
assertThat(jwt.getHeaders().get("alg")).isEqualTo("none");
assertThat(jwt.getSubject()).isEqualTo("sub");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(jwt.tokenValue).isEqualTo("token")
assertThat(jwt.headers["alg"]).isEqualTo("none")
assertThat(jwt.subject).isEqualTo("sub")
----
======

Các giá trị này tất nhiên có thể được cấu hình.

Bạn có thể cấu hình mọi header hoặc claim bằng method tương ứng:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint")
        .with(jwt().jwt((jwt) -> jwt.header("kid", "one").claim("iss", "https://idp.example.org"))));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(
        jwt().jwt { jwt -> jwt.header("kid", "one").claim("iss", "https://idp.example.org") }
    )
}
----
======

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint")
        .with(jwt().jwt((jwt) -> jwt.claims((claims) -> claims.remove("scope")))));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(
        jwt().jwt { jwt -> jwt.claims { claims -> claims.remove("scope") } }
    )
}
----
======

Các claim `scope` và `scp` được xử lý ở đây giống như trong một bearer token request thông thường.
Tuy nhiên, bạn có thể dễ dàng ghi đè hành vi này bằng cách cung cấp danh sách instance `GrantedAuthority` mà bài kiểm thử cần:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint")
        .with(jwt().authorities(new SimpleGrantedAuthority("SCOPE_messages"))));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(
        jwt().authorities(SimpleGrantedAuthority("SCOPE_messages"))
    )
}
----
======

Hoặc nếu bạn có converter tùy chỉnh từ `Jwt` sang `Collection<GrantedAuthority>`, bạn cũng có thể sử dụng converter đó để suy ra các authority:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint")
        .with(jwt().authorities(new MyConverter())));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(
        jwt().authorities(MyConverter())
    )
}
----
======

Bạn cũng có thể chỉ định một `Jwt` đầy đủ; javadoc:org.springframework.security.oauth2.jwt.Jwt$Builder[] rất hữu ích cho việc này:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
Jwt jwt = Jwt.withTokenValue("token")
    .header("alg", "none")
    .claim("sub", "user")
    .claim("scope", "read")
    .build();

mvc
    .perform(get("/endpoint")
        .with(jwt().jwt(jwt)));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
val jwt: Jwt = Jwt.withTokenValue("token")
    .header("alg", "none")
    .claim("sub", "user")
    .claim("scope", "read")
    .build()

mvc.get("/endpoint") {
    with(
        jwt().jwt(jwt)
    )
}
----
======

== `authentication()` `RequestPostProcessor`

Cách thứ hai là sử dụng `authentication()` xref:servlet/test/mockmvc/request-post-processors.adoc[`RequestPostProcessor`].
Về cơ bản, bạn có thể tự khởi tạo `JwtAuthenticationToken` và cung cấp nó trong bài kiểm thử như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
Jwt jwt = Jwt.withTokenValue("token")
    .header("alg", "none")
    .claim("sub", "user")
    .build();
Collection<GrantedAuthority> authorities = AuthorityUtils.createAuthorityList("SCOPE_read");
JwtAuthenticationToken token = new JwtAuthenticationToken(jwt, authorities);

mvc
    .perform(get("/endpoint")
        .with(authentication(token)));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
val jwt = Jwt.withTokenValue("token")
    .header("alg", "none")
    .claim("sub", "user")
    .build()
val authorities: Collection<GrantedAuthority> = AuthorityUtils.createAuthorityList("SCOPE_read")
val token = JwtAuthenticationToken(jwt, authorities)

mvc.get("/endpoint") {
    with(
        authentication(token)
    )
}
----
======

Lưu ý rằng, thay cho các cách trên, bạn cũng có thể mock chính bean `JwtDecoder` bằng annotation `@MockBean`.

[[testing-opaque-token]]
== Kiểm thử Authentication opaque token

Tương tự <<testing-jwt,JWT>>, opaque token yêu cầu Authorization Server để xác minh tính hợp lệ, điều này có thể khiến việc kiểm thử khó khăn hơn.
Để hỗ trợ việc đó, Spring Security có hỗ trợ kiểm thử opaque token.

Giả sử chúng ta có một controller lấy authentication dưới dạng `BearerTokenAuthentication`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public String foo(BearerTokenAuthentication authentication) {
    return (String) authentication.getTokenAttributes().get("sub");
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(authentication: BearerTokenAuthentication): String {
    return authentication.tokenAttributes["sub"] as String
}
----
======

Trong trường hợp đó, chúng ta có thể yêu cầu Spring Security đưa vào một `BearerTokenAuthentication` mặc định bằng method `opaqueToken` xref:servlet/test/mockmvc/request-post-processors.adoc[`RequestPostProcessor`], như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint").with(opaqueToken()));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
mvc.get("/endpoint") {
    with(opaqueToken())
}
----
======

Thao tác này sẽ cấu hình `MockHttpServletRequest` liên kết với một `BearerTokenAuthentication` bao gồm một `OAuth2AuthenticatedPrincipal` đơn giản, `Map` thuộc tính và `Collection` các authority được cấp.

Cụ thể, nó sẽ bao gồm một `Map` có cặp key/value là `sub`/`user`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat((String) token.getTokenAttributes().get("sub")).isEqualTo("user");
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(token.tokenAttributes["sub"] as String).isEqualTo("user")
----
======

và một `Collection` authority chỉ có một authority là `SCOPE_read`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
assertThat(token.getAuthorities()).hasSize(1);
assertThat(token.getAuthorities()).containsExactly(new SimpleGrantedAuthority("SCOPE_read"));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
assertThat(token.authorities).hasSize(1)
assertThat(token.authorities).containsExactly(SimpleGrantedAuthority("SCOPE_read"))
----
======

Spring Security thực hiện các công việc cần thiết để bảo đảm instance `BearerTokenAuthentication` có sẵn cho các method của controller.

[[testing-opaque-token-attributes]]
== Cấu hình Claim

Mặc dù authority được cấp khá phổ biến trong toàn bộ Spring Security, OAuth 2.0 còn có các attribute.

Ví dụ, giả sử bạn có attribute `user_id` biểu thị ID của user trong hệ thống.
Bạn có thể truy cập attribute này trong controller như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/endpoint")
public String foo(BearerTokenAuthentication authentication) {
    String userId = (String) authentication.getTokenAttributes().get("user_id");
    // ...
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/endpoint")
fun foo(authentication: BearerTokenAuthentication): String {
    val userId = authentication.tokenAttributes["user_id"] as String
    // ...
}
----
======

Trong trường hợp đó, bạn sẽ muốn chỉ định attribute này bằng method `attributes()`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
mvc
    .perform(get("/endpoint")
        .with(opaqueToken()

+
[source,kotlin,role="secondary"]

mvc.get("/endpoint") {

[[testing-opaque-token-principal]]
== Cấu hình bổ sung

Ngoài ra còn có các method để cấu hình authentication chi tiết hơn; điều này chỉ phụ thuộc vào dữ liệu mà controller của bạn mong đợi.

Một method như vậy là `principal(OAuth2AuthenticatedPrincipal)`, bạn có thể dùng method này để cấu hình toàn bộ instance `OAuth2AuthenticatedPrincipal` làm nền tảng cho `BearerTokenAuthentication`.

Method này hữu ích nếu bạn:
1. Có implementation riêng của `OAuth2AuthenticatedPrincipal`, hoặc
2. Muốn chỉ định tên principal khác

Ví dụ, giả sử Authorization Server gửi tên principal trong attribute `user_name` thay vì attribute `sub`.
Trong trường hợp đó, bạn có thể cấu hình thủ công một `OAuth2AuthenticatedPrincipal`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
Map<String, Object> attributes = Collections.singletonMap("user_name", "foo_user");
OAuth2AuthenticatedPrincipal principal = new DefaultOAuth2AuthenticatedPrincipal(
        (String) attributes.get("user_name"),
        attributes,
        AuthorityUtils.createAuthorityList("SCOPE_message:read"));

mvc
    .perform(get("/endpoint")
        .with(opaqueToken().principal(principal))
    );
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
val attributes: Map<String, Any> = Collections.singletonMap("user_name", "foo_user")
val principal: OAuth2AuthenticatedPrincipal = DefaultOAuth2AuthenticatedPrincipal(
    attributes["user_name"] as String?,
    attributes,
    AuthorityUtils.createAuthorityList("SCOPE_message:read")
)

mvc.get("/endpoint") {
    with(opaqueToken().principal(principal))
}
----
======

Lưu ý rằng, thay cho việc sử dụng hỗ trợ kiểm thử `opaqueToken()`, bạn cũng có thể mock chính bean `OpaqueTokenIntrospector` bằng annotation `@MockBean`.
