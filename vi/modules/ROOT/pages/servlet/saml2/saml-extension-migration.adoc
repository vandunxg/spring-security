= Di chuyển SAML 2.0 Extension

Tài liệu này cung cấp hướng dẫn chuyển các Service Provider SAML 2.0 từ Spring Security SAML Extensions 1.x sang Spring Security. Vì Spring Security không cung cấp hỗ trợ Identity Provider, việc di chuyển một Identity Provider của Spring Security SAML Extensions nằm ngoài phạm vi tài liệu này.

Do hai cách tiếp cận khác nhau đáng kể, tài liệu này thường tập trung vào các mẫu hơn là các bước tìm và thay thế chính xác.

[[saml2-login-logout]]
== Đăng nhập & Đăng xuất

=== Các thay đổi trong cách tiếp cận

https://github.com/spring-projects/spring-security[Spring Security] có cách tiếp cận hơi khác https://github.com/spring-projects/spring-security-saml[Spring Security SAML Extensions] theo một số khía cạnh đáng chú ý.

==== Bật đơn giản hơn

Hỗ trợ Service Provider của Spring Security SAML Extensions được cung cấp bởi một loạt filter, được bật bằng cách thêm thủ công từng filter theo đúng thứ tự vào nhiều filter chain của Spring Security.

Hỗ trợ Service Provider SAML 2.0 của Spring Security được bật thông qua các method DSL của Spring Security:
xref:servlet/saml2/login/index.adoc[`saml2Login`],
xref:servlet/saml2/logout.adoc[`saml2Logout`], và
xref:servlet/saml2/metadata.adoc[`saml2Metadata`]. Hỗ trợ này chọn các filter phù hợp để thêm và đặt chúng vào vị trí thích hợp trong filter chain.

==== Đóng gói chặt chẽ hơn

Giống như Spring Security SAML Extensions, Spring Security xây dựng hỗ trợ SAML dựa trên OpenSAML. Dự án Extensions cung cấp OpenSAML thông qua các interface public, làm mờ ranh giới giữa hai dự án, trên thực tế buộc phải sử dụng OpenSAML và khiến việc nâng cấp lên các phiên bản OpenSAML mới hơn phức tạp hơn.

Spring Security cung cấp cơ chế đóng gói chặt chẽ hơn. Không có interface public nào công khai các thành phần OpenSAML và mọi class công khai OpenSAML trong public API của mình đều được đặt tên với tiền tố `OpenSaml` để rõ ràng hơn.

==== Multitenancy tích hợp sẵn

Spring Security SAML Extensions cung cấp một số hỗ trợ đơn giản cho việc khai báo nhiều hơn một Identity Provider và truy cập chúng tại thời điểm đăng nhập bằng tham số request `idp`. Điều này hạn chế khả năng thay đổi trong thời gian chạy và cũng không cho phép mối quan hệ nhiều-nhiều giữa các Relying Party và Asserting Party.

Spring Security tích hợp multitenancy SAML 2.0 vào các URL mặc định và thành phần cơ bản dưới dạng một `RelyingPartyRegistration`. Thành phần này hoạt động như một liên kết giữa metadata của một Relying Party và metadata của một Asserting Party, và mọi cặp đều có thể tra cứu trong một `RelyingPartyRegistrationRepository`. Mỗi URL đại diện cho một cặp đăng ký duy nhất để truy xuất.

Dù là AuthnRequests, Responses, LogoutRequests, LogoutResponses hay EntityDescriptors, mỗi filter đều dựa trên `RelyingPartyRegistrationRepository` và vì vậy về bản chất là multi-tenant.

=== Ma trận ví dụ

Cả Spring Security và Spring Security SAML Extensions đều có ví dụ về cách cấu hình Service Provider:

[options="header"]
|===
| Trường hợp sử dụng | Spring Security | Spring Security SAML Extension

| Đăng nhập & Đăng xuất | https://github.com/spring-projects/spring-security-samples/tree/main/servlet/spring-boot/java/saml2/login[Mẫu] |
https://github.com/jzheaux/spring-security-saml-migrate/tree/main/login-logout[Mẫu]
| Đăng nhập bằng URL của SAML Extension | https://github.com/spring-projects/spring-security-samples/tree/main/servlet/spring-boot/java/saml2/custom-urls[Mẫu] | -
| Hỗ trợ metadata | https://github.com/spring-projects/spring-security-samples/tree/main/servlet/spring-boot/java/saml2/refreshable-metadata[Mẫu] | -
|===

Bạn cũng có thể xem một ví dụ minh họa trong dự án GitHub của https://github.com/spring-projects/spring-security-saml/tree/main/sample[Spring Security SAML Extension].


[NOTE]
====
Spring Security không hỗ trợ binding HTTP-Redirect cho các Response SAML 2.0.
Theo đặc tả SAML, binding HTTP-Redirect không được phép dùng cho các SAML Response do giới hạn về độ dài URL và chữ ký. Việc cố sử dụng binding này có thể dẫn đến lỗi không mong muốn.
Thay vào đó, hãy sử dụng binding HTTP-POST khi cấu hình Identity Provider.
====
