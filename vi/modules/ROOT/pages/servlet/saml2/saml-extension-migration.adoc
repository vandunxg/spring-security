= Migration SAML 2.0 Extension

Tài liệu này cung cấp hướng dẫn thực hiện migration cho các SAML 2.0 Service Provider từ Spring Security SAML Extensions 1.x sang Spring Security. Vì Spring Security không cung cấp hỗ trợ cho Identity Provider, migration cho một Identity Provider của Spring Security SAML Extensions nằm ngoài phạm vi tài liệu này.

Do hai cách tiếp cận rất khác nhau, tài liệu này sẽ tập trung vào các pattern hơn là các bước search-and-replace cụ thể.

[[saml2-login-logout]]
== Đăng nhập & Đăng xuất

=== Các thay đổi trong cách tiếp cận

https://github.com/spring-projects/spring-security[Spring Security] có cách tiếp cận hơi khác https://github.com/spring-projects/spring-security-saml[Spring Security SAML Extensions] theo một số khía cạnh đáng chú ý.

==== Enable đơn giản hơn

Hỗ trợ Service Provider của Spring Security SAML Extensions được cung cấp bởi một loạt filter, được enable bằng cách thêm thủ công từng filter theo đúng thứ tự vào các Spring Security filter chain khác nhau.

Hỗ trợ SAML 2.0 Service Provider của Spring Security được enable thông qua các method DSL của Spring Security:
xref:servlet/saml2/login/index.adoc[`saml2Login`],
xref:servlet/saml2/logout.adoc[`saml2Logout`], và
xref:servlet/saml2/metadata.adoc[`saml2Metadata`]. Cấu hình này chọn các filter phù hợp để thêm và đặt chúng vào vị trí thích hợp trong filter chain.

==== Encapsulation chặt chẽ hơn

Giống như Spring Security SAML Extensions, Spring Security xây dựng hỗ trợ SAML dựa trên OpenSAML. Dự án Extensions expose OpenSAML qua các public interface, làm mờ ranh giới giữa hai dự án, qua đó về thực chất buộc các ứng dụng phải sử dụng OpenSAML và khiến việc upgrade lên các version OpenSAML mới hơn phức tạp hơn.

Spring Security cung cấp encapsulation chặt chẽ hơn. Không có public interface nào expose các OpenSAML component và mọi class expose OpenSAML trong public API của mình đều được đặt tên với tiền tố `OpenSaml` để rõ ràng hơn.

==== Multitenancy tích hợp sẵn

Spring Security SAML Extensions cung cấp một số hỗ trợ đơn giản cho việc khai báo nhiều hơn một Identity Provider và truy cập chúng khi login bằng request parameter `idp`. Điều này hạn chế khả năng thay đổi khi runtime và cũng không cho phép mối quan hệ many-to-many giữa các Relying Party và Asserting Party.

Spring Security tích hợp multitenancy SAML 2.0 vào các URL mặc định và component cơ bản dưới dạng một `RelyingPartyRegistration`. Component này hoạt động như một liên kết giữa metadata của một Relying Party và metadata của một Asserting Party, và mọi cặp đều có thể lookup trong một `RelyingPartyRegistrationRepository`. Mỗi URL đại diện cho một registration pair duy nhất để lookup.

Dù là AuthnRequests, Responses, LogoutRequests, LogoutResponses hay EntityDescriptors, mỗi filter đều dựa trên `RelyingPartyRegistrationRepository` và vì vậy về bản chất là multi-tenant.

Cả Spring Security và Spring Security SAML Extensions đều có ví dụ về cách cấu hình Service Provider:

Bạn cũng có thể xem một ví dụ minh họa trong dự án GitHub của https://github.com/spring-projects/spring-security-saml/tree/main/sample[Spring Security SAML Extension].


[NOTE]
====
Spring Security không hỗ trợ HTTP-Redirect binding cho các SAML 2.0 Response.
Theo đặc tả SAML, HTTP-Redirect binding không được phép dùng cho các SAML Response do giới hạn về độ dài URL và chữ ký. Việc cố sử dụng binding này có thể dẫn đến lỗi không mong muốn.
Thay vào đó, hãy sử dụng HTTP-POST binding khi cấu hình Identity Provider.
====

== Các tính năng chưa được port

Có một số tính năng chưa được port và hiện vẫn chưa có kế hoạch port chúng:

* Hỗ trợ Artifact binding
