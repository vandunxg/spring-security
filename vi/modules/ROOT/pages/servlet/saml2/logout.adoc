[[servlet-saml2login-logout]]
= Thực hiện Single Logout

Trong số các xref:servlet/authentication/logout.adoc[cơ chế logout khác], Spring Security cung cấp hỗ trợ cho Single Logout SAML 2.0 do RP hoặc AP khởi tạo.

Tóm lại, Spring Security hỗ trợ hai trường hợp sử dụng:

* **RP-Initiated** - Ứng dụng của bạn có một endpoint mà khi được POST tới sẽ logout user và gửi một `saml2:LogoutRequest` đến asserting party.
Sau đó, asserting party sẽ gửi lại một `saml2:LogoutResponse` để ứng dụng của bạn xử lý response.
* **AP-Initiated** - Ứng dụng của bạn có một endpoint sẽ nhận `saml2:LogoutRequest` từ asserting party.
Tại thời điểm đó, ứng dụng của bạn sẽ hoàn tất logout rồi gửi một `saml2:LogoutResponse` đến asserting party.

[NOTE]
Trong kịch bản **AP-Initiated**, mọi redirect cục bộ mà ứng dụng của bạn thực hiện sau logout đều không còn ý nghĩa.
Khi ứng dụng gửi một `saml2:LogoutResponse`, ứng dụng không còn quyền kiểm soát browser.

== Cấu hình tối thiểu cho Single Logout

Để sử dụng tính năng Single Logout SAML 2.0 của Spring Security, bạn cần những thành phần sau:

* Thứ nhất, asserting party phải hỗ trợ Single Logout SAML 2.0
* Thứ hai, asserting party nên được cấu hình để ký và POST các `saml2:LogoutRequest` và `saml2:LogoutResponse` đến endpoint `/logout/saml2/slo` của ứng dụng
* Thứ ba, ứng dụng của bạn phải có private key PKCS#8 và certificate X.509 để ký các `saml2:LogoutRequest` và `saml2:LogoutResponse`

Bạn có thể thực hiện việc này trong Spring Boot như sau:

[source,yaml]
----
spring:
  security:
    saml2:
      relyingparty:
        registration:
          metadata:
            signing.credentials: <3>
              - private-key-location: classpath:credentials/rp-private.key
                certificate-location: classpath:credentials/rp-certificate.crt
            singlelogout.url: "{baseUrl}/logout/saml2/slo" <2>
            assertingparty:
              metadata-uri: https://ap.example.com/metadata <1>

----
<1> - URI metadata của IDP, cho biết IDP có hỗ trợ SLO
<2> - Endpoint SLO trong ứng dụng
<3> - Credential dùng để ký các ``<saml2:LogoutRequest>`` và ``<saml2:LogoutResponse>``

[NOTE]
----
Một asserting party hỗ trợ Single Logout nếu metadata của nó bao gồm phần tử `<SingleLogoutService>`.
----

Vậy là xong!

Hỗ trợ logout của Spring Security cung cấp một số điểm cấu hình.
Hãy xem xét các trường hợp sử dụng sau:

* Tìm hiểu cách <<_startup_expectations,cấu hình tối thiểu ở trên hoạt động>>
* Có cái nhìn tổng quan về <<architecture,kiến trúc tổng thể>>
* Cho phép người dùng <<separating-local-saml2-logout,chỉ logout khỏi ứng dụng>>
* Tùy chỉnh <<_configuring_logout_endpoints,các endpoint logout>>
* Lưu trữ `<saml2:LogoutRequests>` ở nơi <<_customizing_storage,khác với session>>

=== Kỳ vọng khi khởi động

Khi sử dụng các property này, ngoài login, SAML 2.0 Service Provider sẽ tự động cấu hình để hỗ trợ logout bằng ``<saml2:LogoutRequest>`` và ``<saml2:LogoutResponse>`` theo cơ chế logout do RP hoặc AP khởi tạo.

Quá trình này được thực hiện thông qua một quy trình khởi động có tính xác định:

1. Truy vấn endpoint metadata của Identity Server để tìm phần tử `<SingleLogoutService>`
2. Quét metadata và cache mọi public key dùng để xác minh chữ ký
3. Chuẩn bị các endpoint thích hợp

Hệ quả của quy trình này là identity server phải đang hoạt động và nhận request để Service Provider có thể khởi động thành công.

[NOTE]
Nếu identity server không hoạt động khi Service Provider truy vấn nó (với các timeout phù hợp), quá trình khởi động sẽ thất bại.

=== Kỳ vọng khi chạy

Với cấu hình ở trên, mọi user đã login đều có thể gửi `POST /logout` đến ứng dụng để thực hiện SLO do RP khởi tạo.
Sau đó, ứng dụng sẽ thực hiện các bước sau:

1. Logout user và invalidate session
2. Tạo một `<saml2:LogoutRequest>` rồi POST đến endpoint SLO của asserting party tương ứng
3. Sau đó, nếu asserting party phản hồi bằng một `<saml2:LogoutResponse>`, ứng dụng sẽ verify response và redirect đến success endpoint đã cấu hình

Ngoài ra, ứng dụng của bạn cũng có thể tham gia vào quy trình logout do AP khởi tạo khi asserting party gửi một `<saml2:LogoutRequest>` đến `/logout/saml2/slo`.
Khi đó, ứng dụng sẽ thực hiện các bước sau:

1. Xác minh `<saml2:LogoutRequest>`
2. Logout user và invalidate session
3. Tạo một `<saml2:LogoutResponse>` rồi POST ngược lại đến endpoint SLO của asserting party

== Cấu hình tối thiểu không dùng Boot

Thay vì dùng property của Boot, bạn cũng có thể đạt được kết quả tương tự bằng cách khai báo trực tiếp các bean như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Configuration
public class SecurityConfig {
    @Value("${private.key}") RSAPrivateKey key;
    @Value("${public.certificate}") X509Certificate certificate;

    @Bean
    RelyingPartyRegistrationRepository registrations() {
        Saml2X509Credential credential = Saml2X509Credential.signing(key, certificate);
        RelyingPartyRegistration registration = RelyingPartyRegistrations
                .fromMetadataLocation("https://ap.example.org/metadata") <1>
                .registrationId("metadata")
                .singleLogoutServiceLocation("{baseUrl}/logout/saml2/slo") <2>
                .signingX509Credentials((signing) -> signing.add(credential)) <3>
                .build();
        return new InMemoryRelyingPartyRegistrationRepository(registration);
    }

    @Bean
    SecurityFilterChain web(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests((authorize) -> authorize
                .anyRequest().authenticated()
            )
            .saml2Login(withDefaults())
            .saml2Logout(withDefaults()); <4>

        return http.build();
    }
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----

<1> - URI metadata của IDP, cho biết IDP có hỗ trợ SLO
<2> - Endpoint SLO trong ứng dụng
<3> - Credential dùng để ký các ``<saml2:LogoutRequest>`` và ``<saml2:LogoutResponse>``, bạn cũng có thể thêm chúng vào xref:servlet/saml2/login/overview.adoc#servlet-saml2login-rpr-duplicated[nhiều Relying Party]

Bạn thực hiện việc này bằng cách đặt property `RelyingPartyRegistration.Builder#singleLogoutServiceLocation` như ở trên.

== Cấu hình các endpoint logout

Có ba hành vi có thể được kích hoạt bởi các endpoint khác nhau:

* Logout do RP khởi tạo, cho phép user đã được authenticated thực hiện `POST` và kích hoạt quy trình logout bằng cách gửi một `<saml2:LogoutRequest>` đến asserting party
* Logout do AP khởi tạo, cho phép asserting party gửi một `<saml2:LogoutRequest>` đến ứng dụng
* Logout response từ AP, cho phép asserting party gửi một `<saml2:LogoutResponse>` để phản hồi cho `<saml2:LogoutRequest>` do RP khởi tạo

Hành vi thứ nhất được kích hoạt bằng cách thực hiện `POST /logout` thông thường khi principal có kiểu `Saml2AuthenticatedPrincipal`.

Hành vi thứ hai được kích hoạt bằng cách POST đến endpoint `/logout/saml2/slo` với một `SAMLRequest` được asserting party ký.

Hành vi thứ ba được kích hoạt bằng cách POST đến endpoint `/logout/saml2/slo` với một `SAMLResponse` được asserting party ký.

Vì user đã login hoặc Logout Request ban đầu đã được xác định, `registrationId` cũng đã được xác định.
Vì lý do này, `+{registrationId}+` mặc định không phải là một phần của các URL này.

URL này có thể được tùy chỉnh trong DSL.

Ví dụ, nếu bạn đang migrate Relying Party hiện có sang Spring Security, asserting party có thể đã trỏ đến `GET /SLOService.saml2`.
Để giảm các thay đổi cấu hình cho asserting party, bạn có thể cấu hình filter trong DSL như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
http
    .saml2Logout((saml2) -> saml2
        .logoutRequest((request) -> request.logoutUrl("/SLOService.saml2"))
        .logoutResponse((response) -> response.logoutUrl("/SLOService.saml2"))
    );
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
http {
    saml2Logout {
        logoutRequest {
            logoutUrl = "/SLOService.saml2"
        }
        logoutResponse {
            logoutUrl = "/SLOService.saml2"
        }
    }
}
----
======

Bạn cũng nên cấu hình các endpoint này trong `RelyingPartyRegistration`.

Bạn cũng có thể tùy chỉnh endpoint dùng để kích hoạt logout cục bộ như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
http
    .saml2Logout((saml2) -> saml2.logoutUrl("/saml2/logout"));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
http {
    saml2Logout {
        logoutUrl = "/saml2/logout"
    }
}
----
======

=== Tách logout cục bộ khỏi logout SAML 2.0

Trong một số trường hợp, bạn có thể muốn cung cấp một endpoint logout cho logout cục bộ và một endpoint khác cho SLO do RP khởi tạo.
Tương tự như các cơ chế logout khác, bạn có thể đăng ký nhiều endpoint, miễn là mỗi endpoint có một đường dẫn khác nhau.

Ví dụ, bạn có thể cấu hình DSL như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
http
    .logout((logout) -> logout.logoutUrl("/logout"))
    .saml2Logout((saml2) -> saml2.logoutUrl("/saml2/logout"));
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
http {
    logout {
        logoutUrl = "/logout"
    }
    saml2Logout {
        logoutUrl = "/saml2/logout"
    }
}
----
======

Với cấu hình này, nếu client gửi `POST /logout`, session sẽ được xóa, nhưng sẽ không có `<saml2:LogoutRequest>` nào được gửi đến asserting party.
Tuy nhiên, nếu client gửi `POST /saml2/logout`, ứng dụng sẽ khởi tạo SLO SAML 2.0 như bình thường.

== Tùy chỉnh việc resolve `<saml2:LogoutRequest>`

Thông thường, bạn cần thiết lập thêm các giá trị trong `<saml2:LogoutRequest>` ngoài các giá trị mặc định mà Spring Security cung cấp.

Mặc định, Spring Security sẽ tạo một `<saml2:LogoutRequest>` và cung cấp:

* Thuộc tính `DestinationValidator` - từ `RelyingPartyRegistration#getAssertingPartyMetadata#getSingleLogoutServiceLocation`
* Thuộc tính `ID` - một GUID
* Phần tử `<Issuer>` - từ `RelyingPartyRegistration#getEntityId`
* Phần tử `<NameID>` - từ `Authentication#getName`

Để thêm các giá trị khác, bạn có thể dùng delegation như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
Saml2LogoutRequestResolver logoutRequestResolver(RelyingPartyRegistrationRepository registrations) {
	OpenSaml5LogoutRequestResolver logoutRequestResolver =
			new OpenSaml5LogoutRequestResolver(registrations);
	logoutRequestResolver.setParametersConsumer((parameters) -> {
		String name = ((Saml2AuthenticatedPrincipal) parameters.getAuthentication().getPrincipal()).getFirstAttribute("CustomAttribute");
		String format = "urn:oasis:names:tc:SAML:2.0:nameid-format:transient";
		LogoutRequest logoutRequest = parameters.getLogoutRequest();
		NameID nameId = logoutRequest.getNameID();
		nameId.setValue(name);
		nameId.setFormat(format);
	});
	return logoutRequestResolver;
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
open fun logoutRequestResolver(registrations:RelyingPartyRegistrationRepository?): Saml2LogoutRequestResolver {
    val logoutRequestResolver = OpenSaml5LogoutRequestResolver(registrations)
    logoutRequestResolver.setParametersConsumer { parameters: LogoutRequestParameters ->
        val name: String = (parameters.getAuthentication().getPrincipal() as Saml2AuthenticatedPrincipal).getFirstAttribute("CustomAttribute")
        val format = "urn:oasis:names:tc:SAML:2.0:nameid-format:transient"
        val logoutRequest: LogoutRequest = parameters.getLogoutRequest()
        val nameId: NameID = logoutRequest.getNameID()
        nameId.setValue(name)
        nameId.setFormat(format)
    }
    return logoutRequestResolver
}
----
======

Sau đó, bạn có thể cung cấp `Saml2LogoutRequestResolver` tùy chỉnh trong DSL như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----

        .logoutRequest((request) -> request
            .logoutRequestResolver(this.logoutRequestResolver)
        )
    );
----

Kotlin::
+
[source,kotlin,role="secondary"]
----

        logoutRequest {

        }
    }

== Tùy chỉnh việc resolve `<saml2:LogoutResponse>`

Thông thường, bạn cần thiết lập thêm các giá trị trong `<saml2:LogoutResponse>` ngoài các giá trị mặc định mà Spring Security cung cấp.

Mặc định, Spring Security sẽ tạo một `<saml2:LogoutResponse>` và cung cấp:

* Thuộc tính `DestinationValidator` - từ `RelyingPartyRegistration#getAssertingPartyMetadata#getSingleLogoutServiceResponseLocation`
* Thuộc tính `ID` - một GUID
* Phần tử `<Issuer>` - từ `RelyingPartyRegistration#getEntityId`
* Phần tử `<Status>` - `SUCCESS`

Để thêm các giá trị khác, bạn có thể dùng delegation như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
public Saml2LogoutResponseResolver logoutResponseResolver(RelyingPartyRegistrationRepository registrations) {
	OpenSaml5LogoutResponseResolver resolver = 
			new OpenSaml5LogoutResponseResolver(registrations);
	resolver.setParametersConsumer((parameters) -> {
		if (checkOtherPrevailingConditions(parameters.getRequest())) {
			parameters.getLogoutResponse().getStatus().getStatusCode().setCode(StatusCode.PARTIAL_LOGOUT);
		}
	});
	return resolver;
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
open fun logoutResponseResolver(registrations: RelyingPartyRegistrationRepository?): Saml2LogoutResponseResolver {
    val resolver = OpenSaml5LogoutResponseResolver(registrations)
    resolver.setParametersConsumer { parameters ->
        if (checkOtherPrevailingConditions(parameters.request)) {
            parameters.logoutResponse.status.statusCode.code = StatusCode.PARTIAL_LOGOUT
        }
    }
    return resolver
}
----
======

Sau đó, bạn có thể cung cấp `Saml2LogoutResponseResolver` tùy chỉnh trong DSL như sau:

== Tùy chỉnh authentication cho `<saml2:LogoutRequest>`

Để tùy chỉnh validation, bạn có thể tự triển khai `Saml2LogoutRequestValidator`.
Hiện tại, validation còn tối thiểu, nên trước tiên bạn có thể delegate cho `Saml2LogoutRequestValidator` mặc định như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----

== Tùy chỉnh việc lưu trữ `<saml2:LogoutRequest>`

Khi ứng dụng gửi một `<saml2:LogoutRequest>`, giá trị này được lưu trong session để có thể xác minh tham số `RelayState` và thuộc tính `InResponseTo` trong `<saml2:LogoutResponse>`.

Nếu muốn lưu trữ logout request ở nơi khác thay vì session, bạn có thể cung cấp implementation tùy chỉnh trong DSL như sau:

    .saml2Logout((saml2) -> saml2
