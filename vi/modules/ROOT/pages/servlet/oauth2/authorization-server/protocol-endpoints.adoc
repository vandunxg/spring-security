[[oauth2AuthorizationServer-oauth2-authorization-endpoint]]
== OAuth2 Authorization Endpoint

`OAuth2AuthorizationEndpointConfigurer` cung cấp khả năng tùy chỉnh https://datatracker.ietf.org/doc/html/rfc6749#section-3.1[OAuth2 Authorization endpoint].
Nó định nghĩa các extension point cho phép bạn tùy chỉnh logic pre-processing, main processing và post-processing cho https://datatracker.ietf.org/doc/html/rfc6749#section-4.1.1[OAuth2 authorization request].

`OAuth2AuthorizationEndpointConfigurer` cung cấp các tùy chọn cấu hình sau:

[source,java]
----
@Bean
public SecurityFilterChain authorizationServerSecurityFilterChain(HttpSecurity http) throws Exception {
	http
		.oauth2AuthorizationServer((authorizationServer) ->
			authorizationServer
				.authorizationEndpoint(authorizationEndpoint ->
					authorizationEndpoint
        				.authorizationRequestConverter(authorizationRequestConverter)   <1>
                        .authorizationRequestConverters(authorizationRequestConvertersConsumer) <2>
                        .authenticationProvider(authenticationProvider) <3>
                        .authenticationProviders(authenticationProvidersConsumer)   <4>
                        .authorizationResponseHandler(authorizationResponseHandler) <5>
                        .errorResponseHandler(errorResponseHandler) <6>
                        .consentPage("/oauth2/v1/authorize")    <7>
				)
		);

	return http.build();
}
----
<1> `authorizationRequestConverter()`: Thêm một `AuthenticationConverter` (_pre-processor_) được sử dụng khi cố gắng trích xuất https://datatracker.ietf.org/doc/html/rfc6749#section-4.1.1[OAuth2 authorization request] (hoặc consent) từ `HttpServletRequest` thành một instance của `OAuth2AuthorizationCodeRequestAuthenticationToken` hoặc `OAuth2AuthorizationConsentAuthenticationToken`.
<2> `authorizationRequestConverters()`: Thiết lập `Consumer` cung cấp quyền truy cập vào `List` chứa các ``AuthenticationConverter`` mặc định và các converter được thêm vào (nếu có), cho phép thêm, xóa hoặc tùy chỉnh một `AuthenticationConverter` cụ thể.
<3> `authenticationProvider()`: Thêm một `AuthenticationProvider` (_main processor_) được sử dụng để authenticate `OAuth2AuthorizationCodeRequestAuthenticationToken` hoặc `OAuth2AuthorizationConsentAuthenticationToken`.
<4> `authenticationProviders()`: Thiết lập `Consumer` cung cấp quyền truy cập vào `List` chứa các ``AuthenticationProvider`` mặc định và các provider được thêm vào (nếu có), cho phép thêm, xóa hoặc tùy chỉnh một `AuthenticationProvider` cụ thể.
<5> `authorizationResponseHandler()`: `AuthenticationSuccessHandler` (_post-processor_) được sử dụng để xử lý một `OAuth2AuthorizationCodeRequestAuthenticationToken` ở trạng thái "`authenticated`" và trả về https://datatracker.ietf.org/doc/html/rfc6749#section-4.1.2[`OAuth2AuthorizationResponse`].
<6> `errorResponseHandler()`: `AuthenticationFailureHandler` (_post-processor_) được sử dụng để xử lý `OAuth2AuthorizationCodeRequestAuthenticationException` và trả về https://datatracker.ietf.org/doc/html/rfc6749#section-4.1.2.1[`OAuth2Error` response].
<7> `consentPage()`: `URI` của trang consent tùy chỉnh để redirect resource owner đến nếu cần consent trong authorization request flow.

`OAuth2AuthorizationEndpointConfigurer` cấu hình `OAuth2AuthorizationEndpointFilter` và đăng ký nó với `SecurityFilterChain` `@Bean` của OAuth2 authorization server.
`OAuth2AuthorizationEndpointFilter` là `Filter` xử lý các OAuth2 authorization request (và consent).

`OAuth2AuthorizationEndpointFilter` được cấu hình với các giá trị mặc định sau:

* `*AuthenticationConverter*` -- Một `DelegatingAuthenticationConverter` được tạo thành từ `OAuth2AuthorizationCodeRequestAuthenticationConverter` và `OAuth2AuthorizationConsentAuthenticationConverter`.
* `*AuthenticationManager*` -- Một `AuthenticationManager` được tạo thành từ `OAuth2AuthorizationCodeRequestAuthenticationProvider` và `OAuth2AuthorizationConsentAuthenticationProvider`.
* `*AuthenticationSuccessHandler*` -- Một implementation nội bộ xử lý một `OAuth2AuthorizationCodeRequestAuthenticationToken` ở trạng thái "`authenticated`" và trả về `OAuth2AuthorizationResponse`.
* `*AuthenticationFailureHandler*` -- Một implementation nội bộ sử dụng `OAuth2Error` liên kết với `OAuth2AuthorizationCodeRequestAuthenticationException` và trả về `OAuth2Error` response.

[[oauth2AuthorizationServer-oauth2-authorization-endpoint-customizing-authorization-request-validation]]
=== Tùy chỉnh validation của authorization request

`OAuth2AuthorizationCodeRequestAuthenticationValidator` là validator mặc định được sử dụng để validation các parameter cụ thể của OAuth2 authorization request trong Authorization Code Grant.
Implementation mặc định validate các parameter `redirect_uri` và `scope`.
Nếu validation thất bại, một `OAuth2AuthorizationCodeRequestAuthenticationException` sẽ được throw.

`OAuth2AuthorizationCodeRequestAuthenticationProvider` cung cấp khả năng override validation mặc định của authorization request bằng cách cung cấp một authentication validator tùy chỉnh có kiểu `Consumer<OAuth2AuthorizationCodeRequestAuthenticationContext>` cho `setAuthenticationValidator()`.

[TIP]
`OAuth2AuthorizationCodeRequestAuthenticationContext` chứa `OAuth2AuthorizationCodeRequestAuthenticationToken`, trong đó có các parameter của OAuth2 authorization request.

[IMPORTANT]
Nếu validation thất bại, authentication validator *MUST* throw `OAuth2AuthorizationCodeRequestAuthenticationException`.

Một use case phổ biến trong development lifecycle là cho phép `localhost` trong parameter `redirect_uri`.

Ví dụ sau cho thấy cách cấu hình `OAuth2AuthorizationCodeRequestAuthenticationProvider` với authentication validator tùy chỉnh cho phép `localhost` trong parameter `redirect_uri`:

[source,java]
----
@Bean
public SecurityFilterChain authorizationServerSecurityFilterChain(HttpSecurity http) throws Exception {
	http
		.oauth2AuthorizationServer((authorizationServer) ->
			authorizationServer
				.authorizationEndpoint(authorizationEndpoint ->
					authorizationEndpoint
                        .authenticationProviders(configureAuthenticationValidator())
				)
		);

	return http.build();
}

private Consumer<List<AuthenticationProvider>> configureAuthenticationValidator() {
	return (authenticationProviders) ->
		authenticationProviders.forEach((authenticationProvider) -> {
			if (authenticationProvider instanceof OAuth2AuthorizationCodeRequestAuthenticationProvider) {
				Consumer<OAuth2AuthorizationCodeRequestAuthenticationContext> authenticationValidator =
					// Override validator redirect_uri mặc định
					new CustomRedirectUriValidator()
						// Tái sử dụng validator scope mặc định
						.andThen(OAuth2AuthorizationCodeRequestAuthenticationValidator.DEFAULT_SCOPE_VALIDATOR);

				((OAuth2AuthorizationCodeRequestAuthenticationProvider) authenticationProvider)
					.setAuthenticationValidator(authenticationValidator);
			}
		});
}

static class CustomRedirectUriValidator implements Consumer<OAuth2AuthorizationCodeRequestAuthenticationContext> {

	@Override
	public void accept(OAuth2AuthorizationCodeRequestAuthenticationContext authenticationContext) {
		OAuth2AuthorizationCodeRequestAuthenticationToken authorizationCodeRequestAuthentication =
			authenticationContext.getAuthentication();
		RegisteredClient registeredClient = authenticationContext.getRegisteredClient();
		String requestedRedirectUri = authorizationCodeRequestAuthentication.getRedirectUri();

		// So sánh chính xác client redirect URI với các URI đã đăng ký trước
		if (!registeredClient.getRedirectUris().contains(requestedRedirectUri)) {
			OAuth2Error error = new OAuth2Error(OAuth2ErrorCodes.INVALID_REQUEST);
			throw new OAuth2AuthorizationCodeRequestAuthenticationException(error, null);
		}
	}
}
----

<1> `accessTokenRequestConverter()`: Thêm một `AuthenticationConverter` (_pre-processor_) được sử dụng khi cố gắng trích xuất https://datatracker.ietf.org/doc/html/rfc6749#section-4.1.3[OAuth2 access token request] từ `HttpServletRequest` thành một instance của `OAuth2AuthorizationGrantAuthenticationToken`.

<3> `authenticationProvider()`: Thêm một `AuthenticationProvider` (_main processor_) được sử dụng để authenticate `OAuth2AuthorizationGrantAuthenticationToken`.
<4> `authenticationProviders()`: Thiết lập `Consumer` cung cấp quyền truy cập vào `List` chứa các ``AuthenticationProvider`` mặc định và các provider được thêm vào (nếu có), cho phép thêm, xóa hoặc tùy chỉnh một `AuthenticationProvider` cụ thể.

<6> `errorResponseHandler()`: `AuthenticationFailureHandler` (_post-processor_) được sử dụng để xử lý `OAuth2AuthenticationException` và trả về https://datatracker.ietf.org/doc/html/rfc6749#section-5.2[`OAuth2Error` response].

`OAuth2TokenEndpointConfigurer` cấu hình `OAuth2TokenEndpointFilter` và đăng ký nó với `SecurityFilterChain` `@Bean` của OAuth2 authorization server.
`OAuth2TokenEndpointFilter` là `Filter` xử lý các OAuth2 access token request.

Các https://datatracker.ietf.org/doc/html/rfc6749#section-1.3[authorization grant type] được hỗ trợ là `authorization_code`, `refresh_token`, `client_credentials`, `urn:ietf:params:oauth:grant-type:device_code` và `urn:ietf:params:oauth:grant-type:token-exchange`.

`OAuth2TokenEndpointFilter` được cấu hình với các giá trị mặc định sau:

* `*AuthenticationConverter*` -- Một `DelegatingAuthenticationConverter` được tạo thành từ `OAuth2AuthorizationCodeAuthenticationConverter`, `OAuth2RefreshTokenAuthenticationConverter`, `OAuth2ClientCredentialsAuthenticationConverter`, `OAuth2DeviceCodeAuthenticationConverter` và `OAuth2TokenExchangeAuthenticationConverter`.
* `*AuthenticationManager*` -- Một `AuthenticationManager` được tạo thành từ `OAuth2AuthorizationCodeAuthenticationProvider`, `OAuth2RefreshTokenAuthenticationProvider`, `OAuth2ClientCredentialsAuthenticationProvider`, `OAuth2DeviceCodeAuthenticationProvider` và `OAuth2TokenExchangeAuthenticationProvider`.
* `*AuthenticationSuccessHandler*` -- Một `OAuth2AccessTokenResponseAuthenticationSuccessHandler`.
* `*AuthenticationFailureHandler*` -- Một `OAuth2ErrorAuthenticationFailureHandler`.

=== Tùy chỉnh validation của Client Credentials Grant request

`OAuth2ClientCredentialsAuthenticationValidator` là validator mặc định được sử dụng để validation các parameter cụ thể của OAuth2 Client Credentials Grant request.

[TIP]

[[oauth2AuthorizationServer-oauth2-token-endpoint-dpop-bound-access-tokens]]
=== DPoP-bound Access Tokens

https://datatracker.ietf.org/doc/html/rfc9449[RFC 9449 OAuth 2.0 Demonstrating Proof of Possession (DPoP)] là một cơ chế ở cấp ứng dụng để sender-constrain access token.

Mục tiêu chính của DPoP là ngăn client trái phép hoặc không hợp lệ sử dụng access token bị làm lộ hoặc đánh cắp, bằng cách bind access token với một public key khi authorization server cấp token và yêu cầu client chứng minh quyền sở hữu private key tương ứng khi sử dụng access token tại resource server.

Access token được sender-constrain thông qua DPoP khác với bearer token thông thường, vốn có thể được sử dụng bởi bất kỳ client nào sở hữu access token.

DPoP đưa ra khái niệm https://datatracker.ietf.org/doc/html/rfc9449#name-dpop-proof-jwts[DPoP Proof], là một JWT do client tạo và gửi trong header của HTTP request.
Client sử dụng DPoP proof để chứng minh quyền sở hữu private key tương ứng với một public key nhất định.

Khi client khởi tạo access token request, nó đính kèm DPoP proof vào request trong HTTP header.
Authorization server bind (sender-constrain) access token với public key được liên kết trong DPoP proof.

Khi client khởi tạo protected resource request, nó lại đính kèm DPoP proof vào request trong HTTP header.

Resource server lấy thông tin về public key được liên kết với access token, trực tiếp từ access token (JWT) hoặc thông qua <<oauth2AuthorizationServer-oauth2-token-introspection-endpoint,OAuth2 Token Introspection endpoint>>.
Sau đó resource server verify public key được liên kết với access token khớp với public key trong DPoP proof.
Nó cũng verify hash của access token trong DPoP proof khớp với access token trong request.

[[oauth2AuthorizationServer-oauth2-token-endpoint-dpop-public-key-confirmation]]
==== Public Key Confirmation

Resource server MUST có khả năng xác định access token có được bind với DPoP hay không và verify binding với public key của DPoP proof.
Binding được thực hiện bằng cách liên kết public key với access token theo cách resource server có thể truy cập, chẳng hạn nhúng trực tiếp hash của public key vào access token (JWT) hoặc thông qua token introspection.

Khi access token được biểu diễn dưới dạng JWT, hash của public key nằm trong claim `jkt` bên dưới confirmation method claim (`cnf`).

Ví dụ sau cho thấy các claim của JWT access token chứa claim `cnf` với claim `jkt`, là JWK SHA-256 Thumbprint của public key trong DPoP proof:

[source,json]

  "cnf":
  {

`OidcLogoutAuthenticationValidator` là validator mặc định được sử dụng để validation các parameter cụ thể của OpenID Connect RP-Initiated Logout request.

`OidcClientRegistrationEndpointFilter` được cấu hình với các giá trị mặc định sau:

* `*AuthenticationConverter*` -- Một `OidcClientRegistrationAuthenticationConverter`.
* `*AuthenticationManager*` -- Một `AuthenticationManager` được tạo thành từ `OidcClientRegistrationAuthenticationProvider` và `OidcClientConfigurationAuthenticationProvider`.
* `*AuthenticationSuccessHandler*` -- Một implementation nội bộ xử lý một `OidcClientRegistrationAuthenticationToken` ở trạng thái "`authenticated`" và trả về `OidcClientRegistration` response.
* `*AuthenticationFailureHandler*` -- Một implementation nội bộ sử dụng `OAuth2Error` liên kết với `OAuth2AuthenticationException` và trả về `OAuth2Error` response.

OpenID Connect 1.0 Client Registration endpoint là một https://openid.net/specs/openid-connect-registration-1_0.html#ClientRegistration[OAuth2 protected resource], *REQUIRES* access token được gửi dưới dạng bearer token trong Client Registration (hoặc Client Read) request.

[NOTE]
Hỗ trợ OAuth2 resource server được tự động cấu hình, tuy nhiên `JwtDecoder` `@Bean` *REQUIRED* cho OpenID Connect 1.0 Client Registration endpoint.

[IMPORTANT]
Access token trong Client Registration request *REQUIRES* OAuth2 scope `client.create`.

[IMPORTANT]
Access token trong Client Read request *REQUIRES* OAuth2 scope `client.read`.
