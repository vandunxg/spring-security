= Opaque Token của OAuth 2.0 Resource Server
:figures: servlet/oauth2

[[oauth2resourceserver-opaque-minimaldependencies]]
== Dependency tối thiểu cho introspection
Như đã mô tả trong xref:servlet/oauth2/resource-server/jwt.adoc#oauth2resourceserver-jwt-minimaldependencies[Dependency tối thiểu cho JWT], phần lớn phần hỗ trợ Resource Server được tập hợp trong `spring-security-oauth2-resource-server`.
Tuy nhiên, nếu không cung cấp một <<oauth2resourceserver-opaque-introspector,`OpaqueTokenIntrospector`>> tùy chỉnh, Resource Server sẽ fallback về `SpringOpaqueTokenIntrospector`.
Điều này có nghĩa là chỉ cần `spring-security-oauth2-resource-server` để có một Resource Server tối thiểu hoạt động được và hỗ trợ opaque Bearer Token.

[[oauth2resourceserver-opaque-minimalconfiguration]]
== Cấu hình tối thiểu cho introspection

Thông thường, opaque token có thể được xác minh thông qua https://tools.ietf.org/html/rfc7662[OAuth 2.0 Introspection Endpoint] do Authorization Server lưu trữ.
Điều này hữu ích khi yêu cầu đặt ra là phải thu hồi token.

Khi sử dụng https://spring.io/projects/spring-boot[Spring Boot], việc cấu hình một ứng dụng thành Resource Server sử dụng introspection gồm hai bước cơ bản.
Thứ nhất, thêm các dependency cần thiết; thứ hai, chỉ định thông tin chi tiết của introspection endpoint.

[[oauth2resourceserver-opaque-introspectionuri]]
=== Chỉ định Authorization Server

Để chỉ định vị trí của introspection endpoint, chỉ cần làm như sau:

[source,yaml]
----
spring:
  security:
    oauth2:
      resourceserver:
        opaquetoken:
          introspection-uri: https://idp.example.com/introspect
          client-id: client
          client-secret: secret
----

Trong đó, `https://idp.example.com/introspect` là introspection endpoint được Authorization Server của bạn host, còn `client-id` và `client-secret` là các credential cần thiết để gọi endpoint đó.

Resource Server sẽ sử dụng các property này để tự cấu hình thêm và sau đó xác thực JWT đến.

[NOTE]
Khi sử dụng introspection, kết luận của Authorization Server là quyết định cuối cùng.
Nếu Authorization Server phản hồi rằng token hợp lệ thì token đó hợp lệ.

Vậy là xong!

=== Kỳ vọng khi khởi động

Khi sử dụng property và các dependency này, Resource Server sẽ tự động cấu hình để xác thực Opaque Bearer Token.

Quy trình khởi động này đơn giản hơn khá nhiều so với JWT vì không cần discovery endpoint và không thêm quy tắc xác thực nào khác.

=== Kỳ vọng khi chạy

Sau khi ứng dụng khởi động, Resource Server sẽ cố gắng xử lý mọi request chứa header `Authorization: Bearer`:

[source,http]
----
GET / HTTP/1.1
Authorization: Bearer some-token-value # Resource Server will process this
----

Miễn là scheme này được chỉ định, Resource Server sẽ cố gắng xử lý request theo đặc tả Bearer Token.

Với một Opaque Token, Resource Server sẽ

1. Truy vấn introspection endpoint đã cung cấp bằng credential và token đã cung cấp
2. Kiểm tra response để tìm attribute `{ 'active' : true }`
3. Ánh xạ mỗi scope thành một authority với tiền tố `SCOPE_`

Kết quả của `Authentication#getPrincipal`, theo mặc định, là một object Spring Security javadoc:org.springframework.security.oauth2.core.OAuth2AuthenticatedPrincipal[], còn `Authentication#getName` ánh xạ tới property `sub` của token nếu property này tồn tại.

Từ đây, bạn có thể chuyển tới:

* <<oauth2resourceserver-opaque-architecture>>
* <<oauth2resourceserver-opaque-attributes,Tra cứu attribute sau authentication>>
* <<oauth2resourceserver-opaque-authorization-extraction,Trích xuất authority thủ công>>
* <<oauth2resourceserver-opaque-jwt-introspector,Sử dụng introspection với JWT>>

[[oauth2resourceserver-opaque-architecture]]
== Authentication bằng Opaque Token hoạt động như thế nào

Tiếp theo, hãy xem các thành phần kiến trúc mà Spring Security sử dụng để hỗ trợ authentication cho https://tools.ietf.org/html/rfc7662[opaque token] trong các ứng dụng dựa trên Servlet, như ứng dụng vừa xem.

javadoc:org.springframework.security.oauth2.server.resource.authentication.OpaqueTokenAuthenticationProvider[] là một implementation của xref:servlet/authentication/architecture.adoc#servlet-authentication-authenticationprovider[`AuthenticationProvider`], sử dụng <<oauth2resourceserver-opaque-introspector,`OpaqueTokenIntrospector`>> để authenticate một opaque token.

Hãy xem `OpaqueTokenAuthenticationProvider` hoạt động như thế nào trong Spring Security.
Hình minh họa giải thích chi tiết cách xref:servlet/authentication/architecture.adoc#servlet-authentication-authenticationmanager[`AuthenticationManager`] trong các hình thuộc xref:servlet/oauth2/resource-server/index.adoc#oauth2resourceserver-authentication-bearertokenauthenticationfilter[Đọc Bearer Token] hoạt động.

.Cách sử dụng `OpaqueTokenAuthenticationProvider`
[.invert-dark]
image::{figures}/opaquetokenauthenticationprovider.png[]

image:{icondir}/number_1.png[] `Filter` authentication từ xref:servlet/oauth2/resource-server/index.adoc#oauth2resourceserver-authentication-bearertokenauthenticationfilter[Đọc Bearer Token] truyền một `BearerTokenAuthenticationToken` tới `AuthenticationManager`, được triển khai bởi xref:servlet/authentication/architecture.adoc#servlet-authentication-providermanager[`ProviderManager`].

image:{icondir}/number_2.png[] `ProviderManager` được cấu hình để sử dụng xref:servlet/authentication/architecture.adoc#servlet-authentication-authenticationprovider[AuthenticationProvider] có kiểu `OpaqueTokenAuthenticationProvider`.

[[oauth2resourceserver-opaque-architecture-introspector]]
image:{icondir}/number_3.png[] `OpaqueTokenAuthenticationProvider` thực hiện introspection opaque token và thêm các authority được cấp thông qua một <<oauth2resourceserver-opaque-introspector,`OpaqueTokenIntrospector`>>.
Khi authentication thành công, xref:servlet/authentication/architecture.adoc#servlet-authentication-authentication[`Authentication`] được trả về có kiểu `BearerTokenAuthentication`, với principal là `OAuth2AuthenticatedPrincipal` do <<oauth2resourceserver-opaque-introspector,`OpaqueTokenIntrospector`>> đã cấu hình trả về, và một tập authority chứa ít nhất `FACTOR_BEARER`.
Cuối cùng, `BearerTokenAuthentication` được trả về sẽ được `Filter` authentication đặt vào xref:servlet/authentication/architecture.adoc#servlet-authentication-securitycontextholder[`SecurityContextHolder`].

[[oauth2resourceserver-opaque-attributes]]
== Tra cứu attribute sau authentication

Sau khi token được authenticated, một instance của `BearerTokenAuthentication` được đặt trong `SecurityContext`.

Điều này có nghĩa là nó khả dụng trong các method `@Controller` khi sử dụng `@EnableWebMvc` trong cấu hình:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/foo")
public String foo(BearerTokenAuthentication authentication) {
    return authentication.getTokenAttributes().get("sub") + " is the subject";
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/foo")
fun foo(authentication: BearerTokenAuthentication): String {
    return authentication.tokenAttributes["sub"].toString() + " is the subject"
}
----
======

Vì `BearerTokenAuthentication` chứa một `OAuth2AuthenticatedPrincipal`, điều đó cũng có nghĩa là nó khả dụng trong các method của controller:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@GetMapping("/foo")
public String foo(@AuthenticationPrincipal OAuth2AuthenticatedPrincipal principal) {
    return principal.getAttribute("sub") + " is the subject";
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@GetMapping("/foo")
fun foo(@AuthenticationPrincipal principal: OAuth2AuthenticatedPrincipal): String {
    return principal.getAttribute<Any>("sub").toString() + " is the subject"
}
----
======

[[oauth2resourceserver-opaque-sansboot]]
== Ghi đè hoặc thay thế Boot Auto Configuration

Có hai ``@Bean`` được Spring Boot tạo thay cho Resource Server.

Bean đầu tiên là một `SecurityFilterChain` cấu hình ứng dụng thành Resource Server.
Khi sử dụng Opaque Token, `SecurityFilterChain` này có dạng:

.Cấu hình Opaque Token mặc định
[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http
        .authorizeHttpRequests((authorize) -> authorize
            .anyRequest().authenticated()
        )
        .oauth2ResourceServer((oauth2) -> oauth2
            .opaqueToken(Customizer.withDefaults())
        );
    return http.build();
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
open fun filterChain(http: HttpSecurity): SecurityFilterChain {
    http {
        authorizeHttpRequests {
            authorize(anyRequest, authenticated)
        }
        oauth2ResourceServer {
            opaqueToken { }
        }
    }
    return http.build()
}
----
======

Nếu ứng dụng không expose một bean `SecurityFilterChain`, Spring Boot sẽ expose bean mặc định như trên.

Việc thay thế bean này đơn giản là expose bean đó trong ứng dụng:

.Cấu hình Opaque Token tùy chỉnh
[tabs]
======
Java::
+
[source,java,role="primary"]
----
import static org.springframework.security.oauth2.core.authorization.OAuth2AuthorizationManagers.hasScope;

@Configuration
@EnableWebSecurity
public class MyCustomSecurityConfiguration {
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests((authorize) -> authorize
                .requestMatchers("/messages/**").access(hasScope("message:read"))
                .anyRequest().authenticated()
            )
            .oauth2ResourceServer((oauth2) -> oauth2
                .opaqueToken((opaqueToken) -> opaqueToken
                    .introspector(myIntrospector())
                )
            );
        return http.build();
    }
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
import org.springframework.security.oauth2.core.authorization.OAuth2AuthorizationManagers.hasScope;

@Configuration
@EnableWebSecurity
class MyCustomSecurityConfiguration {
    @Bean
    open fun filterChain(http: HttpSecurity): SecurityFilterChain {
        http {
            authorizeHttpRequests {
                authorize("/messages/**", hasScope("SCOPE_message:read"))
                authorize(anyRequest, authenticated)
            }
            oauth2ResourceServer {
                opaqueToken {
                    introspector = myIntrospector()
                }
            }
        }
        return http.build()
    }
}
----
======

Phần trên yêu cầu scope `message:read` cho mọi URL bắt đầu bằng `/messages/`.

Các method trên DSL `oauth2ResourceServer` cũng sẽ ghi đè hoặc thay thế auto-configuration.

[[oauth2resourceserver-opaque-introspector]]
Ví dụ, `@Bean` thứ hai Spring Boot tạo là một `OpaqueTokenIntrospector`, <<oauth2resourceserver-opaque-architecture-introspector,giải mã token `String` thành các instance `OAuth2AuthenticatedPrincipal` đã được xác thực>>:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
public OpaqueTokenIntrospector introspector() {
    return SpringOpaqueTokenIntrospector.withIntrospectionUri(introspectionUri)
            .clientId(clientId).clientSecret(clientSecret).build();
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
fun introspector(): OpaqueTokenIntrospector {
    return SpringOpaqueTokenIntrospector.withIntrospectionUri(introspectionUri)
            .clientId(clientId).clientSecret(clientSecret).build()
}
----
======

Nếu ứng dụng không expose bean <<oauth2resourceserver-opaque-architecture-introspector,`OpaqueTokenIntrospector`>>, Spring Boot sẽ expose bean mặc định như trên.

Cấu hình của bean này có thể được ghi đè bằng `introspectionUri()` và `introspectionClientCredentials()`, hoặc được thay thế bằng `introspector()`.

Nếu ứng dụng không expose bean `OpaqueTokenAuthenticationConverter`, spring-security sẽ xây dựng `BearerTokenAuthentication`.

Hoặc, nếu hoàn toàn không sử dụng Spring Boot, tất cả các thành phần này - filter chain, một <<oauth2resourceserver-opaque-architecture-introspector,`OpaqueTokenIntrospector`>> và một `OpaqueTokenAuthenticationConverter` - có thể được chỉ định trong XML.

[[oauth2resourceserver-opaque-authorization]]
== Cấu hình authorization

OAuth 2.0 Introspection endpoint thường trả về một attribute `scope`, cho biết các scope (hoặc authority) đã được cấp, ví dụ:

`{ ..., "scope" : "messages contacts"}`

Trong trường hợp này, Resource Server sẽ cố gắng chuyển các scope này thành một danh sách authority được cấp, thêm chuỗi "SCOPE_" làm tiền tố cho mỗi scope.

Điều này có nghĩa là để bảo vệ một endpoint hoặc method bằng scope được lấy từ Opaque Token, các expression tương ứng phải chứa tiền tố này:

.Cấu hình authorization cho Opaque Token
[tabs]
======
Java::
+
[source,java,role="primary"]
----
import static org.springframework.security.oauth2.core.authorization.OAuth2AuthorizationManagers.hasScope;

@Configuration
@EnableWebSecurity
public class MappedAuthorities {
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests((authorizeRequests) -> authorizeRequests
                .requestMatchers("/contacts/**").access(hasScope("contacts"))
                .requestMatchers("/messages/**").access(hasScope("messages"))
                .anyRequest().authenticated()
            )
            .oauth2ResourceServer((oauth2) -> oauth2
                .opaqueToken(Customizer.withDefaults())
            );
        return http.build();
    }
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
import org.springframework.security.oauth2.core.authorization.OAuth2AuthorizationManagers.hasScope

@Configuration
@EnableWebSecurity

    @Bean

                authorize(anyRequest, authenticated)
            }
           oauth2ResourceServer {
               opaqueToken { }
           }
        }
        return http.build()
    }
}
----

[[oauth2resourceserver-opaque-authorization-extraction]]
=== Trích xuất authority thủ công

Theo mặc định, phần hỗ trợ Opaque Token sẽ trích xuất claim scope từ introspection response và phân tích thành các instance `GrantedAuthority` riêng lẻ.

Ví dụ, nếu introspection response là:

[source,json]
----
{
    "active" : true,
    "scope" : "message:read message:write"
}
----

Resource Server sẽ tạo một `Authentication` với hai authority, một cho `message:read` và một cho `message:write`.

Tất nhiên, có thể tùy chỉnh điều này bằng một <<oauth2resourceserver-opaque-architecture-introspector,`OpaqueTokenIntrospector`>> tùy chỉnh, xem xét tập attribute và chuyển đổi theo cách riêng:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
public class CustomAuthoritiesOpaqueTokenIntrospector implements OpaqueTokenIntrospector {
    private OpaqueTokenIntrospector delegate = SpringOpaqueTokenIntrospector
            .withIntrospectionUri("https://idp.example.org/introspect")
            .clientId("client").clientSecret("secret").build();

    public OAuth2AuthenticatedPrincipal introspect(String token) {
        OAuth2AuthenticatedPrincipal principal = this.delegate.introspect(token);
        return new DefaultOAuth2AuthenticatedPrincipal(
                principal.getName(), principal.getAttributes(), extractAuthorities(principal));
    }

    private Collection<GrantedAuthority> extractAuthorities(OAuth2AuthenticatedPrincipal principal) {
        List<String> scopes = principal.getAttribute(OAuth2IntrospectionClaimNames.SCOPE);
        return scopes.stream()
                .map(SimpleGrantedAuthority::new)
                .collect(Collectors.toList());
    }
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----

[[oauth2resourceserver-opaque-jwt-introspector]]
== Sử dụng introspection với JWT

Một câu hỏi thường gặp là introspection có tương thích với JWT hay không.
Phần hỗ trợ Opaque Token của Spring Security được thiết kế để không quan tâm đến format của token -- nó sẽ chuyển bất kỳ token nào tới introspection endpoint được cung cấp.

Giả sử bạn có yêu cầu phải kiểm tra với Authorization Server trong mỗi request, phòng trường hợp JWT bị thu hồi.

Dù token dùng format JWT, phương thức validation của bạn là introspection, nên bạn sẽ làm như sau:

[source,yaml]
----
spring:
  security:
    oauth2:
      resourceserver:
        opaquetoken:
          introspection-uri: https://idp.example.org/introspection
          client-id: client
          client-secret: secret
----

Trong trường hợp này, `Authentication` kết quả sẽ là `BearerTokenAuthentication`.
Mọi attribute trong `OAuth2AuthenticatedPrincipal` tương ứng sẽ là các giá trị do introspection endpoint trả về.

Nhưng giả sử, khá đặc biệt, introspection endpoint chỉ trả về việc token có active hay không.
Khi đó phải làm gì?

Trong trường hợp này, bạn có thể tạo một <<oauth2resourceserver-opaque-architecture-introspector,`OpaqueTokenIntrospector`>> tùy chỉnh, vẫn gọi endpoint đó nhưng sau đó cập nhật principal được trả về để các claim của JWT trở thành attribute:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
public class JwtOpaqueTokenIntrospector implements OpaqueTokenIntrospector {
    private OpaqueTokenIntrospector delegate = SpringOpaqueTokenIntrospector
            .withIntrospectionUri("https://idp.example.org/introspect")
            .clientId("client").clientSecret("secret").build();
    private JwtDecoder jwtDecoder = new NimbusJwtDecoder(new ParseOnlyJWTProcessor());

    public OAuth2AuthenticatedPrincipal introspect(String token) {
        OAuth2AuthenticatedPrincipal principal = this.delegate.introspect(token);
        try {
            Jwt jwt = this.jwtDecoder.decode(token);
            return new DefaultOAuth2AuthenticatedPrincipal(jwt.getClaims(), NO_AUTHORITIES);
        } catch (JwtException ex) {
            throw new OAuth2IntrospectionException(ex);
        }
    }

    private static class ParseOnlyJWTProcessor extends DefaultJWTProcessor<SecurityContext> {
    	JWTClaimsSet process(SignedJWT jwt, SecurityContext context)
                throws JOSEException {
            return jwt.getJWTClaimsSet();
        }
    }
}
----

Kotlin::
+

[[oauth2resourceserver-opaque-userinfo]]
== Gọi endpoint `/userinfo`

Nói chung, Resource Server không quan tâm đến user đứng sau mà quan tâm đến các authority đã được cấp.

Tuy vậy, đôi khi việc gắn quyết định authorization với một user có thể hữu ích.

Nếu ứng dụng cũng sử dụng `spring-security-oauth2-client` và đã thiết lập `ClientRegistrationRepository` phù hợp, việc này khá đơn giản với một <<oauth2resourceserver-opaque-architecture-introspector,`OpaqueTokenIntrospector`>> tùy chỉnh.
Implementation này thực hiện ba việc:

* Ủy thác việc gọi introspection endpoint để xác nhận token hợp lệ
* Tra cứu client registration tương ứng được liên kết với endpoint `/userinfo`
* Gọi endpoint `/userinfo` và trả về response của endpoint đó

[tabs]
======
Java::
+
[source,java,role="primary"]
----
public class UserInfoOpaqueTokenIntrospector implements OpaqueTokenIntrospector {
    private final OpaqueTokenIntrospector delegate = SpringOpaqueTokenIntrospector
            .withIntrospectionUri("https://idp.example.org/introspect")
            .clientId("client").clientSecret("secret").build();
    private final OAuth2UserService oauth2UserService = new DefaultOAuth2UserService();

    private final ClientRegistrationRepository repository;

    // ... constructor

    @Override
    public OAuth2AuthenticatedPrincipal introspect(String token) {
        OAuth2AuthenticatedPrincipal authorized = this.delegate.introspect(token);
        Instant issuedAt = authorized.getAttribute(ISSUED_AT);
        Instant expiresAt = authorized.getAttribute(EXPIRES_AT);
        ClientRegistration clientRegistration = this.repository.findByRegistrationId("registration-id");
        OAuth2AccessToken token = new OAuth2AccessToken(BEARER, token, issuedAt, expiresAt);
        OAuth2UserRequest oauth2UserRequest = new OAuth2UserRequest(clientRegistration, token);
        return this.oauth2UserService.loadUser(oauth2UserRequest);
    }
}
----
