= OAuth 2.0 Resource Server JWT
:figures: servlet/oauth2

[[oauth2resourceserver-jwt-minimaldependencies]]
== Dependency tối thiểu cho JWT

Phần lớn hỗ trợ cho Resource Server được tập hợp trong `spring-security-oauth2-resource-server`.
Tuy nhiên, phần hỗ trợ giải mã và xác minh JWT nằm trong `spring-security-oauth2-jose`, nên cần cả hai dependency để có một Resource Server hoạt động hỗ trợ Bearer Token được mã hóa bằng JWT.

[[oauth2resourceserver-jwt-minimalconfiguration]]
== Cấu hình tối thiểu cho JWT

Khi sử dụng https://spring.io/projects/spring-boot[Spring Boot], việc cấu hình một ứng dụng thành Resource Server gồm hai bước cơ bản.
Trước tiên, thêm các dependency cần thiết, sau đó chỉ ra vị trí của Authorization Server.

=== Chỉ định Authorization Server

Trong một ứng dụng Spring Boot, để chỉ định authorization server cần sử dụng, chỉ cần làm như sau:

[source,yml]
----
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://idp.example.com/issuer
----

Trong đó, `https://idp.example.com/issuer` là giá trị nằm trong claim `iss` của các JWT token mà authorization server sẽ cấp.
Resource Server sẽ sử dụng property này để tự cấu hình thêm, phát hiện public key của authorization server, rồi xác thực các JWT đến.

[NOTE]
Để sử dụng property `issuer-uri`, một trong các endpoint `https://idp.example.com/issuer/.well-known/openid-configuration`, `https://idp.example.com/.well-known/openid-configuration/issuer` hoặc `https://idp.example.com/.well-known/oauth-authorization-server/issuer` cũng phải là endpoint được authorization server hỗ trợ.
Endpoint này được gọi là endpoint https://openid.net/specs/openid-connect-discovery-1_0.html#ProviderConfig[Cấu hình Provider] hoặc endpoint https://tools.ietf.org/html/rfc8414#section-3[Metadata của Authorization Server].

Chỉ vậy thôi!

=== Kỳ vọng khi khởi động

Khi sử dụng property và các dependency này, Resource Server sẽ tự động cấu hình để xác thực Bearer Token được mã hóa bằng JWT.

Resource Server thực hiện việc này thông qua một quy trình discovery xác định được khởi chạy khi có request đầu tiên chứa JWT:

1. Truy vấn endpoint Provider Configuration hoặc Authorization Server Metadata để lấy property `jwks_url`
2. Truy vấn endpoint `jwks_url` để lấy các algorithm được hỗ trợ
3. Cấu hình strategy xác thực để truy vấn `jwks_url` nhằm lấy public key hợp lệ của các algorithm đã tìm thấy
4. Cấu hình strategy xác thực để kiểm tra claim `iss` của từng JWT với `https://idp.example.com`.

Một lợi ích của việc trì hoãn quy trình này là việc khởi động Resource Server không phụ thuộc vào tính khả dụng của authorization server.

[NOTE]
====
Việc trì hoãn này được quản lý bởi javadoc:org.springframework.security.oauth2.jwt.SupplierJwtDecoder[`SupplierJwtDecoder`].
Hãy cân nhắc bọc mọi <<oauth2resourceserver-jwt-decoder,`JwtDecoder` `@Bean`>> mà bạn khai báo để giữ nguyên behavior này.
====

=== Kỳ vọng khi chạy

Sau khi ứng dụng khởi động, Resource Server sẽ cố gắng xử lý mọi request chứa header `Authorization: Bearer`:

[source,html]
----
GET / HTTP/1.1
Authorization: Bearer some-token-value # Resource Server will process this
----

Miễn là scheme này được chỉ định, Resource Server sẽ cố gắng xử lý request theo đặc tả Bearer Token.

Với một JWT có định dạng hợp lệ, Resource Server sẽ:

1. Xác thực chữ ký của JWT bằng public key lấy từ endpoint `jwks_url` khi khởi động hoặc trong request đầu tiên, tùy cấu hình, và đối chiếu với JWT
2. Xác thực timestamp `exp` và `nbf` cùng claim `iss` của JWT, và
3. Map mỗi scope thành một authority với prefix `SCOPE_`.

[NOTE]
Khi authorization server cung cấp các key mới, Spring Security sẽ tự động rotate các key được dùng để xác thực JWT.

Theo mặc định, `Authentication#getPrincipal` kết quả là một object `Jwt` của Spring Security, còn `Authentication#getName` map tới property `sub` của JWT nếu property này tồn tại.

Từ đây, bạn có thể chuyển tới:

* <<oauth2resourceserver-jwt-architecture,Authentication JWT hoạt động như thế nào>>
* <<oauth2resourceserver-jwt-jwkseturi,Cách cấu hình mà không ràng buộc việc khởi động Resource Server với tính khả dụng của authorization server>>
* <<oauth2resourceserver-jwt-sansboot,Cách cấu hình mà không dùng Spring Boot>>

== Authentication JWT hoạt động như thế nào

Tiếp theo, hãy xem các thành phần kiến trúc mà Spring Security sử dụng để hỗ trợ Authentication https://tools.ietf.org/html/rfc7519[JWT] trong các ứng dụng dựa trên Servlet như ứng dụng vừa xem.

javadoc:org.springframework.security.oauth2.server.resource.authentication.JwtAuthenticationProvider[] là một implementation của xref:servlet/authentication/architecture.adoc#servlet-authentication-authenticationprovider[`AuthenticationProvider`] sử dụng <<oauth2resourceserver-jwt-decoder,`JwtDecoder`>> và <<oauth2resourceserver-jwt-authorization-extraction,`JwtAuthenticationConverter`>> để thực hiện authentication cho JWT.

Hãy xem `JwtAuthenticationProvider` hoạt động như thế nào trong Spring Security.

[[oauth2resourceserver-jwt-jwkseturi]]
== Chỉ định trực tiếp JWK Set Uri của Authorization Server

Nếu authorization server không hỗ trợ endpoint cấu hình nào, hoặc Resource Server phải có khả năng khởi tạo độc lập với authorization server, bạn cũng có thể cung cấp `jwk-set-uri`:

[source,yaml]
----
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://idp.example.com
          jwk-set-uri: https://idp.example.com/.well-known/jwks.json
----

[NOTE]
JWK Set uri không được chuẩn hóa, nhưng thường có thể tìm thấy trong tài liệu của authorization server

Do đó, Resource Server sẽ không ping authorization server khi khởi động.
Chúng ta vẫn chỉ định `issuer-uri` để Resource Server tiếp tục xác thực claim `iss` trên các JWT đến.

[NOTE]
Property này cũng có thể được cung cấp trực tiếp trong <<oauth2resourceserver-jwt-jwkseturi-dsl,DSL>>.

== Cung cấp audience

Như đã thấy, <<_specifying_the_authorization_server,property `issuer-uri` xác thực claim `iss`>>; đây là bên đã gửi JWT.

Boot cũng có property `audiences` để xác thực claim `aud`; đây là bên nhận JWT.

Audience của Resource Server có thể được chỉ định như sau:

[source,yaml]
----
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://idp.example.com
          audiences: https://my-resource-server.example.com
----

[NOTE]
Nếu cần, bạn cũng có thể <<oauth2resourceserver-jwt-validation-custom,thêm việc xác thực `aud` bằng code>>.

Kết quả là nếu claim `iss` của JWT không phải `https://idp.example.com` và claim `aud` không chứa `https://my-resource-server.example.com` trong danh sách, việc xác thực sẽ thất bại.

[[oauth2resourceserver-jwt-sansboot]]
== Ghi đè hoặc thay thế auto-configuration của Boot

Spring Boot tạo hai ``@Bean`` thay mặt cho Resource Server.

Bean đầu tiên là một `SecurityFilterChain` cấu hình ứng dụng thành Resource Server. Khi thêm `spring-security-oauth2-jose`, `SecurityFilterChain` này có dạng:

.Cấu hình JWT mặc định
[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http
        .authorizeHttpRequests((authorize) -> authorize
            .anyRequest().authenticated()
        )
        .oauth2ResourceServer((oauth2) -> oauth2.jwt(Customizer.withDefaults()));
    return http.build();
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
open fun filterChain(http: HttpSecurity): SecurityFilterChain {
    http {
        authorizeHttpRequests {
            authorize(anyRequest, authenticated)
        }
        oauth2ResourceServer {
            jwt { }
        }
    }
    return http.build()
}
----
======

Nếu ứng dụng không expose bean `SecurityFilterChain`, Spring Boot sẽ expose bean mặc định như trên.

Việc thay thế bean này đơn giản như expose bean trong ứng dụng:

.Cấu hình JWT tùy chỉnh
[tabs]
======
Java::
+
[source,java,role="primary"]
----
import static org.springframework.security.oauth2.core.authorization.OAuth2AuthorizationManagers.hasScope;

@Configuration
@EnableWebSecurity
public class MyCustomSecurityConfiguration {
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests((authorize) -> authorize
                .requestMatchers("/messages/**").access(hasScope("message:read"))
                .anyRequest().authenticated()
            )
            .oauth2ResourceServer((oauth2) -> oauth2
                .jwt((jwt) -> jwt
                    .jwtAuthenticationConverter(myConverter())
                )
            );
        return http.build();
    }
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
import org.springframework.security.oauth2.core.authorization.OAuth2AuthorizationManagers.hasScope

@Configuration
@EnableWebSecurity
class MyCustomSecurityConfiguration {
    @Bean
    open fun filterChain(http: HttpSecurity): SecurityFilterChain {
        http {
            authorizeHttpRequests {
                authorize("/messages/**", hasScope("message:read"))
                authorize(anyRequest, authenticated)
            }
            oauth2ResourceServer {
                jwt {
                    jwtAuthenticationConverter = myConverter()
                }
            }
        }
        return http.build()
    }
}
----
======

Cấu hình trên yêu cầu scope `message:read` cho mọi URL bắt đầu bằng `/messages/`.

Các method trên DSL `oauth2ResourceServer` cũng sẽ ghi đè hoặc thay thế auto-configuration.

[[oauth2resourceserver-jwt-decoder]]
Ví dụ, `@Bean` thứ hai mà Spring Boot tạo là một `JwtDecoder`, dùng để <<oauth2resourceserver-jwt-architecture-jwtdecoder,giải mã token `String` thành các instance `Jwt` đã được xác thực>>:

.JWT Decoder
[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
public JwtDecoder jwtDecoder() {
    return JwtDecoders.fromIssuerLocation(issuerUri);
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
fun jwtDecoder(): JwtDecoder {
    return JwtDecoders.fromIssuerLocation(issuerUri)
}
----
======

[NOTE]
Việc gọi javadoc:org.springframework.security.oauth2.jwt.JwtDecoders#fromIssuerLocation-java.lang.String-[JwtDecoders#fromIssuerLocation] sẽ gọi endpoint Provider Configuration hoặc Authorization Server Metadata để suy ra JWK Set Uri.

Nếu ứng dụng không expose bean `JwtDecoder`, Spring Boot sẽ expose bean mặc định như trên.

Bạn có thể ghi đè cấu hình của nó bằng `jwkSetUri()` hoặc thay thế bằng `decoder()`.

Hoặc, nếu hoàn toàn không sử dụng Spring Boot, bạn có thể chỉ định cả hai thành phần này - filter chain và một `JwtDecoder` - trong XML.

Filter chain được chỉ định như sau:

.Cấu hình JWT mặc định
[tabs]
======
Xml::
+
[source,xml,role="primary"]
----
<http>
    <intercept-uri pattern="/**" access="authenticated"/>
    <oauth2-resource-server>
        <jwt decoder-ref="jwtDecoder"/>
    </oauth2-resource-server>
</http>
----
======

`JwtDecoder` được chỉ định như sau:

.JWT Decoder
[tabs]
======
Xml::
+
[source,xml,role="primary"]
----
<bean id="jwtDecoder"
        class="org.springframework.security.oauth2.jwt.JwtDecoders"
        factory-method="fromIssuerLocation">
    <constructor-arg value="${spring.security.oauth2.resourceserver.jwt.jwk-set-uri}"/>
</bean>
----
======

=== Sử dụng `decoder()`

Mạnh hơn `jwkSetUri()` là `decoder()`, method này sẽ hoàn toàn thay thế mọi auto-configuration của Boot đối với <<oauth2resourceserver-jwt-architecture-jwtdecoder,`JwtDecoder`>>:

.Cấu hình JWT Decoder
[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Configuration
@EnableWebSecurity
public class DirectlyConfiguredJwtDecoder {
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests((authorize) -> authorize
                .anyRequest().authenticated()
            )
            .oauth2ResourceServer((oauth2) -> oauth2
                .jwt((jwt) -> jwt
                    .decoder(myCustomDecoder())
                )
            );
        return http.build();
    }
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----

@EnableWebSecurity
class DirectlyConfiguredJwtDecoder {

    open fun filterChain(http: HttpSecurity): SecurityFilterChain {

                authorize(anyRequest, authenticated)
            }
            oauth2ResourceServer {
                jwt {
                    jwtDecoder = myCustomDecoder()
                }

}

+
[source,xml,role="secondary"]

Hoặc, expose một `@Bean` <<oauth2resourceserver-jwt-architecture-jwtdecoder,`JwtDecoder`>> cũng có tác dụng giống `decoder()`.
Bạn có thể tạo một bean với `jwkSetUri` như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
public JwtDecoder jwtDecoder() {
    return NimbusJwtDecoder.withJwkSetUri(jwkSetUri).build();
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
fun jwtDecoder(): JwtDecoder {
    return NimbusJwtDecoder.withJwkSetUri(jwkSetUri).build()
}
----
======

hoặc bạn có thể sử dụng issuer và để `NimbusJwtDecoder` tra cứu `jwkSetUri` khi gọi `build()`, như sau:

[tabs]
======
Java::
+
[source,java,role="primary"]
----

public JwtDecoder jwtDecoder() {
    NimbusJwtDecoder jwtDecoder = NimbusJwtDecoder.withIssuerLocation(issuer).build();

    return jwtDecoder;

----

+

[[oauth2resourceserver-jwt-decoder-algorithm]]
== Cấu hình algorithm được tin cậy

Theo mặc định, `NimbusJwtDecoder`, và do đó cả Resource Server, chỉ tin cậy và xác minh token sử dụng `RS256`.

Bạn có thể tùy chỉnh điều này thông qua <<oauth2resourceserver-jwt-boot-algorithm,Spring Boot>>, <<oauth2resourceserver-jwt-decoder-builder,builder của NimbusJwtDecoder>> hoặc từ <<oauth2resourceserver-jwt-decoder-jwk-response,phản hồi JWK Set>>.

[[oauth2resourceserver-jwt-boot-algorithm]]
=== Qua Spring Boot

Cách đơn giản nhất để đặt algorithm là sử dụng property:

[source,yaml]
----
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          jws-algorithms: RS512
          jwk-set-uri: https://idp.example.org/.well-known/jwks.json
----

[[oauth2resourceserver-jwt-decoder-builder]]
=== Sử dụng Builder

Tuy nhiên, để có nhiều khả năng tùy chỉnh hơn, chúng ta có thể sử dụng builder đi kèm `NimbusJwtDecoder`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
JwtDecoder jwtDecoder() {
    NimbusJwtDecoder jwtDecoder = NimbusJwtDecoder.withIssuerLocation(this.issuer)
            .jwsAlgorithm(RS512).build();
    jwtDecoder.setJwtValidator(JwtValidators.createDefaultWithIssuer(this.issuer));
    return jwtDecoder;
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
fun jwtDecoder(): JwtDecoder {

=== Từ phản hồi JWK Set

Vì phần hỗ trợ JWT của Spring Security dựa trên Nimbus, bạn cũng có thể sử dụng tất cả các tính năng hữu ích của Nimbus.

[[oauth2resourceserver-jwt-authorization]]
== Cấu hình authorization

JWT được cấp từ OAuth 2.0 Authorization Server thường có attribute `scope` hoặc `scp`, cho biết các scope (hoặc authority) đã được cấp, ví dụ:

`{ ..., "scope" : "messages contacts"}`

Trong trường hợp này, Resource Server sẽ cố gắng chuyển các scope này thành danh sách authority được cấp, thêm chuỗi "SCOPE_" vào trước mỗi scope.

Điều này có nghĩa là để bảo vệ một endpoint hoặc method bằng scope lấy từ JWT, các expression tương ứng phải chứa prefix này:

.Cấu hình authorization
[tabs]
======
Java::
+
[source,java,role="primary"]
----
import static org.springframework.security.oauth2.core.authorization.OAuth2AuthorizationManagers.hasScope;

@Configuration
@EnableWebSecurity
public class DirectlyConfiguredJwkSetUri {
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests((authorize) -> authorize
                .requestMatchers("/contacts/**").access(hasScope("contacts"))
                .requestMatchers("/messages/**").access(hasScope("messages"))
                .anyRequest().authenticated()
            )
            .oauth2ResourceServer((oauth2) -> oauth2
                .jwt(Customizer.withDefaults())
            );
        return http.build();
    }
}
----

[[oauth2resourceserver-jwt-authorization-extraction]]
=== Trích xuất authority thủ công

Tuy nhiên, có một số trường hợp giá trị mặc định này không đủ.
Ví dụ, một số authorization server không sử dụng attribute `scope` mà có attribute tùy chỉnh riêng.
Hoặc trong những trường hợp khác, Resource Server có thể cần chuyển một attribute hoặc tổ hợp các attribute thành các authority nội bộ.

Khi cấu hình `JwtAuthenticationConverter`, bạn có thể cung cấp một converter phụ để chuyển từ `Jwt` thành `Collection` các authority được cấp.

[[oauth2resourceserver-jwt-validation]]
== Cấu hình validation

Khi sử dụng <<oauth2resourceserver-jwt-minimalconfiguration,cấu hình Spring Boot tối thiểu>> và chỉ định issuer uri của authorization server, Resource Server mặc định sẽ xác minh claim `iss` cùng các claim timestamp `exp` và `nbf`.

Trong trường hợp cần tùy chỉnh validation, Resource Server cung cấp hai validator tiêu chuẩn và cũng chấp nhận các instance `OAuth2TokenValidator` tùy chỉnh.

[[oauth2resourceserver-jwt-validation-clockskew]]
=== Tùy chỉnh validation timestamp

JWT thường có một khoảng thời gian hợp lệ, trong đó thời điểm bắt đầu được chỉ ra trong claim `nbf` và thời điểm kết thúc được chỉ ra trong claim `exp`.

Tuy nhiên, mọi server đều có thể gặp hiện tượng clock drift, khiến token có vẻ đã hết hạn trên server này nhưng chưa hết hạn trên server khác.
Điều này có thể gây khó khăn trong implementation khi số lượng server phối hợp tăng lên trong một hệ thống phân tán.

Resource Server sử dụng `JwtTimestampValidator` để xác minh khoảng thời gian hợp lệ của token và có thể cấu hình `clockSkew` để giảm vấn đề trên:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
JwtDecoder jwtDecoder() {
     NimbusJwtDecoder jwtDecoder = (NimbusJwtDecoder)
             JwtDecoders.fromIssuerLocation(issuerUri);

     OAuth2TokenValidator<Jwt> withClockSkew = new DelegatingOAuth2TokenValidator<>(
            new JwtTimestampValidator(Duration.ofSeconds(60)),
            new JwtIssuerValidator(issuerUri));

     jwtDecoder.setJwtValidator(withClockSkew);

     return jwtDecoder;
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
fun jwtDecoder(): JwtDecoder {
    val jwtDecoder: NimbusJwtDecoder = JwtDecoders.fromIssuerLocation(issuerUri) as NimbusJwtDecoder

    val withClockSkew: OAuth2TokenValidator<Jwt> = DelegatingOAuth2TokenValidator(
            JwtTimestampValidator(Duration.ofSeconds(60)),
            JwtIssuerValidator(issuerUri))

    jwtDecoder.setJwtValidator(withClockSkew)

    return jwtDecoder
}
----

[NOTE]
Theo mặc định, Resource Server cấu hình clock skew là 60 giây.

    @Override
    public OAuth2TokenValidatorResult validate(Jwt jwt) {
        if (jwt.getAudience().contains("messaging")) {

[[oauth2resourceserver-jwt-claimsetmapping]]
== Cấu hình mapping claim set

Spring Security sử dụng thư viện https://bitbucket.org/connect2id/nimbus-jose-jwt/wiki/Home[Nimbus] để phân tích JWT và xác thực chữ ký của chúng.
Do đó, Spring Security phụ thuộc vào cách Nimbus diễn giải giá trị của từng field và chuyển từng giá trị thành kiểu Java như thế nào.

Ví dụ, vì Nimbus vẫn tương thích với Java 7, nó không sử dụng `Instant` để biểu diễn các field timestamp.

Bạn hoàn toàn có thể sử dụng một thư viện khác để xử lý JWT, và thư viện đó có thể có các quyết định chuyển đổi riêng cần được điều chỉnh.

Hoặc đơn giản là Resource Server có thể muốn thêm hoặc xóa claim khỏi JWT vì các lý do đặc thù của domain.

Vì những mục đích này, Resource Server hỗ trợ mapping JWT claim set bằng `MappedJwtClaimSetConverter`.

[[oauth2resourceserver-jwt-claimsetmapping-singleclaim]]
=== Tùy chỉnh việc chuyển đổi một claim

Theo mặc định, `MappedJwtClaimSetConverter` sẽ cố gắng chuyển các claim thành những kiểu sau:

|============
| Claim | Kiểu Java
| `aud` | `Collection<String>`
| `exp` | `Instant`
| `iat` | `Instant`
| `iss` | `String`
| `jti` | `String`
| `nbf` | `Instant`
| `sub` | `String`
|============

Strategy chuyển đổi của từng claim có thể được cấu hình bằng `MappedJwtClaimSetConverter.withDefaults`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
JwtDecoder jwtDecoder() {
    NimbusJwtDecoder jwtDecoder = NimbusJwtDecoder.withIssuerLocation(issuer).build();

    MappedJwtClaimSetConverter converter = MappedJwtClaimSetConverter
            .withDefaults(Collections.singletonMap("sub", this::lookupUserIdBySub));
    jwtDecoder.setClaimSetConverter(converter);

    return jwtDecoder;
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
fun jwtDecoder(): JwtDecoder {
    val jwtDecoder = NimbusJwtDecoder.withIssuerLocation(issuer).build()

    val converter = MappedJwtClaimSetConverter
            .withDefaults(mapOf("sub" to this::lookupUserIdBySub))
    jwtDecoder.setClaimSetConverter(converter)

    return jwtDecoder
}
----
======
Thao tác này giữ nguyên mọi giá trị mặc định, ngoại trừ việc ghi đè claim converter mặc định cho `sub`.

[[oauth2resourceserver-jwt-claimsetmapping-rename]]
=== Đổi tên một claim

Trong các tình huống phức tạp hơn, chẳng hạn như truy vấn nhiều claim cùng lúc hoặc đổi tên claim, Resource Server chấp nhận mọi class implement `Converter<Map<String, Object>, Map<String,Object>>`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
public class UsernameSubClaimAdapter implements Converter<Map<String, Object>, Map<String, Object>> {
    private final MappedJwtClaimSetConverter delegate =
            MappedJwtClaimSetConverter.withDefaults(Collections.emptyMap());

    public Map<String, Object> convert(Map<String, Object> claims) {
        Map<String, Object> convertedClaims = this.delegate.convert(claims);

        String username = (String) convertedClaims.get("user_name");
        convertedClaims.put("sub", username);

        return convertedClaims;
    }
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
class UsernameSubClaimAdapter : Converter<Map<String, Any?>, Map<String, Any?>> {
    private val delegate = MappedJwtClaimSetConverter.withDefaults(Collections.emptyMap())
    override fun convert(claims: Map<String, Any?>): Map<String, Any?> {
        val convertedClaims = delegate.convert(claims)
        val username = convertedClaims["user_name"] as String
        convertedClaims["sub"] = username
        return convertedClaims
    }
}
----
======

[[oauth2resourceserver-jwt-timeouts]]
== Cấu hình timeout

Theo mặc định, Resource Server sử dụng connection timeout và socket timeout, mỗi timeout là 30 giây, để phối hợp với authorization server.
Bạn có thể ghi đè các giá trị mặc định này mà không cần thay đổi code bằng cách đặt system property `sun.net.client.defaultConnectTimeout` và `sun.net.client.defaultReadTimeout` của JDK (tính bằng millisecond).

Trong một số tình huống, khoảng thời gian này có thể quá ngắn.
Ngoài ra, cách này không tính đến các pattern phức tạp hơn như back-off và discovery.

Để điều chỉnh cách Resource Server kết nối tới authorization server, `NimbusJwtDecoder` chấp nhận một instance của `RestOperations`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
public JwtDecoder jwtDecoder(RestTemplateBuilder builder) {
    RestOperations rest = builder
            .setConnectTimeout(Duration.ofSeconds(60))
            .setReadTimeout(Duration.ofSeconds(60))
            .build();

    NimbusJwtDecoder jwtDecoder = NimbusJwtDecoder.withIssuerLocation(issuer).restOperations(rest).build();
    return jwtDecoder;
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
fun jwtDecoder(builder: RestTemplateBuilder): JwtDecoder {
    val rest: RestOperations = builder
            .setConnectTimeout(Duration.ofSeconds(60))
            .setReadTimeout(Duration.ofSeconds(60))
            .build()
    return NimbusJwtDecoder.withIssuerLocation(issuer).restOperations(rest).build()
}
----
======

Ngoài ra, theo mặc định, Resource Server cache JWK set của authorization server trong memory trong 5 phút; bạn có thể muốn điều chỉnh giá trị này.
Hơn nữa, cách này không tính đến các pattern caching phức tạp hơn như eviction hoặc sử dụng shared cache.

Để điều chỉnh cách Resource Server cache JWK set, `NimbusJwtDecoder` chấp nhận một instance của `Cache`:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
@Bean
public JwtDecoder jwtDecoder(CacheManager cacheManager) {
    return NimbusJwtDecoder.withIssuerLocation(issuer)
            .cache(cacheManager.getCache("jwks"))
            .build();
}
----

Kotlin::
+
[source,kotlin,role="secondary"]
----
@Bean
fun jwtDecoder(cacheManager: CacheManager): JwtDecoder {
    return NimbusJwtDecoder.withIssuerLocation(issuer)
            .cache(cacheManager.getCache("jwks"))
            .build()
}
----
======

Khi được cung cấp một `Cache`, Resource Server sẽ sử dụng JWK Set Uri làm key và JWK Set JSON làm value.

NOTE: Spring không phải là cache provider, vì vậy bạn cần đảm bảo đã thêm các dependency phù hợp, chẳng hạn như `spring-boot-starter-cache` và cache provider ưa thích của bạn.

NOTE: Dù là socket timeout hay cache timeout, thay vào đó bạn có thể muốn làm việc trực tiếp với Nimbus.
Để làm vậy, hãy nhớ rằng `NimbusJwtDecoder` cung cấp một constructor nhận `JWTProcessor` của Nimbus.
