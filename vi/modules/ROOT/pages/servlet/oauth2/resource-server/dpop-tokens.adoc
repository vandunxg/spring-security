[[oauth2-dpop-bound-access-tokens]]
= Access token ràng buộc DPoP của OAuth 2.0

https://datatracker.ietf.org/doc/html/rfc9449[RFC 9449 OAuth 2.0 Demonstrating Proof of Possession (DPoP)] là một cơ chế ở cấp ứng dụng để sender-constrain access token.

Mục tiêu chính của DPoP là ngăn các client không được ủy quyền hoặc không hợp lệ sử dụng access token bị rò rỉ hoặc đánh cắp, bằng cách bind access token với một public key khi authorization server cấp token và yêu cầu client chứng minh quyền sở hữu private key tương ứng khi sử dụng access token tại resource server.

Access token được sender-constrain thông qua DPoP khác với bearer token thông thường, vốn có thể được sử dụng bởi bất kỳ client nào sở hữu access token đó.

DPoP giới thiệu khái niệm https://datatracker.ietf.org/doc/html/rfc9449#name-dpop-proof-jwts[DPoP proof], là một JWT được client tạo và gửi dưới dạng header trong HTTP request.
Client sử dụng DPoP proof để chứng minh quyền sở hữu private key tương ứng với một public key cụ thể.

Khi client khởi tạo một <<dpop-access-token-request,access token request>>, client đính kèm DPoP proof vào request trong một HTTP header.
Authorization server bind (sender-constrain) access token với public key được liên kết trong DPoP proof.

Khi client khởi tạo một <<dpop-protected-resource-request,protected resource request>>, client lại đính kèm DPoP proof vào request trong một HTTP header.

Resource server lấy thông tin về public key được bind với access token, trực tiếp trong access token (JWT) hoặc thông qua token introspection endpoint.
Sau đó, resource server verify rằng public key được bind với access token khớp với public key trong DPoP proof.
Resource server cũng verify rằng hash của access token trong DPoP proof khớp với access token trong request.

[[dpop-access-token-request]]
== Yêu cầu access token DPoP

Để request một access token được bind với public key bằng DPoP, client MUST cung cấp DPoP proof hợp lệ trong header `DPoP` khi thực hiện access token request tới token endpoint của authorization server.
Điều này áp dụng cho mọi access token request, không phụ thuộc vào authorization grant type (ví dụ: `authorization_code`, `refresh_token`, `client_credentials`, v.v.).

Đoạn code sau đây minh họa cách tạo DPoP proof JWT:

[tabs]
======
Java::
+
[source,java,role="primary"]
----
RSAKey rsaKey = ...
JWKSource<SecurityContext> jwkSource = (jwkSelector, securityContext) -> jwkSelector
		.select(new JWKSet(rsaKey));
NimbusJwtEncoder jwtEncoder = new NimbusJwtEncoder(jwkSource);

JwsHeader jwsHeader = JwsHeader.with(SignatureAlgorithm.RS256)
		.type("dpop+jwt")
		.jwk(rsaKey.toPublicJWK().toJSONObject())
		.build();
JwtClaimsSet claims = JwtClaimsSet.builder()
		.issuedAt(Instant.now())
		.claim("htm", "POST")
		.claim("htu", "https://server.example.com/oauth2/token")
		.id(UUID.randomUUID().toString())
		.build();

Jwt dPoPProof = jwtEncoder.encode(JwtEncoderParameters.from(jwsHeader, claims));
----
======

Sau khi authorization server validate thành công DPoP proof, public key từ DPoP proof sẽ được bind (sender-constrain) với access token đã cấp.

Phản hồi access token sau đây đặt tham số `token_type` là `DPoP` để báo hiệu cho client rằng access token đã được bind với public key trong DPoP proof của nó:

[source,shell]
----
HTTP/1.1 200 OK
Content-Type: application/json
Cache-Control: no-store

{
 "access_token": "Kz~8mXK1EalYznwH-LC-1fBAo.4Ljp~zsPE_NeO.gxU",
 "token_type": "DPoP",
 "expires_in": 2677
}
----

[[dpop-public-key-confirmation]]
== Xác nhận khóa công khai

Resource server MUST có khả năng xác định access token có được bind với DPoP hay không và verify binding với public key của DPoP proof.
Binding được thực hiện bằng cách liên kết public key với access token theo cách resource server có thể truy cập, chẳng hạn như nhúng trực tiếp hash của public key vào access token (JWT) hoặc thông qua token introspection.

Khi access token được biểu diễn dưới dạng JWT, hash của public key nằm trong claim `jkt` bên dưới confirmation method claim (`cnf`).

Ví dụ sau đây minh họa các claim của JWT access token chứa claim `cnf` với claim `jkt`, là JWK SHA-256 Thumbprint của public key trong DPoP proof:

[source,json]
----
{
  "sub":"user@example.com",
  "iss":"https://server.example.com",
  "nbf":1562262611,
  "exp":1562266216,
  "cnf":
  {
    "jkt":"CQMknzRoZ5YUi7vS58jck1q8TmZT8wiIiXrCN1Ny4VU"
  }
}
----

[[dpop-protected-resource-request]]
== Yêu cầu tài nguyên được bảo vệ DPoP

Request tới DPoP-protected resource MUST bao gồm cả DPoP proof và DPoP-bound access token.
DPoP proof MUST bao gồm claim `ath` chứa hash hợp lệ của access token.
Resource server sẽ calculate hash của access token nhận được và verify rằng hash này giống với claim `ath` trong DPoP proof.

DPoP-bound access token được gửi bằng request header `Authorization` với authentication scheme là `DPoP`.

HTTP request sau đây minh họa protected resource request với DPoP-bound access token trong header `Authorization` và DPoP proof trong header `DPoP`:

[source,shell]
